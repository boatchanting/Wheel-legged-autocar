# 双轮足打滑检测机制说明

## 1. 背景与前因
在两轮并联腿自平衡机器人（双轮足）的高速运动与寻迹控制中，精准的打滑检测是保障姿态稳定与惯导推算精度的核心。
早期的打滑检测逻辑套用了四轮刚体车的“角速度对比法”（对比轮速推算的理论角速度与 IMU 实测角速度）。但在双轮足机器人上，由于系统是一个“倒立摆”模型，在连续 S 弯极限压弯时，底部轮子先动作，而上方高悬的沉重机体需要时间来完成倾斜和横向摆动。这种先天的“机械相位滞后”导致 IMU 测出的角速度天然跟不上轮速推算的理论角速度。
若继续沿用四轮车的判断逻辑，会将这种**正常的动态迟滞**误判为严重打滑（偏航失控），从而在 S 弯等工况产生大量误报并干扰速度融合。

## 2. 核心物理事实：只有径向平移侧滑
对于两轮倒立摆机器人而言，真正的打滑危机只会在**失去侧向抓地力、整车向外飘出**时发生（例如“纸片拖拽实验”工况）。
在此类打滑中，由于车身并未发生异常扭转，传统的角速度对比法会完全失效（期望与实际角速度均趋近于 0），甚至在低速打滑时误判为“静止”。

## 3. 全新检测逻辑：向心加速度校验
为了彻底解决双轮足高重心带来的相位差误报，并精准捕获真正的侧面平移打滑，当前的系统彻底剔除了“角速度对比”，100% 依赖**向心加速度校验模型**。

### 3.1 理论基础
根据刚体运动学，在车体坐标系下，真实的侧向加速度分布满足：
$$ a_{y, imu} = \dot{v}_y + v_x \cdot \omega $$
- $a_{y, imu}$：IMU 测得的原始侧向加速度 (`acc_lat_left`)
- $v_x \cdot \omega$：维持当前转弯所必需的**向心加速度**
- $\dot{v}_y$：**异常的侧向平移加速度**

当轮胎抓地力充足时，小车没有平移滑动（$\dot{v}_y \approx 0$），IMU 的读数应当完全等同于向心加速度：$a_{y, imu} \approx v_x \cdot \omega$。
当发生真正的侧向平移打滑时，两者将产生巨大差值。

### 3.2 逻辑实现 (`inertial_nav.c`)
打滑判断由以下几个步骤组成（当 `sys_options.h` 中的 `SLIP_DETECTION_ENABLE` 开启时生效）：

1. **计算向心加速度与异常横移**：
   提取出真正的纯横向平移异常加速度：
   ```c
   float centripetal_accel = v_wheel_avg * actual_yaw_rate;
   float anomaly_lat_accel = acc_lat_left - centripetal_accel;
   ```
   *(注：前向速度 $v_x$ 为负，向右转向时 $\omega$ 为正，$a_c$ 计算结果为负，正好匹配 `acc_lat_left` 正向朝左时受向右离心力为负值的物理极性，无需额外修正。)*

2. **动态侧滑阈值**：
   考虑到平衡车压弯时的倾角分量和测量噪声，侧滑容忍阈值设定为基础值附加一个随速度线性增加的宽限值：
   ```c
   float lat_slip_thres = 500.0f + fabsf(v_wheel_avg) * 0.2f;
   ```

3. **综合打滑判定树**：
   - **静止态 (`SlipFlag = 2`)**：必须满足三个条件——轮速极低、无异常角速度、且**无异常横向滑动加速度**。这确保了小车纯平移滑移时绝不会误判为静止。
   - **原地自转 (`SlipFlag = 3`)**：轮速极低，但存在较大的真实旋转角速度。
   - **平移侧滑 (`SlipFlag = 1`)**：运动过程中，`fabsf(anomaly_lat_accel) > lat_slip_thres` 阈值被击穿，即发生纯径向侧滑。
   - **正常抓地 (`SlipFlag = 0`)**：向心加速度吻合，未发生侧移或处于可控容差范围内。

## 4. 全局配置开关
为便于对比调试或针对特殊任务关闭干预，此逻辑已受控于全局编译开关：
**文件位置**：`code/config/sys_options.h`
**配置宏**：`#define SLIP_DETECTION_ENABLE 1U`

- **开启 (1)**：按上述逻辑计算 `slip_flag` 并参与惯导速度融合的置信度分配（如降低轮速权重）。
- **关闭 (0)**：直接跳过侧滑解算，强制 `slip_flag = 0`。下游逻辑将无感地继续使用默认的平滑权重（如 `NAV_ALPHA_VEL`）进行姿态与位置估算。
