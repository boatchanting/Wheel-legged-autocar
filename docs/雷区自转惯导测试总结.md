# 科目二雷区自转（Minefield）惯导定位测试总结

## 1. 背景与问题描述
在之前的代码逻辑中，一旦小车进入雷区高速自转状态（`minefield_is_active == 1`），0 核中断会强行切断惯导更新（`InertialNav_Update` 被跳过），导致 `vx_body` 和 `vy_body` 强行锁 0，丧失了对自转期间物理滑移（蠕动）的记录能力。

为了评估是否可以利用惯导补偿自转期间的物理偏移，我们在去除该屏蔽逻辑、开启“完整版惯导（IMU 积分 + 轮速计）”后进行了三次实车自转数据采集，并对日志进行了对比分析。

## 2. 测试数据与现象分析

### 2.1 轮速计数据：产生“幽灵后退”（完全不可信）
* **现象**：在高达 1000 deg/s 的极高速自转下，左右轮处于差速狂转状态。但由于电机死区和地面抓地力不平衡，左右轮速均值 `(speed_L + speed_R)/2` 并不为 0，而是始终维持在 **-230 ~ -270 mm/s** 的负值。
* **结论**：如果在此期间信任轮速计，导航系统会认为小车正在以 25 cm/s 的速度向后疯狂倒车（每次自转累计十多厘米的后退位移）。但物理观测显示，小车绝大部分时间是原地不动的（误差 < 5cm）。因此，**自转期间的轮速计均值是完全虚假的，采用轮速计会导致巨大的向后定位漂移**。

### 2.2 IMU 陀螺仪与加速度计：成功纠偏物理前冲
* **Yaw 航向角积分**：非常可靠。陀螺仪准确记录了最高达 **17.8 rad/s**（约 1020 deg/s）的极限角速度，与规划的 1000 deg/s 吻合，保证了自转后车头朝向不会丢失。
* **纵向加速度（X 轴积分）**：
  * 在第三次自转时，小车发生了真实的物理前移。此时开启的 IMU 加速度计敏锐地捕捉到了前冲，`vx_body` 输出了高达 **+630 mm/s** 的正向速度尖峰。
  * 这个真实的正向 IMU 积分，强行压制了轮速计传来的 -268 mm/s 的“后退假象”，将最终算出的总位移纠正到了 **3.5 cm** 左右，这与肉眼观察到的物理现实高度相符。

### 2.3 潜在风险：离心力串扰与权重拉扯
* 由于目前的惯导融合算法在雷区时仍保留了 `10%` 的轮速计权重（`alpha = 0.1`），在前两次小车真实原地不动的自转中，`vx_body` 仍被那 10% 的“幽灵后退”轮速慢慢拉偏到了 -190 mm/s 左右，产生了无中生有的十多厘米后退记录。
* 高速自转时，如果 IMU 安装未绝对居中，或者车身发生轻微震荡倾斜，极易产生巨大的向心加速度串扰到纵向轴（$a = \omega^2 r$），引起速度积分剧烈波动。

## 3. 最终结论与优化建议

**结论：自转期间开启惯导远比彻底锁死要好，但绝不能掺杂轮速计数据。**

建议后续在 `inertial_nav.c` 中进行如下优化：
1. **彻底抛弃轮速计**：当 `slip_flag == 3`（雷区自转）时，将速度融合权重 `alpha` 强制设为 `0.0f`。既然轮速计在这几秒钟里全是虚假信号，就不要让它污染 IMU 的积分。
2. **加入抗干扰死区**：对纵向加速度 `acc_lon_forward` 增加一个死区过滤（比如加速度必须大于某阈值才算作真实滑移，否则归 0），防止完美原地自转时因为机械震动和离心力积攒出虚假速度。
