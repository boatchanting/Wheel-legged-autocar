# 单边桥视觉阈值审计（宏包裹 vs 写死魔法数字）

> 审计日期：2026-08-15
> 范围：单边桥视觉全链路（1 核检测 → 仲裁/滤波 → 0 核控制状态机）
> 原则：**只记录、不改代码**。所有数值均以当前工作区代码为准。

---

## 0. 管线概览与文件清单

单边桥视觉按数据流分为 6 层，涉及 7 个源文件：

| 层 | 文件 | 运行核 | 职责 |
|---|---|---|---|
| 检测核心（桥上 v8/v11 三线透视） | `code1/vision/bridge_detect.h/.c` | CM7_1 | 94×60 灰度 → 红/绿/蓝三线 + 粉色退出线 |
| 参考检测器（远处亮区） | `code1/vision/bridge_ref_detection.h/.c` | CM7_1 | 亮区连通域 + 凸包，远处接近/脱出阶段 |
| 远近融合 | `code1/vision/bridge_fusion.h/.c` | CM7_1 | gate_bottom/gate_top 双门控，二选一引擎 |
| 仲裁层 | `code1/vision/bridge_v2_arbiter.h/.c` | CM7_1 | 三线结果 → 一条控制线（定点 a×1000 / b×100） |
| 中值滤波层 | `code1/vision/bridge_output_filter.h/.c` | CM7_1 | 滑动窗中值 + 结束线多帧门控 → `b2_*` |
| 0 核控制状态机 | `code/vision/vision_bridge_control.h/.c` | CM7_0 | 消费 `b2_*`，ALIGN→RUN→EXIT 状态机 |
| 1 核接线 | `user/main_cm7_1.c` | CM7_1 | 帧循环调用融合/仲裁/滤波 |

**活跃/死代码速览（bridge_detect.c 内）：**

- 当前生效的结束线检测是 `v11_top_gy`（v11 gy 行游程连通域法），`TOP_GRAD = 0`。
- `#if TOP_GRAD` 块（约 1579–1818 行）：旧梯度粉线校验，**不编译**（死代码）。
- `#if 0` 块（约 2009–2712 行）：原 MLP 结束线全套 + `bimodal_ref8` + `top_edge_validate`，**不编译**（死代码）。
- `extract_top_region`（亮区顶边界法）、`inner_threshold`：**会被编译但从未被调用**（死函数）。
- `otsu_img()`：会被调用，但 `tb` 结果在 `TOP_GRAD=0` 下被 `(void)tb` 丢弃，**计算结果未使用**。
- 残留宏：`V8_WEAK_TL / V8_WEAK_UM / V8_WEAK_BAND`、`W_PRIOR_HI` 仅定义、全代码零引用。

## 9. 重点风险提示

1. **`bridge_ref_detection.c` 打分体系完全无宏**：`evaluate_component` 的 11 个权重 + 5 个惩罚项、`score_side_fit`、`fit_line_fast` 的偏好系数全部写死，调参需直接改函数体，且这些系数间相互耦合，极易改一处破坏整体候选排序。
2. **`bridge_detect.c` 的 `LOCK_K` 宏被绕过**：热路径 `step3_4_dyn_threshold` 写 `gv * 2`，未引用 `LOCK_K`（当前值一致，但改宏不会生效）。
3. **底部 gate 50% 白占比写死**（`br * 2 > tot`），与融合层 `BF_GATE_BOT_WHITE_MIN=0.75` 语义同类但数值不同且不可调（v8 内 50%、融合层 ref 阶段 75%）。
4. **`bridge_fusion.c` 顶部复制了 v8 的 `Y_REF=55` / `MIN_SPACING=14`**（`BF_Y_REF` / `BF_MIN_SPACING`），两处独立维护，改一处会漏另一处。
5. **大量死代码仍占据工程**：`#if 0` MLP 块、`#if TOP_GRAD` 旧梯度块、`extract_top_region` / `inner_threshold` 死函数、4 个残留宏——它们含大量阈值宏，审计或搜索阈值时易被误导为"生效中"。
6. **`otsu_img()` 每帧仍执行但其结果被丢弃**（`TOP_GRAD=0` 下 `(void)tb`），属无效计算。
