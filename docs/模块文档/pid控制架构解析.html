先给结论

1. PID 不是直接算出“真实速度”

PID 算出的是控制指令：舵机 duty 调整量、目标角速度、电机 PWM。真实速度由车轮编码器测出来，再用 rpm × 4.936 换成 mm/s 反馈回来。

2. 现在速度主调节在舵机速度环

1ms 中断里每 9ms 调用 Servo_Speed_Control()，输出 g_target_pwm_speed_adj 给舵机执行器；传统 Speed_Loop_Control() 在当前 Core0 ISR 中没有实际参与。

3. 要测的不是一个参数，而是一组约束

老师说的“限幅、单次舵机增量、角度环 Kp/Kd”要一起测：总输出限幅决定目标能有多大，单次增量决定目标多久到位，Kp/Kd 决定车身恢复力和阻尼。

重要：本文没有读取 servo_executor.c，因为你明确说不要读取；所以“单次舵机增量”在求解器里作为可调输入。这个值应当来自执行器里的斜率限制配置或你实测的每 1ms duty 变化量。
按你给出的开关理解：ACCEL_FF_ENABLE=1 且 ACCEL_FF_MODE=1，所以加速前馈是“直接叠加 PWM”模式，不是“临时增强舵机速度环 Kp”模式；求解器里的 Kp boost 默认按 1，只用于对比假设。IMU_CATEGORY=3，所以本文按 IMU963RA 与 CAR_SELECT=3 的轴向取法解释。

速度从哪里来

编码器 rpm 到车速

当前 1ms 中断每 9ms 读取左右轮编码器速度，并计算中间变量：

current_actual_speed = 0.5 × (right_rpm - left_rpm)

然后把它当作“实际速度 rpm 单位量”送入舵机速度环。你给出的实车换算是：

v_mm_s = rpm × 4.936

如果要从期望线速度反推 PID 目标速度：

target_rpm = v_mm_s / 4.936

这个系数代表什么

轮子每分钟转 rpm 圈，线速度等于轮周长乘转速再除以 60 秒：

v_mm_s = rpm × C_mm / 60

已知 v_mm_s = rpm × 4.936，所以：

C_mm = 4.936 × 60 = 296.16 mm D_mm = C_mm / π ≈ 94.27 mm

这说明你的速度系数大约对应直径 94mm 的轮子，和小车轮径是一个合理量级。

PID 基础公式

离散 PID 公式

控制器每隔固定周期运行一次，第 k 次运行时：

e[k] = target[k] - actual[k] I[k] = clamp(I[k-1] + e[k], -Imax, Imax) D[k] = e[k] - e[k-1] u_raw[k] = Kp·e[k] + Ki·I[k] + Kd·D[k] u[k] = clamp(u_raw[k], -Omax, Omax)

你的代码里 D 项没有除以采样周期，所以周期改变时，Kd 要按比例换算。代码注释中的做法是 Kd_new = Kd_old × T_old / T_new。

限幅的物理含义

限幅不是“随便挡一下”，它定义了系统最多能发出多大控制意图。

输出限幅 Omax：本环最多允许输出多少 duty / PWM / 角速度指令 积分限幅 Imax：防止长期误差把积分累到无法恢复 单次增量 S：执行器每 1ms 最多追多少 duty

速度环总输出限幅和单次舵机增量要配套测。前者决定“想动多大”，后者决定“多久动到”。

舵机速度环：速度误差变成腿部 duty

代码里的完整数学链

speed_now = 0.6·actual + 0.3·last + 0.1·prelast e = target_speed - speed_now k = 0.4 + 0.6 × (1 - exp(-|e|/10)) / (1 + exp(-|e|/10)) Kp_eff = -4.5 × k × Kp_boost u_raw = Kp_eff·e + 0·I + (-0.17)·(e - e_last) g_target_pwm_speed_adj = clamp(u_raw, -1000, 1000)

这里 k 是自适应比例系数：速度误差很小时约为 0.4，误差很大时接近 1.0。也就是说，小误差时温柔，大误差时更硬。

你当前配置是 ACCEL_FF_MODE=1，Kp 增强模式未启用，所以正常运行时 Kp_boost = 1。

从 duty 到舵机角度的粗换算

舵机 PWM 频率为 300Hz，代码给出：

DUTY_RANGE_180 = 2.0ms × 300Hz × 10000 / 1000 = 6000 DEGREE_PER_DUTY = 180 / 6000 = 0.03°/duty

所以速度环输出限幅 ±1000 duty 理论上对应约：

1000 × 0.03 = 30°

注意：V 腿最终高度/角度还要经过五连杆查表和执行器斜率限制。这个 30° 是“原始舵机 duty 到角度”的粗换算，不等于车身一定转 30°。

小白理解：速度环像一个“腿部姿态指挥官”。目标速度和实际速度差很多，它就给较大的腿部 duty 调整；但它自己不会直接让轮子转，轮子仍由平衡角速度环和前馈融合输出 PWM。

平衡角度环与角速度环

角度环，3ms

代码里目标角度由机械零点和 speed_loop_out 合成：

target_angle = ANG_MECH_ZERO - speed_loop_out e_angle = target_angle - pitch u_angle_raw = -12·e_angle + (-13.3333)·(e_angle - e_last) angle_loop_out = -clamp(u_angle_raw, -8000, 8000)

当前 ISR 中 speed_loop_out 没有被传统速度环更新，所以多数情况下目标角度就是机械零点 -3°。

角速度环，1ms

IMU963RA 且 CAR_SELECT=3 时，pitch 角速度取 imu_data.gyro_x 转成 deg/s，并做低通：

now_gyro = 0.8·now_gyro_old + 0.2·gyro_x_deg_s e_gyro = angle_loop_out - now_gyro gyro_loop_out = clamp(-16·e_gyro, -9000, 9000)

最后左右轮差动：

pwm_left = gyro_loop_out + drive_ff + turn_gyro_loop_out pwm_right = -gyro_loop_out - drive_ff + turn_gyro_loop_out

转向与主动侧倾

转向 PID

转向先把 yaw 误差归一化到 -180° ~ 180°，再把输入误差限到 ±45°：

yaw_error = wrap(err_degree, -180°, 180°) yaw_error = clamp(yaw_error, -45°, 45°) turn_angle_loop_out = clamp(-8·yaw_error, -8000, 8000) turn_gyro_loop_out = clamp(20·e + 16·(e - e_last), -8000, 8000)

转向 PWM 是同向加到左右轮上，所以它让两轮形成偏航力矩，而不是维持直立的差动平衡力矩。

主动侧倾的物理式

转弯时，车身需要向内侧倾来抵抗向心加速度。代码用速度与 yaw 角速度估计横向加速度：

v_m_s = current_actual_speed × 0.004936 × (-1) a_lat = v_m_s × yaw_rate_rad_s roll_request = -atan2(a_lat, 9.80665) × 57.2958 roll_target = clamp(roll_request, -18°, 18°)

再把目标横滚角换成左右腿高度差，最大单侧高度差为 3.5cm，并由 5ms ramp 平滑建立。

按公式调参，而不是只看波形试

1. 先把速度和加速度算出来

每 9ms 记录一次实际 rpm，就能算实车线速度和加速度：

v[k] = 4.936 × rpm[k] (mm/s) a[k] = (v[k] - v[k-1]) / 0.009 (mm/s²) a_m_s2[k] = a[k] / 1000

如果你希望从 v0 在 t 秒内变到 v1：

a_des = (v1 - v0) / t 每 9ms 应变化 Δrpm = a_des × 0.009 / 4.936

2. 再看限幅是否合理

舵机速度环当前总输出限幅为 1000 duty。若执行器单次增量为 S duty/ms：

执行器最大 duty 速度 = S / 0.001 = 1000S duty/s 9ms 内最多追上 min(1000, 9S) duty 等效舵机角速度 ≈ 0.03S / 0.001 = 30S °/s

如果波形里 g_target_pwm_speed_adj 经常顶到 ±1000，说明速度环总输出限幅或 Kp/Kd 过强；如果目标没顶但实际舵机 duty 跟不上，问题更可能在单次增量太小。

3. 平衡角度环 Kp/Kd 怎么看

Kp 是“扶正力度”，Kd 是“刹住晃动的阻尼”。

u_angle = Kp·角度误差 + Kd·误差变化

调试思路：

  • 车身软、倒得慢但扶不住：Kp 可能偏小。
  • 车身大幅来回摆：Kp 可能偏大或 Kd 不够。
  • 高频抖、噪声放大：Kd 可能偏大，或 gyro/pitch 滤波不够。
  • 改采样周期后，优先按 Kd_new = Kd_old × T_old / T_new 换算，再微调。

4. 建议记录的波形

  • target_speed_set、current_actual_speed、换算后的 v_mm_s。
  • pid_servo_speed.error、g_target_pwm_speed_adj、实际四舵机 duty。
  • euler_angle.pitch、angle_loop_out、now_gyro、gyro_loop_out。
  • turn_angle_loop_out、turn_gyro_loop_out、最终 pwm_left/right。
  • 刹车/加速前馈：brake_pwm、accel_ff_pwm。

想在赛道上跑得更快，底层该怎么优化

短答案：不是简单把加速度和减速度都调大，而是做“动态加减速”。直道允许更大加速度，弯前按刹车距离提前降速，弯中保留平衡和转向 PWM 余量，出弯再用可控加速度拉起来。更快的本质是平均速度更高，而不是每一瞬间都更猛。

当前代码里的提速瓶颈

  • target_speed_set 经常被上层任务直接写成固定值，底层 9ms 速度环会看到台阶输入，缺少统一的速度斜率与 jerk 管理。
  • Accel_Feedforward_Update() 目前主要服务复刻运行窗口；PVC、桥梁、三阶段、特殊动作等场景会屏蔽或清空加速前馈。
  • OUR_PWM_MAX_LIMIT = 8000，但平衡、转向、加速前馈、刹车前馈都在抢同一个最终 PWM 余量。
  • GYR_MAX_O = 9000 大于最终电机限幅 8000，平衡内环自己就可能把最终输出顶满，导致转向和驱动前馈没有余量。
  • ROLL_BALANCE_ENABLE_INIT = 0，主动侧倾默认关闭；高速弯道时如果没有侧倾支撑，能跑的弯中速度会受限。
  • 传统 Speed_Loop_Control() 在当前 Core0 ISR 中没有参与，speed_loop_out 基本不会给平衡角度环提供速度外环倾角补偿。

更快不等于更暴力

速度提升要同时满足三个约束：

纵向约束：|a_x| ≤ a_x_max，防止后坐、前栽、打滑、舵机跟不上 横向约束：|a_y| = |v·ω| ≤ a_y_max，防止弯中侧翻或横向漂移 PWM 约束：|balance + drive + turn| ≤ 8000，并保留平衡优先余量

所以应该用动态速度规划：

v_plan[k] = ramp_with_jerk(v_plan[k-1], v_limit_by_track, a_up, a_down, j_limit)

如果没有规划器，目标速度一跳变，底层只能靠 PID、前馈、限幅硬接，波形看起来会“猛”，但平均速度未必更高。

建议 1：加统一速度规划器

在所有上层任务写 target_speed_set 之前或之后增加一层：

target_speed_raw：遥控/导航/视觉想要的速度 target_speed_plan：经过加速度、减速度、jerk、弯道限速后的速度 底层 PID 只看 target_speed_plan

推荐按场景分参数：

  • 直道：较大的 a_up，较小 jerk，允许快速提速但不突然给满。
  • 弯前：较大的 a_down，按刹车距离提前降速。
  • 弯中：速度上限由 yaw 角速度、视觉曲率或转向误差决定。
  • 出弯：短时间提高 a_up 或加速前馈，但要看 PWM 余量。

建议 2：用刹车距离，而不是到弯口才刹

如果当前速度是 v_now，弯中安全速度是 v_turn，允许最大减速度是 a_down，应提前这么远开始减速：

d_brake = (v_now² - v_turn²) / (2·a_down) + margin

例子：从 1000mm/s 降到 400mm/s，允许减速度 2.0m/s²：

d = (1.0² - 0.4²) / (2×2.0) = 0.21m

这会比“看见弯再把目标速度切低”稳定很多，因为刹车前馈、舵机姿态保护、平衡环都有时间进入状态。

建议 3：做 PWM 余量仲裁

现在最终融合是直接相加再统一限幅：

left = gyro + brake/accel + turn right = -gyro - brake/accel + turn

更稳的做法是明确优先级：

优先级：平衡 gyro > 刹车 brake > 转向 turn > 加速 accel 如果 |总和| 超过 8000，先缩小低优先级项，而不是让最终限幅悄悄截断

建议增加饱和计数：

  • gyro_saturation_count：平衡环是否经常顶满。
  • drive_ff_cut_count：加速前馈是否经常被刹车/特殊任务清掉。
  • motor_final_saturation_count：最终左右轮是否经常被 8000 截断。
  • servo_speed_saturation_count：舵机速度环是否经常到 ±1000。

建议 4：不要急着恢复传统速度外环

代码里 Speed_Loop_Control() 存在，但当前没有参与。理论上速度外环可以输出目标倾角，让车通过“倾斜追重心”加速；但你现在已经用舵机速度环改变腿部姿态。

如果两个速度外环同时工作，容易出现：

  • 舵机速度环想通过腿部姿态提速。
  • 传统速度环又想通过车身倾角提速。
  • 平衡角度环同时要救直立，最后互相抢控制权。

建议先选择一个主速度执行器。当前架构下优先把“舵机速度环 + 电机前馈 + 平衡保护”调清楚，再考虑小幅、低频地把速度外环接回 speed_loop_out。

建议 5：加速前馈改成规划器驱动

当前加速前馈触发条件强调复刻起步/目标速度阶跃：

speed_lag = |target| > |actual| + 30 target_step_up = |target| - |last_target| ≥ 30 accel_ff_target = clamp(10 × speed_deficit × direction, ±3000)

如果要比赛提速，建议让规划器输出 a_request，前馈按加速度请求给，而不是只看速度缺口：

accel_ff_target = Kff_a · a_request + Kff_v · (v_plan - v_actual)

这样直道、出弯、低速起步可以共用一套逻辑，也更容易用波形验证。

建议 6：主动侧倾可以成为高速弯道工具

代码已经有主动侧倾公式：

a_lat = v_m_s × yaw_rate_rad_s roll = atan2(a_lat, g)

但默认 roll_balance_enable = 0。如果赛道弯道速度上不去，可以做分阶段测试：

  • 先只在中高速、非刹车、非跳跃、非特殊任务时启用。
  • 从较小 TURN_ACTIVE_ROLL_MAX 和较小 ramp 开始。
  • 观察四舵机是否触边界、弯中 pitch 是否恶化、最终电机 PWM 是否更少饱和。

建议优先级

优先级 优化项 为什么先做 验证波形
1 加饱和计数和速度/加速度记录 先知道是电机 PWM、舵机 duty、还是目标速度规划卡住了。 v、a、gyro_loop_out、turn_gyro_loop_out、drive_ff、最终 PWM。
2 统一速度规划器 消除上层速度台阶，动态控制加减速和 jerk。 target_speed_raw vs target_speed_plan vs current_actual_speed。

5 高速弯道启用主动侧倾 提高弯中横向稳定性，但必须先确认舵机余量。 roll_degree、四舵机 duty、横滚角、弯中速度。

SERVO_SPEED_MAX_O 已到 2000 但仍然慢，下一步该查什么

核心判断：SERVO_SPEED_MAX_O 只是舵机速度环输出 g_target_pwm_speed_adj 的限幅，不是最终电机 PWM 的总油门。调到 2000 后仍慢，通常说明瓶颈已经转移到“输出没有长期打满”“舵机执行斜率/机械姿态跟不上”“最终电机 PWM 被平衡或转向吃掉”“加速前馈被场景屏蔽”这几类。

1. 先判断 2000 有没有真的起作用

舵机速度环近似是：

speed_now = 0.6v[k] + 0.3v[k-1] + 0.1v[k-2] e_v = target_speed - speed_now Kp_eff = Kp · k(e_v) · kp_boost u_raw = Kp_eff · e_v + Kd · (e_v - e_v_last) u_servo = clamp(u_raw, -SERVO_SPEED_MAX_O, +SERVO_SPEED_MAX_O)

如果记录波形发现 |u_raw| 很少超过 1000，或者 g_target_pwm_speed_adj 很少贴着 ±2000，那么把限幅从 1000 调到 2000 本来就不会明显变快。此时该加的是目标速度规划、前馈或有效 Kp，不是继续加限幅。

2. 如果已经打满，查下游

  • 舵机单次增量：如果执行层每 1ms 只允许走很小的 duty，2000 只是目标差值，真实腿部姿态仍会慢慢爬。
  • 机械限位：LF/RF/RR/LR_LIMIT_DUTY_MIN/MAX 约束了四个舵机最终范围，贴边后再大的速度输出也没有有效姿态变化。
  • 最终 PWM 余量：当前融合是 left = gyro + drive_ff + turn、right = -gyro - drive_ff + turn，最后再限到 ±8000。平衡和转向占满时，加速前馈会被最终限幅吞掉。
  • 前馈屏蔽条件：桥梁、三阶段、PVC、特殊动作、强刹、推车、跳跃等场景会屏蔽或清空 Accel_Feedforward。

3. 更快的底层优化建议

  • 记录饱和计数：每 9ms 记录 u_raw、u_servo、g_target_pwm_speed_adj，每 1ms 记录 gyro_loop_out、turn_gyro_loop_out、drive_ff_pwm、最终左右轮 PWM。
  • 把加速前馈从“速度缺口触发”升级为“规划器驱动”：accel_ff = Kff_a·a_request + Kff_v·(v_plan-v_actual)，直道和出弯会更主动。
  • 小步提高前馈建立速度：优先试 ACCEL_FF_RAMP_UP，再试 ACCEL_FF_GAIN，最后才试 ACCEL_FF_MAX。因为慢往往是“建立太慢”，不是“峰值不够”。
  • 按场景给速度斜率：直道大 a_up，弯前大 a_down，弯中按 a_y=v·ω 限速，出弯短时间提高 a_up 和前馈。
  • 做 PWM 预算仲裁：先保平衡，再保刹车，再保转向，最后给加速。不要让最终 Float_Constrain() 悄悄截断所有量。
  • 减少速度反馈滞后：当前速度滤波 0.6/0.3/0.1 比较稳，但急加速时会让误差反应慢。可测试低延迟版本，例如 0.75/0.2/0.05，观察噪声和超调。
  • 把 9ms 速度段缩短做 A/B 测试：如果 CPU 余量够，可试 6ms 或 3ms 更新舵机速度环和前馈，但要同时下调每周期 ramp，保持每秒斜率一致。
  • 弯中启用主动侧倾的保守版本：它不直接提高直线加速度，但能提高弯中可用速度，平均速度会更高。

4. 建议测试顺序

  1. 空旷直线，用固定目标速度阶跃，记录 target_speed_set/current_actual_speed/u_raw/u_servo/final_pwm。
  2. 看 u_servo 是否长期贴 ±2000。没贴满就调 Kp/kp_boost/速度规划，贴满再查执行斜率。
  3. 看最终 PWM 是否贴 ±8000。若贴满，先降低同一时刻的转向或加速前馈，保留平衡余量。
  4. 逐步提高 ACCEL_FF_RAMP_UP：800 → 1000 → 1200，每次只改一个参数，看起步 0.3s 内速度斜率。
  5. 再小步提高 ACCEL_FF_GAIN：10 → 12 → 14。如果 pitch 明显后坐、轮胎打滑或平衡 PWM 饱和，就退回。
  6. 最后按赛道分段调 a_up/a_down/v_turn，不要用一个全局速度跑完整条赛道。

已知小车正在单调加速/减速时，可以做的更细控制

核心思路：不要让底层只看到“目标速度”和“当前速度”的误差，而是额外告诉底层：我现在是在加速、减速、匀速、弯前收速、还是出弯提速。这样舵机每周期增量、电机前馈、刹车前馈和 PWM 预算都可以提前进入正确状态，而不是等速度误差变大后再被动补救。

1. 加一个运动趋势状态机

速度规划器每 9ms 输出两个量：计划速度 v_plan 和计划加速度 a_req。

a_req[k] = (v_plan[k] - v_plan[k-1]) / T trend = ACCEL，当 a_req > a_th 且连续 N 次同号 trend = DECEL，当 a_req < -a_th 且连续 N 次同号 trend = HOLD，当 |a_req| ≤ a_th 或目标速度基本不变

建议不要单次判断，至少连续 N=3 个 9ms 周期再切状态，避免视觉速度抖动让底层反复切换。

if (a_req > +a_th) accel_count++;
else accel_count = 0;

if (a_req < -a_th) decel_count++;
else decel_count = 0;

if (accel_count >= 3) trend = ACCEL;
else if (decel_count >= 3) trend = DECEL;
else trend = HOLD;

2. 舵机每周期增量动态化

现在的关键不是只把 g_target_pwm_speed_adj 算大，而是让执行层知道“什么时候该快，什么时候该慢”。可以把单次舵机增量从常数改成动态值：

step_servo = clamp(step_base + K_a|a_req| + K_e|e_v|, step_min, step_max) duty_next = duty_now + clamp(duty_target - duty_now, -step_servo, +step_servo)

建议分方向：加速方向允许更大步长，回正方向保持较小步长；减速时相反。方向标定不要凭感觉，用实车看 g_target_pwm_speed_adj 正负对应前压还是后坐。

  • ACCEL：加速姿态方向 step_fast，反方向 step_slow，快速把腿打到提速姿态。
  • DECEL：刹车/反后坐姿态方向 step_brake_fast，释放方向 step_release，避免一下松开导致回弹。
  • HOLD：用 step_base，让姿态安静，减少舵机抖动和电流峰值。

3. 电机端做加速度前馈，而不只看速度缺口

当前加速前馈主要由速度缺口触发：

accel_ff ≈ K_v · (|v_target| - |v_actual|)

更适合比赛的做法是加入计划加速度：

drive_ff_target = K_a · a_req + K_v · (v_plan - v_actual) + K_s · sign(v_plan) drive_ff = ramp(drive_ff, drive_ff_target, ramp_up, ramp_down)

K_a 负责“提前给力”，K_v 负责“没跟上时补力”，K_s 负责克服静摩擦。这样直道刚开始加速时，不必等速度误差变大才输出电机前馈。

4. PWM 预算要先算余量，再给加速

最终电机融合不能只靠最后的 Float_Constrain()。推荐先估计剩余可用驱动量：

reserve_balance = 1000 ~ 1800 PWM drive_cap = PWM_LIMIT - |gyro| - |turn| - reserve_balance drive_ff = clamp(drive_ff_target, -drive_cap, +drive_cap)

如果 drive_cap < 0，说明平衡/转向已经吃满电机能力，此时继续加速只会被最终限幅截掉，甚至破坏平衡。正确动作是：弯中降速、减小转向峰值、或者提前减速。

5. 单调减速时的专门策略

  • 先撤加速前馈：当 trend=DECEL，先让 accel_ff 快速回零，不要加速和刹车同时拉扯。
  • 再建立刹车前馈：brake_ff = -K_b · |a_req| - K_overspeed · max(|v|-|v_plan|,0)。
  • 舵机给反后坐支撑：强刹时保留一点反后坐姿态，避免车身被刹车力矩压塌。
  • 低速释放：低于 30~40rpm 或接近目标速度时，刹车 ramp_down 要快，防止低速反抽。
  • 弯前公式：d_brake=(v_now²-v_turn²)/(2a_down)+margin，提前进入 DECEL，而不是到弯口才急刹。

6. 单调加速时的专门策略

  • 预充前馈：只要 v_plan 开始单调上升，就给 K_a·a_req，不等速度误差变大。
  • 舵机快速进入提速姿态：加速方向使用更大的 step_servo，但加一个 pitch_guard，车身后坐过大时自动降步长。
  • 出弯短 boost：在 yaw 角速度下降且目标速度上升时，允许 200~400ms 的较高 a_up 和 ACCEL_FF_RAMP_UP。
  • 打滑保护：如果电机 PWM 很大但编码器加速度上不来，判定轮胎打滑或姿态不对，降低前馈而不是继续加。
  • 平衡优先：如果 |gyro_loop_out| 长时间超过最终限幅的 65%，停止继续加速，先让车站稳。

从“调 PID”升级到“改控制架构”

先建立一个关键认知：PID 本身不会理解赛道，也不会主动知道“现在应该猛加速还是提前刹车”。PID 只会做一件事：看误差，输出修正量。想让车整体跑快，架构上要给 PID 一个更聪明的目标、更合适的前馈、更清楚的限幅和更明确的优先级。

1. PID 响应到底在看什么

最基础的离散 PID 可以写成：

e[k] = target[k] - feedback[k] P = Kp · e[k] I = I + Ki · e[k] · T D = Kd · (e[k] - e[k-1]) / T u[k] = clamp(P + I + D, -limit, +limit)

小白理解：P 看现在差多少，I 看过去欠多少，D 看变化有多猛。加速响应慢，可能是 P 不够，也可能是目标规划太保守、前馈太慢、限幅太早、执行器斜率太小，不能只怪 PID。

2. 加速响应的几个指标

  • 上升时间：从低速到目标速度需要多久。它决定直道提速快不快。
  • 超调：速度冲过目标多少。超调大会导致弯前刹不住、姿态乱。
  • 稳定时间：速度接近目标后多久不再晃。它决定跑起来是不是“稳”。
  • 饱和时间：输出有多久贴着限幅。长期饱和说明系统想做但做不到，继续加 Kp 不一定有效。
  • 相位滞后：反馈和执行器慢半拍。速度滤波太重、舵机斜率太小、控制周期太长都会增加滞后。

3. 为什么只调 PID 很容易遇到瓶颈

你的车不是单个电机速度环，而是平衡车加并联腿：

速度目标 → 舵机姿态/腿部形态 → 车身 pitch → 平衡电机 PWM → 实际速度

这条链路中每一层都会产生延迟和限幅。比如：

  • 舵机速度环输出很大，但执行层每 1ms 只能走一点点，腿部姿态慢。
  • 腿部姿态到了，但平衡环为了防倒车，把电机 PWM 用在救姿态上，没余量加速。
  • 电机前馈给了，但最终左右轮 PWM 已经被 ±8000 截断。
  • 目标速度突然跳变，PID 输出猛，但车身姿态和轮胎抓地跟不上。

4. 架构上应该分成五层

  1. 赛道速度层：根据直道、弯道、障碍决定原始目标速度 v_raw。
  2. 速度规划层：把 v_raw 变成连续的 v_plan、a_req、jerk_req。
  3. 运动状态层：判断 ACCEL / DECEL / HOLD / TURN / BRAKE。
  4. 执行器分配层：把目标分给舵机姿态、电机前馈、刹车前馈、主动侧倾。
  5. PID 稳定层：各个 PID 只负责把分配后的目标稳定跟住。

这样改完之后，PID 不再被迫猜你的意图。上层明确说“我要加速”，底层就提前给舵机快步长和电机前馈；上层说“我要减速”，底层就提前撤加速、建刹车、保护姿态。

5. 加速响应应该由 PID + 前馈共同完成

纯 PID 是“错了再补”，前馈是“知道要发生，提前给”。加速要快，不能只靠误差变大后 PID 再追。

u_total = u_pid + u_feedforward u_feedforward = K_a · a_req + K_v · (v_plan - v_actual) + K_s · sign(v_plan)

其中：

  • K_a·a_req：我要多大加速度，就提前给多大力矩。
  • K_v·速度差：如果实际速度没跟上，再补一点。
  • K_s：低速克服静摩擦、齿轮阻力和死区。

6. 限幅也要从“固定值”变成“有条件的值”

固定限幅适合保命，但不适合跑快。建议把限幅变成动态表：

servo_step = f(mode, |a_req|, |e_v|, pitch, pwm_margin) drive_cap = PWM_LIMIT - |gyro| - |turn| - balance_reserve accel_ff = clamp(accel_ff_target, -drive_cap, +drive_cap)

比如直道加速时允许舵机大步长；弯中或平衡 PWM 紧张时缩小加速前馈；强刹时允许刹车前馈大，但要给舵机反后坐支撑。

7. 建议你真正改代码时的顺序

  1. 先加日志：记录 v_raw/v_plan/a_req/current_speed/u_servo/gyro/turn/drive/final_pwm。
  2. 加速度规划器：不要让任务直接写台阶速度，统一经过 v_plan。
  3. 加运动状态机：至少有 ACCEL/DECEL/HOLD。
  4. 舵机执行层支持动态步长：加速方向、刹车方向、回正方向分开限速。
  5. 电机端加入 K_a·a_req 前馈，并受 PWM 余量限制。
  6. 最后再调 PID：先调内环稳定，再调外层响应。

8. 调参时不要同时改很多

建议一轮只改一个类别：

  • 响应慢但不饱和：先加前馈或有效 Kp。
  • 响应慢且舵机目标饱和：查舵机每周期步长和机械限位。
  • 响应慢且电机 PWM 饱和：做 PWM 仲裁，降弯中速度或减转向峰值。
  • 响应快但晃：降低 jerk、降低步长、加 D 或增加滤波。
  • 刹车后反抽：低速释放刹车前馈，减小减速末端舵机步长。
一句话总结：真正的架构优化不是把 PID 变复杂，而是让 PID 前面有规划器，旁边有前馈，后面有限幅仲裁。PID 负责稳定，规划器负责聪明，前馈负责快，仲裁负责不失控。
