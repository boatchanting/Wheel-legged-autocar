虽然它看起来只是在“闪烁 LED 灯”，但在智能车竞赛，特别是**轮腿穿越组**这样极其复杂的系统中，它是**人机交互（HMI）的核心**。

---

### 第一部分：代码解读

这段代码的功能非常简单：**通过按键和拨码开关，控制 LED 灯闪烁的频率。**

1.  **初始化 (Init):**
    *   配置了系统时钟（250MHz，说明可能是 TC264 或 TC364/377 系列）。
    *   **LED1** 配置为推挽输出（Output），用来发光。
    *   **KEY1-4** 和 **SWITCH1-2** 配置为上拉输入（Input Pull-up），用来读取外部信号。

2.  **主循环 (While True):**
    *   **检测按键：** `!gpio_get_level(KEY1)` 表示检测低电平（因为是上拉输入，按下通常接地变低）。只要有任意一个按键按下，基础延时设为 500ms（快闪）。没人按，设为 1000ms（慢闪）。
    *   **检测开关：** `gpio_get_level(SWITCH1)` 检测高电平。如果开关拨上去（接高），延时时间除以 2（闪烁速度翻倍）。
    *   **执行动作：** 翻转 LED 状态，然后**死等**（`system_delay_ms`）一段时间。

### 第二部分：在轮腿穿越组中的应用实战

轮腿车（变结构平衡车）对控制要求极高，通常没有屏幕或者屏幕信息量有限。这套 GPIO 逻辑是你在发车区**唯一能和车交流的方式**。

#### 1. 拨码开关 (SWITCH)：策略选择神器
在比赛现场，光照、地面摩擦力可能与你实验室不同，或者你需要跑不同的赛道元素。你不能每次都重新烧录代码，这时就要用拨码开关。

*   **场景一：发车模式选择**
    *   `SWITCH1 = 0`: **调试模式**（车直立但不走，方便看姿态波形）。
    *   `SWITCH1 = 1`: **竞赛模式**（直立且开启速度环，可以直接跑）。
*   **场景二：赛道元素使能**
    *   `SWITCH2 = 1`: 开启**跳跃检测**（遇到台阶自动跳跃）。如果现场台阶取消了，拨下来就能禁用该功能，防止误判。
    *   `SWITCH3 = 1`: 开启**大长腿模式**（重心升高，通过障碍能力强，但容易倒）。
*   **场景三：速度档位**
    *   比如 00 为低速稳跑（1.5m/s），01 为高速冲刺（2.5m/s）。

**代码改造示例：**
```c
// 在控制循环之外读取策略
uint8_t strategy_mode = 0;
if(gpio_get_level(SWITCH1)) strategy_mode |= 0x01; // 二进制掩码
if(gpio_get_level(SWITCH2)) strategy_mode |= 0x02;

if(strategy_mode == 3) {
    // 两个开关都拨上去，执行疯狗模式参数
    target_speed = 300;
}
```

#### 2. 按键 (KEY)：功能触发与参数归零
轮腿组涉及到陀螺仪积分，很容易产生漂移，或者需要临时调整腿部零点。

*   **场景一：陀螺仪零点校准（最重要！）**
    *   上场前，把车静止放在赛道上，按住 `KEY1` 保持 2 秒。车子内部程序读取当前的陀螺仪数据作为“零偏”，防止车子一跑就歪。
*   **场景二：一键复位/急停**
    *   调试时车子失控乱跑，为了保护电机和结构，设置 `KEY2` 为急停键，按下后 PWM 输出全部归零，腿部舵机泄力。
*   **场景三：腿部长度初始化**
    *   轮腿结构通电前腿是软的，通电瞬间需要知道“现在的腿有多长”。可以在特定姿态下按下 `KEY3` 告诉单片机：“现在是最短状态”。

#### 3. LED 灯：状态指示灯（Visual Debugging）
当车子跑在赛道对面时，你看不见电脑屏幕，LED 是唯一的反馈。

*   **场景一：电量/故障报警**
    *   电池电压低于 7.4V，LED **快闪**（提示换电池，防止控制失效摔车）。
*   **场景二：传感器状态**
    *   陀螺仪初始化成功：LED **常亮**。
    *   摄像头识别到圆环/断路：LED **闪烁一下**（让你知道车子看到了，如果没进去圆环，那就是控制写得烂，而不是图像没处理好）。
*   **场景三：姿态超限**
    *   当车身倾角太大（即将摔倒）时，点亮 LED，提示程序进入了“保护模式”。

### 第三部分：给你的修改建议（避坑指南）

这个例程有一个**致命**的问题，在实际控制代码中绝对不能照搬：

**千万不要在控制代码中使用 `system_delay_ms`！！！**

*   **原因：** 轮腿车的平衡控制周期通常是 1ms 到 5ms（1000Hz - 200Hz）。如果你在主循环里写了 `system_delay_ms(500)`，意味着单片机这 0.5 秒在发呆，**车子 0.5 秒不调整姿态，必倒无疑。**

**如何正确使用：**

你应该在定时器中断里控制车身平衡，在主循环里处理这些 LED 和按键逻辑，并且**使用“非阻塞”的方式**（记时法）。

**修改后的逻辑结构（伪代码）：**

```c
// 定义一个全局计时器变量，由定时器中断累加
uint32_t global_tick_ms = 0; 

int main(void)
{
    // 初始化...
    
    while(true)
    {
        // --- 1. 处理策略开关 (每100ms看一次就行) ---
        if(global_tick_ms % 100 == 0) {
            check_switches(); // 更新策略变量
        }

        // --- 2. 处理LED闪烁 (非阻塞) ---
        // 假设我们需要 500ms 闪烁一次
        static uint32_t last_toggle_time = 0;
        if(global_tick_ms - last_toggle_time > 500) 
        {
            led_state = !led_state;
            gpio_set_level(LED1, led_state);
            last_toggle_time = global_tick_ms; // 更新上次闪烁时间
        }
        
        // --- 3. 处理按键 (需要消抖) ---
        if(!gpio_get_level(KEY1)) {
            // 这里不要用 delay 消抖，而是判断按下的持续时间
            // 执行校准逻辑...
        }
    }
}

// 定时器中断 (1ms 一次)
void timer_interrupt_handler(void)
{
    global_tick_ms++;
    
    // 这里跑核心控制算法，绝对不能被 delay 卡住
    Balance_Control(); // 直立环
    Speed_Control();   // 速度环
    Leg_Control();     // 腿部控制
}
```

**总结：**
这给你的例程是用来**测试板子好坏**以及**学习怎么读引脚**的。在真正的轮腿组代码中，请把 Switch 和 Key 当作**战术开关**，把 LED 当作**仪表盘**，并且**坚决扔掉 delay 函数**。
