# 转向控制优化

【角色设定】
你是一位资深嵌入式平衡车控制工程师和自动控制专家，熟悉 C 语言、双核 CM7 架构、姿态解算、三环平衡控制、转向控制、舵机姿态执行和 PWM 融合。

【任务背景】
当前工程已经有直立平衡、转向控制、Rolling 横滚平衡环和舵机姿态执行逻辑。现在需要针对“转向时车身侧倾不足/转向稳定性不足”的问题做优化。

图片中给出了两个思路：
- 方案一：转向时引入主动 Rolling 目标，让车身在转弯方向产生合理侧倾，用姿态/舵机配合提高转向稳定性。
- 方案二：调整转向环或电机差速侧的参数与输出，让转向响应更强。

本次优先实现“转向时主动 Rolling”提示词，不要求直接改单边桥逻辑。单边桥场景只需要原有 Rolling 被动调节即可，不要把单边桥状态机作为本次优化对象。

【核心要求】
- `roll_balance_enable` 必须由统一的 Rolling 平衡环开关控制。
- 转向时新增的主动侧倾目标必须受 `roll_balance_enable` 控制。
- 当 `roll_balance_enable == 0` 时，转向主动侧倾必须不生效，并且不能残留旧的主动侧倾目标。
- Rolling 环默认开关必须写入 `code\config\sys_options.h`，不要把默认值写死在 `pid-new.c`。
- 不要修改单边桥已有主动/被动 Rolling 流程，除非只是阅读确认边界。

【推荐实现策略】
优先做方案一：转向主动 Rolling 目标。

建议做法：
- 在 `code\config\sys_options.h` 中新增 Rolling 平衡环默认开关，例如：
  `ROLL_BALANCE_ENABLE_INIT`
- 在 `code\calculate\pid-new.c` 中使用该宏初始化 `roll_balance_enable`。
- 新增或复用一个“转向主动侧倾目标”变量，不要直接覆盖单边桥使用的特殊测试目标，除非代码中已经明确共用 `roll_degree` 且不会影响其他场景。
- 主动侧倾目标应由转向请求生成，例如可基于 `err_degree`、目标 yaw rate、`turn_angle_loop_out` 或 `turn_gyro_loop_out` 做限幅映射。
- 主动侧倾目标必须带限幅、死区和斜率限制，避免转向瞬间舵机猛跳。
- 当转向请求回到死区、车辆停止、倒地、跳跃、刹车、推车模式或 `roll_balance_enable == 0` 时，主动侧倾目标必须平滑回零或立即清零。

【主动 Rolling 门控要求】
主动侧倾必须满足：

```c
if (roll_balance_enable == 0U) {
    active_turn_roll_target = 0.0f;
    // 不允许继续向 roll_degree 或 Rolling 控制目标写入有效侧倾
}
```

如果最终复用 `roll_degree` 作为 Rolling 目标，必须保证：
- 只有转向主动 Rolling 模块负责转向时写入。
- 单边桥、桥梁、测试状态机的写入不被本次改动破坏。
- 转向主动 Rolling 退出时不会把单边桥需要的 Rolling 目标清掉。

【禁止改动范围】
- 不要修改 `code\plan\bridge.c` 的单边桥状态机。
- 不要修改 `code\vision\vision_bridge_control.c` 的桥梁任务流程。
- 不要把单边桥主动侧倾门控当成本次任务。
- 不要改写 `Roll_Balance_Control()` 的核心 PID 公式，除非只是补充开关关闭时清零。
- 不要通过大幅提高转向 PID 参数或长期固定 duty 来掩盖问题。

【具体任务指令】
请在工程中实现“转向时主动 Rolling 优化”，要求最小化修改：

任务1：配置迁移
- 在 `code\config\sys_options.h` 中增加 Rolling 环默认开关。
- 在 `pid-new.c` 中让 `roll_balance_enable` 从该宏初始化。

任务2：转向主动侧倾
- 找到转向控制链路的合适位置，生成主动侧倾目标。
- 主动侧倾目标根据转向强度变化，带死区、限幅、斜率限制。
- 开关关闭或安全场景触发时，主动侧倾目标清零。

任务3：与被动 Rolling 环配合
- 转向主动侧倾只提供 Rolling 目标，不替代 `Roll_Balance_Control()`。
- `Roll_Balance_Control()` 仍负责根据实际 roll 与目标 roll 计算 `g_target_pwm_roll_adj`。
- `servo_executor.c` 仍按现有方式执行 `g_target_pwm_roll_adj`，不要重写舵机执行框架。

任务4：验证
- 检查新增变量声明、extern、include 和宏定义是否完整。
- 如果不能编译，至少做静态检查，确认没有未声明符号、重复定义和条件编译错误。
- 输出建议观测量：`roll_balance_enable`、主动侧倾目标、`roll_degree`、`euler_angle.roll`、`g_target_pwm_roll_adj`、`err_degree`、`turn_angle_loop_out`、`turn_gyro_loop_out`。

【验收标准】
- `roll_balance_enable` 默认值可通过 `sys_options.h` 配置。
- 关闭 Rolling 开关后，转向主动侧倾完全失效且无残留目标。
- 打开 Rolling 开关后，转向时能产生受限、平滑的主动侧倾目标。
- 单边桥已有被动 Rolling 调节逻辑没有被改动。
- 代码改动集中、可回退、可调参，不破坏现有转向和舵机执行框架。

- 禁止删除已有注释和调试逻辑。
