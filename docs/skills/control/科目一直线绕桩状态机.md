# 科目一直线绕桩状态机提示词

## 角色设定
你是一名资深嵌入式控制工程师和自动控制工程师，精通 C 语言、双核 MCU 架构、定时器/中断调度、惯导/GNSS 复刻、三环控制、速度闭环、前馈控制以及 PWM 融合。

## 任务背景
当前科目一流程是“直线过去，再回来绕桩”。我希望把控制逻辑拆成两个状态：
1. 直线状态：更偏向往前跑，重点是尽快建立速度。
2. 绕桩状态：更偏向稳定，参数更保守，控制更平顺。

另外，在直线与绕桩的状态机切换时，希望增加一个更快速的掉头/转向过渡效果，类似现在惯导复刻里“跑到最后一个点时，能瞬间转回出发时的角度”的感觉，让切换更迅速、更干脆。

## 核心目标
- 只实现一个主方案：新增独立的速度/加速前馈逻辑。
- 不用“动态放大 angle kp”作为方案。
- 不用长时间 bang-bang 或固定大 duty 粗暴拉满。
- 前馈必须可开关、可限幅、可平滑上升/释放。
- 现有 PID、三环控制、刹车前馈、PWM 融合框架都要保留，只做局部增强。

- `current_actual_speed` 的计算方式和正负号约定。
- 当前 `Servo_Speed_Control()` 是否只影响 `g_target_pwm_speed_adj`，以及 `speed_loop_out` 是否真的参与了 `Angle_Loop_Control()`。
- 最终电机 PWM 融合点是不是类似 `gyro_loop_out + brake_pwm + turn_gyro_loop_out` 这一类结构。
- 刹车前馈与急停、倒地、推车模式、复刻停止等逻辑如何互斥。

## 设计要求
### 1. 新增状态机
建议拆成至少三个状态：
- `STRAIGHT`：直线加速状态
- `TURN`：绕桩稳定状态
- `TURN_TRANSITION`：直线切到绕桩时的快速掉头过渡状态

### 2. 新增前馈模块
只新增一个独立的加速/速度前馈模块，例如：
- `Accel_Feedforward_Update()`
- `Accel_Feedforward_GetPwm()`
- `Accel_Feedforward_Reset()`

这个模块要和现有刹车前馈并列，不要互相混写。

### 3. 直线与绕桩两套参数
直线状态和绕桩状态要能使用两套参数，至少包括：
- 前馈增益
- 前馈最大值
- 启动窗口
- 上升斜率
- 退出斜率
- 死区
- 速度误差阈值

### 4. 快速掉头逻辑
在直线状态切换到绕桩状态时：
- 如果目标角度/目标速度变化满足切换条件，就短时间输出一个快速角度/速度前馈。
- 目的是让车头尽快回到绕桩所需的方向，而不是慢慢拐。
- 前馈要在达到目标附近后自动退出，回到原有三环稳定控制。

## 代码实现约束
- 只允许在原有中断、控制函数、前馈模块、PWM 融合框架内做局部修改。
- 不要重构整个导航或控制链路。
- 不要删除原有注释、TODO、特殊标记。
- 新增宏定义要集中放在头文件，方便调参。
- 所有新增变量、函数、状态都要保证可编译、可关闭、可观测。
- 最终左/右 PWM 仍需经过现有限幅函数，不能突破系统最大限制。

## 必须处理的安全场景
以下场景必须清零或禁止前馈：
- `g_motor_enable == 0`
- `jump_flag != 0`
- `g_is_push_mode == 1`
- 刹车前馈有效
- 倒地保护
- 复刻停止
- 终点停车
- GNSS 失效停车
- 导航对齐阶段停车

## 建议的判断条件
前馈只建议在这些场景介入：
- 复刻正在运行
- 目标速度相对上周期明显增大
- 当前速度明显低于目标速度
- 处于启动后的短窗口期
- 直线转绕桩状态切换窗口内

## 验证重点
- 直线起步时，速度建立更快。
- 切到绕桩时，车头能快速掉头。
- 稳态绕桩时，前馈自动退出，不影响原有稳定性。
- 刹车、停止、倒地、推车、GNSS 失效时，前馈必须清零。
- 最终 PWM 不超限，不破坏现有三环和刹车前馈。

## 严格禁止
- 禁止用动态放大 `pid_angle.kp` 代替方案。
- 禁止做长时间 bang-bang。
- 禁止让加速前馈和刹车前馈同时强输出。
- 禁止在未确认电机方向、速度符号、PWM 极性前就写死前馈符号。
- 禁止重构控制框架或改掉现有调用链。
