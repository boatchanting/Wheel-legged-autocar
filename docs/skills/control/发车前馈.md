【推荐实现策略】
只实现“独立加速 PWM 前馈项”，仿照刹车前馈的结构做最小化新增：

- 在 `pid-new.h` 增加可调宏，命名风格参考 `BRAKE_*`，例如：
  - `ACCEL_FF_ENABLE`
  - `ACCEL_FF_ERR_MIN`
  - `ACCEL_FF_TARGET_STEP_MIN`
  - `ACCEL_FF_SPEED_DEADBAND`
  - `ACCEL_FF_GAIN`
  - `ACCEL_FF_MAX`
  - `ACCEL_FF_RAMP_UP`
  - `ACCEL_FF_RAMP_DOWN`
  - `ACCEL_FF_START_WINDOW_MS`
  - `ACCEL_FF_SIGN`
- 在 `pid-new.c` 内维护静态状态，例如上一周期目标速度、起步窗口计数、当前前馈 PWM、目标前馈 PWM。
- 前馈输出必须有斜率限制、最大幅值限制、低速死区和退出回落，不能直接阶跃到大 duty。
- 前馈只在“加速请求”中生效：`abs(target_speed)` 明显大于 `abs(actual_speed)`，且目标速度相对上一周期有明显增大，或者处于复刻刚启动的短窗口。
- 如果目标速度符号与实际速度符号不一致，必须先判断这是起步、换向还是刹车；不允许与 `Brake_Feedforward_Update()` 抢控制。

【PWM 融合要求】
速度前馈应叠加到和 `brake_pwm` 同一条前后驱动轴上，不要简单地给左右轮都 `+ duty_base`。

推荐融合形式：
```c
float brake_pwm = Brake_Feedforward_GetPwm();
float accel_ff_pwm = Accel_Feedforward_GetPwm();
float drive_ff_pwm = brake_pwm + accel_ff_pwm;

int16_t pwm_left  = (int16_t)( gyro_loop_out + drive_ff_pwm + turn_gyro_loop_out);
int16_t pwm_right = (int16_t)(-gyro_loop_out - drive_ff_pwm + turn_gyro_loop_out);
```

注意事项：
- 以上符号必须结合当前电机极性、速度符号和刹车前馈方向验证；必要时通过 `ACCEL_FF_SIGN` 调整。
- 如果发现 `accel_ff_pwm` 输出后实际变成减速，说明符号方向错了，必须先修正符号，不要继续加大增益。
- 最终左右 PWM 仍必须经过现有 `Float_Constrain()` 限幅，不能超过 `OUR_PWM_MAX_LIMIT`。

【介入场景要求】
速度前馈默认只允许在以下场景介入：
- 惯导复刻正在运行：`g_replay_state == REPLAY_RUNNING`。
- GPS 复刻正在运行：`g_gps_replay_state == REPLAY_RUNNING`（注意 `GNSS_NAV` 条件编译）。
- 复刻刚启动后的短窗口，例如 `NavReplay_Start()` 或 `GpsNavReplay_Start()` 后的若干百毫秒。
- 运行中目标速度相对上一周期明显增大，并且当前速度距离目标速度超过阈值。

必须禁止介入的场景：
- `g_motor_enable == 0`。
- `jump_flag != 0`。
- `g_is_push_mode == 1`。
- `g_brake_active != 0` 或 `g_reverse_brake_active != 0`。
- `Brake_Feedforward_GetPwm()` 当前非零或刹车前馈处于有效减速输出。
- 倒地保护、复刻停止、终点停车、GNSS 无效停车、导航对齐阶段停车。
- 颠簸、桥、三级跳等特殊状态机正在强制锁速或接管速度时，除非代码中能明确证明该状态也需要急加速前馈。
