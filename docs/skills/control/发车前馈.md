【推荐实现策略】
优先实现“独立速度前馈 PWM 项”，不要一开始就永久修改 `pid_angle.kp`：
- 仿照刹车前馈新增 `Accel_Feedforward_Update()`、`Accel_Feedforward_GetPwm()`、`Accel_Feedforward_Reset()`。
- 在 `pid-new.h` 增加可调宏，命名风格参考 `BRAKE_*`，例如：
  - `ACCEL_FF_ENABLE`
  - `ACCEL_FF_ERR_MIN`
  - `ACCEL_FF_TARGET_STEP_MIN`
  - `ACCEL_FF_SPEED_DEADBAND`
  - `ACCEL_FF_GAIN_LIGHT`
  - `ACCEL_FF_GAIN_HEAVY`
  - `ACCEL_FF_MAX_LIGHT`
  - `ACCEL_FF_MAX_HEAVY`
  - `ACCEL_FF_RAMP_UP`
  - `ACCEL_FF_RAMP_DOWN`
  - `ACCEL_FF_START_WINDOW_MS`
  - `ACCEL_FF_SIGN`
  - `ACCEL_FF_MODE`
- 在 `pid-new.c` 内维护静态状态，例如上一周期目标速度、起步窗口计数、当前前馈 PWM、目标前馈 PWM。
- 前馈输出必须有斜率限制、最大幅值限制、低速死区和退出回落，不能直接阶跃到大 duty。
- 前馈只在“加速请求”中生效：`abs(target_speed)` 明显大于 `abs(actual_speed)`，且不是刹车/减速/反向制动场景。
- 如果目标速度符号与实际速度符号不一致，必须先判断这是起步、换向还是刹车；不允许与 `Brake_Feedforward_Update()` 抢控制。
- 最终融合建议先形成 `drive_ff_pwm = brake_pwm + accel_ff_pwm`，再在现有差动电机输出位置叠加。具体符号必须根据当前电机极性和刹车前馈方向验证，必要时用 `ACCEL_FF_SIGN` 宏调整，不要硬编码假设。

【介入场景要求】
速度前馈默认只允许在以下场景介入：
- 惯导复刻正在运行：`g_replay_state == REPLAY_RUNNING`。
- GPS 复刻正在运行：`g_gps_replay_state == REPLAY_RUNNING`（注意 `GNSS_NAV` 条件编译）。
- 复刻刚启动后的短窗口，例如 `NavReplay_Start()` 或 `GpsNavReplay_Start()` 后的若干百毫秒。
- 运行中（不管是复刻还是遥控器控制）目标速度相对上一周期明显增大，并且当前速度距离目标速度超过阈值。

必须禁止介入的场景：
- `g_motor_enable == 0`。
- `jump_flag != 0`。
- `g_is_push_mode == 1`。
- `g_brake_active != 0` 或 `g_reverse_brake_active != 0`。
- `Brake_Feedforward_GetPwm()` 当前非零或刹车前馈处于有效减速输出。
- 倒地保护、复刻停止、终点停车、GNSS 无效停车、导航对齐阶段停车。
- 颠簸、桥、三级跳等特殊状态机正在强制锁速或接管速度时，除非代码中能明确证明该状态也需要急加速前馈。

【可选方案 A：动态角度环 Kp】
如果选择验证“速度差过大时放大 angle 环 Kp”，必须遵守：
- 不要永久修改 `pid_angle.kp`，只在 `Angle_Loop_Control()` 内使用局部变量 `kp_adj`。
- `kp_adj = pid_angle.kp * boost`，其中 `boost` 必须由速度误差平滑计算，并设置最大倍数，例如 1.2~1.8，不允许无上限。
- boost 只在复刻起步或急加速场景启用，退出时必须平滑回到 1.0。
- 必须同时观察俯仰角、角速度环输出、最终 PWM 是否饱和；如果引发抬头/点头振荡，优先降低 boost 或改用独立 PWM 前馈。
- 不能通过修改全局 `pid_angle.kp` 来实现，否则会影响所有场景和 WiFi 在线调参。

【可选方案 B：bang-bang duty】
如果选择验证 bang-bang 急加速：
- 只允许作为短时起步辅助，不允许长期闭环运行。
- 必须设置持续时间、速度误差退出阈值、最大 duty、斜率限制和冷却时间。
- 必须与刹车前馈互斥；一旦进入刹车、停车、目标速度下降或复刻停止，立即按斜率释放并 reset。
- 必须保留一个宏开关，默认可以关闭，方便快速回退。
