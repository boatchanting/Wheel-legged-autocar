## 1. 背景与目标

### 1.1 现状（旧管线）

- 1核 侧：`code1/vision/bridge_vision.c` 检测桥黑块/左右边线/上边线/中心线，经 IPC 送 0核。
- 0核 侧：`code/vision/vision_bridge_control.c` 2ms 状态机（IDLE→ALIGN→RUN→EXIT→FINISH）消费中心线端点 → IPM 前视差角 → `err_degree`。
- 旧管线问题：中心线提取粗糙、退出靠 `up_line` 启发式（端点均值<10）、无退出线精确位置。

### 1.2 新管线（trials/bridge）

- `bridge_detect.c/.h`：单边桥三线透视结构提取（**红=左界 / 绿=中缝 / 蓝=右界**）+ **粉色退出线**（MLP 结束线）。
- 输入 94×60 uint8 灰度（与主工程 1核 图像尺寸一致）；性能 avg≈5.54ms/帧（250MHz），预算 ≥8ms/帧。
- 输出 `bridge_result_t`：`mode`（NONE/R/B/M/RB/RMB/RM/MB/RB_Q）、`has_red/green/blue/top`、三条竖线 + 顶线的**拟合系数**（`x=a·y+b` / `y=a·x+b` + rms + 支撑范围 `u_lo/u_hi`）、`spacing`、`mid_ratio`、`gate`（底部变白锁存）。
- 跨帧状态：`gate` 锁存 + 间距滑动窗 + 先验间距自校准（`wp_a/wp_b`）；上桥需 `bridge_detect_init` 复位。
- 依赖：汇编算子（仅 Cortex-M7/SMLAD）、TCM 段、C99；无动态内存、无中断、非阻塞。

### 1.3 接入目标

把新管线接入 0核 桥任务状态机，实现：
1. **中线取信逻辑**（§3.3）替换旧中心线；
2. **上桥/出口判定**改由新信号驱动；
3. **退出视觉-惯导融合**（§6）：用退出线位置 + IPM + 惯导精确锚定"轮子退出桥面那一下"。

## 3. 总体架构决策（本轮已确认）

### 3.1 控制层契约（不可变）

控制层只消费以下全局量，与视觉来源无关：

| 全局量 | 语义 | 桥任务负责填 |
| --- | --- | --- |
| `err_degree` | 转向角（度），控制层闭环到 0 | 视觉几何差角 **或** 锁角差，见 §3.3/§7 |
| `target_speed_set` | 目标速度（负数=前进） | 各阶段速度宏 |
| `servo_height` | 高度姿态（3.0↔6.0 步进） | `Bridge_Apply_Height_Control` |
| `acc_limit/dec_limit` | 舵机斜率 | 上桥 100 / 下桥恢复 |
| `roll_balance_enable` | Roll 环（当前恒 0） | 维持 0 |
| `g_special_action_trigger` | 接管标志 | 进入置 1，结束清 0 |

### 3.2 双核分工（核心原则，反复确认过）

- **1核**：只负责"视觉信号自身"——检测 + **空间仲裁**（mode→控制线）+ 发布；不承诺任何跨源平滑（它没有惯导）。
- **0核**：拥有全部"物理/时序"逻辑——IPM 查表、位姿旋转、`trusted_valid` 防抖、**视觉↔锁角换源 ramp**、里程门、状态机推进、**退出融合**。
- 理由：锁角误差（`locked_yaw−relative_yaw`）只有 0核 能算，换源平滑只能在 0核；1核 连锁角误差是多少都不知道。

### 3.3 中线取信逻辑（仲裁规则，已确认）

| 新模块 mode | 判定 | 控制参考线 |
| --- | --- | --- |
| `RB`(4) 红+蓝 | ✅ 以左右边线为准 | **红蓝中点线** $x(y)=\frac{x_{red}(y)+x_{blue}(y)}{2}$ |
| `RMB`(5) 红+绿+蓝 | ✅ 以左右边线为准 | 红蓝中点线（绿线仅校验） |
| `RM`(6) 红+中线 | ✅ 直接出中线 | 绿线 $x_{green}(y)$ |
| `MB`(7) 中线+蓝 | ✅ 直接出中线 | 绿线 $x_{green}(y)$ |
| `R`(1)/`B`(2)/`M`(3)/`NONE`(0)/`RB_Q`(8) | ❌ **视觉失能** | 回退锁角 |

- **可信度序**：红蓝两线 > 绿线；`RB_Q` 即使有两线也判失能（保守）。
- 仲裁在 **1核** 完成，输出"仲裁后的控制线 + 原始可信标志"（见 §4）。

## 4. IPC 传输协议设计（b2_* 块）

### 4.1 设计原则

- 在 `vision_ipc_packet_t` 尾部**新增 `b2_*` 字段块**；旧 `bridge_*` 字段**保留过渡**（编译开关切换，稳定后清理）。
- 控制线以**直线系数**形式传输（比两点更好：定点精度、内点支撑诚实、原生输出、0核 可自选前视行）——§4.2 有对比结论。
- 沿用 `seq` 门控、`valid_mask`、CRC、`frame_dt_us/cost_us`。

### 4.2 为什么传直线而不是两点（决策记录）

两点与 (a,b)+支撑**数学等价**（可无损互转），差异在工程：定点精度（端点取整 ±0.5px vs 系数 ×1000 达 0.01px）、支撑诚实性（u_lo/u_hi 是内点真实支撑 vs 端点暗示）、1核 是否做额外转换（a,b 是原生输出）、0核 消费成本（一次 MAC）与扩展性（可改前视行）。**结论：传直线。**

### 4.3 字段表（b2_* 块）

| 字段 | 类型 | 定点 | 语义 | 0核 消费点 |
| --- | --- | --- | --- | --- |
| `b2_valid` | uint8 | — | 本帧仲裁后控制线**原始可信** | 防抖后决定视觉/锁角 |
| `b2_source` | uint8 | — | 0=红蓝中点 1=绿线 2=失能 | 诊断 |
| `b2_line_a` | int16 | ×1000 | 控制线斜率 `x=a·y+b` | 第①级代入 y=25 |
| `b2_line_b` | int16 | ×100 | 控制线截距 | 同上 |
| `b2_line_u_lo` | uint8 | — | 控制线支撑 y 下限 | 校验 `25∈[u_lo,u_hi]` |
| `b2_line_u_hi` | uint8 | — | 控制线支撑 y 上限 | 同上 |
| `b2_mode` | uint8 | — | 原始 mode（0~8） | 状态机：上桥判定 |
| `b2_gate` | uint8 | — | 底部变白锁存 | 状态机：上桥判定 |
| `b2_has_top` | uint8 | — | 退出线有效（需 gate=1） | 退出融合触发候选 |
| `b2_top_a` | int16 | ×1000 | 退出线斜率 `y=a·x+b`（横线） | 退出融合 IPM 锚定 |
| `b2_top_b` | int16 | ×100 | 退出线截距 | 同上 |

| `b2_mid_ratio` | uint16 | ×1000 | 中线底间距比 | 诊断（可选） |

### 4.4 坐标系约定

- 控制线/退出线均为**图像坐标**（94×60，y 上小下大），与旧 `center_line` 同构、与 IPM 表（`code1/vision/ipm_transform.c`，已链入 0核）同构。

## 6. 退出视觉-惯导融合设计

### 6.1 目标

精确判定"**桥面侧车轮接地点越过桥面远端边线**"的时刻（即退出那一下），用于：
1. 精确触发 EXIT 缓冲段（下腿时机可提前规划）；
2. （可选）为导航 rebase 提供更准的出口绝对坐标。

### 6.2 算法流程（推荐：1 维 EKF，全部在 0核）

**状态** = 车体参考点到出口线的剩余距离 `d`（mm，沿行驶方向）。出口线是横向贯穿线，只需求纵向距离；标量状态天然避免"车体系↔世界系"旋转与轴约定坑（IPM"X 右 Y 前" vs 惯导"x 前 y 左"）。

```
【时间更新】每 2ms tick —— 轮速计预测（高频，直接用对外 API）
  d_pred = d − v_body·dt
  // v_body = (vL+vR)/2（mm/s）：small_driver_get_speed() 开启后
  // motor_value.receive_left/right_speed_data（int16，10ms 上报）× SPEED_TO_MM_S 换算
  P_pred = P + Q                       // Q ∝ 里程不确定度；slip_flag 打滑时 Q↑（降权预测）

【测量更新】视觉帧到达，且 b2_has_top && b2_gate && y_meas < EXIT_MEAS_GATE_MM(≈1500)
  z = y_exit_body_mm                   // IPM 前向距离（车体系，无需旋转；与预测共参考点）
  R = R0·(z / Z_REF)²                  // 远处测量噪声大（透视放大），自适应
  K = P_pred / (P_pred + R)
  d = d_pred + K·(z − d_pred)
  P = (1−K)·P_pred

【初始化】第一次可靠测量（has_top && gate && 近距）→ d = z, P = P0

【越过判定】每 tick
  d_exit = d − offset_wheel(servo_height)   // 车轮接地点补偿（腿几何标定表）
  d_exit ≤ 0 → 触发 EXIT
```

**为什么 EKF 优于"多帧锚定"**：
- **R 随距离自适应**：近处视觉可信（K 大、快速收敛），远处噪声大（K 小、少污染）；
- **每帧持续修正**，而非"锚定一次后纯惯导"；
- **无视觉帧靠预测维持**（轮速计里程自然续上），丢线不中断；
- **显式不确定性 P**，可为触发加置信门限（P 过大时保守触发）；
- **打滑降权**：`slip_flag` 时增大 Q，避免桥上打滑污染预测。

### 6.3 参考点与腿几何补偿

- **EKF 状态参考点**：车体参考点（惯导 `x/y` 位置）。测量 `z`（IPM 前向距离）相对**摄像头**，两者有固定纵向偏移——需统一参考点：`z_body = z_cam − cam_to_body_offset`（标定），否则预测与测量存在固定偏置（实施时列为显式核对项）。
- **越过判定参考点** = **车轮接地点**（不是车身/质心；车为双轮足并联腿，无前后轮）：`d_exit = d − offset_wheel(servo_height)`。
- 车体→车轮接地点的纵向偏移是**腿几何函数**（随 `servo_height` 变化）；实施前需标定 `offset_wheel(servo_height)` 表；若实测位移可忽略则简化。
- ⚠️ **轮速计↔视觉系统误差需提前标定**（EKF 两元 = 视觉测量 + 轮速计里程预测）：① 轮径/里程标度（`SPEED_TO_MM_S` 换算）；② 打滑误差模型（桥上/颠簸 `slip_flag` 时 Q↑）；③ 摄像头→车体参考点纵向偏移 `cam_to_body_offset`；④ `offset_wheel(servo_height)`。这些系统性误差不标定，EKF 预测与测量会有固定偏置，收敛后的 `d` 仍带误差。
- ⚠️ 轴约定：IPM 是"X 右、Y 前"，`inertial_nav` 是"x 前、y 左"——1 维 EKF 天然规避旋转；仅未来扩展 2D 状态时才涉及。

### 6.4 与 rebase 的关系

- 现状：`Plan4_CompleteSpecial` 仅 `VISUAL_CONFIRMED` 时把 `nav_vision_fusion` rebase 到**路表出口点**。
- 融合出的 `exit_world` 比路表出口点更"实测"；做成**宏开关**（`BRIDGE_V2_REBASE_FROM_FUSION`，默认关），开时融合结果进 rebase，A/B 对比后定默认值（2026-08-08 确认）。

| `EXIT_EKF_P0_MM2` | `6400.0f` | mm² | 首次注入时初始协方差 ≈ R0·(gate/Z_REF)² = 1000×(1500/600)² |
| `EXIT_WHEEL_OFFSET_MM` | `0.0f`（待标定） | mm | 车轮接地点相对车体参考点纵向偏移（腿几何 offset_wheel(servo_height)，未标定前默认 0） |

## 7. 平滑与防抖设计（汇总）

| 项 | 位置 | 量化目标 |
| --- | --- | --- |
| 线系数噪声（1~3px） | 0核 α=0.40 滤波 | 吸收（复用现有） |
| 跳变拒绝（8°/8px、3°/3px 确认） | 0核（复用） | 视觉源内部 |
| `trusted_valid` 防抖 | 0核（C09） | 失能 N≈5~10 帧、恢复 M≈3~5 帧 |
| **换源 ramp（视觉↔锁角）** | 0核（C10，**只能在 0核**） | ≤0.5°/2ms-tick |
| 控制参考线切换（红蓝中点↔绿线） | 1核 仲裁 + 0核 平滑 | 差异小时忽略，大时走 ramp |
| 退出线锚定滤波 | 0核（C13） | 仅近距锚定 + 多帧 |

参照系：Plan4 交接回导航用 `PLAN4_SPECIAL_HANDOFF_ERR_STEP_DEG=1.0`（1°/10ms）ramp，是系统"舒适变化率"参考；换源硬切换 10°+ 会超舒适区，必须 ramp。
