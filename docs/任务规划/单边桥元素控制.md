既然你的硬件具备**四轮独立舵机高度调节**的能力，并且**拥有全局惯导数据（精确测距）、桥的高度已知、且知道是左右交替**。

这就意味着你手握着一把“屠龙刀”。如果选择“硬开过去”（底盘锁死），无异于拿屠龙刀砍柴。**最快、最稳的方案绝对是“主动伸缩腿（自适应姿态）”。**

针对这种堪称完美的已知条件，我为你整理了 **4 种由简入深的控制策略方案**。你可以根据距离比赛的时间和代码调车能力，选择最适合的一种。

---

### 方案一：纯闭环反馈流（被动适应策略）—— 稳妥保底方案
*   **原理**：不管前方有什么，只要车身歪了，我就把它拉平。
*   **实现方式**：在底层的 1ms/5ms 定时器中，始终运行一个 **Roll (横滚角) PID 控制器**。当单侧车轮上桥导致车身倾斜（Roll 偏差增大）时，PID 计算出偏差，自动收缩高处的腿，伸长低处的腿。
*   **优点**：代码最简单，不依赖里程计精度，对桥的真实高度不敏感（桥高3cm还是4cm，PID都能自动稳住）。
*   **缺点**：**有滞后性**。车必须“先被颠歪”，PID 才会介入。在高速（>1.5m/s）下，上桥瞬间的冲击力会让车身剧烈抛跳，PID 反应不过来，容易导致摄像头瞬间致盲丢线。
*   **速度上限**：中等（约 1.2m/s - 1.5m/s）。

---

### 方案二：纯开环前馈流（盲操变形策略）—— 激进竞速方案
*   **原理**：既然我已经知道单边桥距离我还有 10cm，桥高 3cm。我干脆在距离桥 1cm 的时候，**瞬间把那一侧的腿缩短 3cm**，假装那里没有桥。
*   **实现方式**：完全依赖 `bridge.c` 的状态机和 `InertialNav_t` 的距离测算。到达触发距离 `trigger_dist` 时，直接给 `g_target_pwm_roll_adj` 赋一个**死值**（等于桥高对应的 PWM），并把舵机斜率 `acc_limit` 拉到最大，瞬间执行。
*   **优点**：**没有滞后！** 上桥瞬间车身姿态完美水平，丝滑得像走平地，可以全速冲刺。
*   **缺点**：**容错率为零**。如果你的惯导里程计有一点点漂移（比如实际离桥还有 5cm，系统以为到了），车就会在平地上突然“瘸”一条腿，底盘磕地；或者上桥晚了，车被弹飞。
*   **速度上限**：极高（> 2.5m/s），但翻车率也高。

---

### 方案三：前馈预判 + 闭环微调（融合策略）—— 🏆 冠军主流方案
*   **原理**：结合前两种的优点。走到桥前，先用“前馈”主动把腿缩短 80%（抵消掉撞击瞬间的剧烈冲击），剩下的 20% 误差以及行驶过程中的抖动，交给“Roll PID”去吸收。
*   **实现方式**：
    1.  **宏观状态机 (`bridge.c`)**：算出距离桥还有 5cm 时，输出一个前馈量 `Feedforward_PWM = 0.8 * 桥高对应PWM`。
    2.  **微观控制器 (`pid.c`)**：底层的 Roll PID 始终开启。
    3.  **最终输出**：`g_target_pwm_roll_adj = Feedforward_PWM + Roll_PID_Out`。
*   **优点**：**极致的速度与极高的稳定性**。前馈抵消了上桥瞬间的物理冲击，底盘基本不跳；PID 容忍了里程计的测距误差和桥面的不平整。面对“左右交替桥”，这种方案能让底盘像悬浮在空中一样。
*   **缺点**：需要调校“前馈触发距离”和“PID参数”的配合。
*   **速度上限**：极高（拉满电机极限）。

---

### 方案四：四轮独立运动学规划（降维打击策略）—— 国赛顶级车方案
*   **原理**：单边桥不仅有 Roll（横滚），在刚上桥时还有 Pitch（俯仰）。真正的车轮是一前一后上桥的，所以四条腿不应该一起动。
*   **实现方式**：
    *   **左前轮触桥**：单独收缩左前腿。
    *   **左后轮触桥**（半个车身长度后）：单独收缩左后腿。此时车身完全水平。
    *   **左前轮下桥**：单独伸长左前腿。
    *   **左后轮下桥**：单独伸长左后腿。
*   **优点**：绝对的“贴地飞行”，摄像头画面不会有哪怕 1 度的晃动。
*   **缺点**：逻辑复杂，需要维护四个轮子的独立状态机，而不是简单的 `左侧/右侧` 联动。

---

### 🚀 强烈建议：采用【方案三：前馈预判 + 闭环微调】

基于你现有的代码架构，实施**方案三**是最具性价比的。下面是关键的逻辑伪代码：

#### 1. 底层控制 (`pid.c` 或 1ms 定时器)
保留一个简单的 Roll PID，它只负责把车身拉平。
```c
// 底层始终在运行这个 PID
float roll_error = 0.0f - inertial_nav.roll; // 目标永远是水平 0 度
int16 roll_pid_out = (int16)(Kp * roll_error + Kd * (roll_error - last_error));

// 最终叠加给舵机的补偿量 = 前馈量(状态机给的) + 闭环反馈量(PID算的)
g_target_pwm_roll_adj = bridge_feedforward_pwm + roll_pid_out; 
```

#### 2. 上层状态机 (`bridge.c` 的 Update 函数中)
用你极其精准的 `InertialNav_t` 进行测距触发前馈。

```c
// 假设已知单边桥参数：
#define BRIDGE_HEIGHT_PWM 400  // 桥高对应的舵机收缩PWM值
#define WHEELBASE 200.0f       // 前后轮轴距 200mm

switch(current_bridge_state) {
    case BRIDGE_STATE_READY:
        // 维持高速，不要刹车太狠！
        target_speed_set = bridge_params.speed_high; 

        // 核心：前馈触发！当距离桥头仅剩 50mm 时，提前变形
        if (remaining_dist < 50.0f) {
            
            // 假设这是左边上桥
            if (next_bridge_side == LEFT_SIDE) {
                // 直接给出前馈量，瞬间把左腿缩短（假设正数代表左腿收缩，右腿伸长）
                bridge_feedforward_pwm = BRIDGE_HEIGHT_PWM; 
            } else {
                bridge_feedforward_pwm = -BRIDGE_HEIGHT_PWM; 
            }

            // 解除舵机速度限制，让腿瞬间弹上去
            acc_limit = 100; 
            dec_limit = 100;
            
            current_bridge_state = BRIDGE_STATE_ON_BRIDGE;
        }
        break;

    case BRIDGE_STATE_ON_BRIDGE:
        // 在桥上行驶时，前馈保持 bridge_feedforward_pwm 不变。
        // 底层的 roll_pid_out 会自动吸收掉桥高不准导致的微小倾斜。
        
        // 当距离行驶完毕（准备下桥）前 50mm 时
        if (bridge_params.on_bridge_length - Get_Traveled_Distance() < 50.0f) {
            // 撤销前馈量，腿瞬间伸直，准备落地
            bridge_feedforward_pwm = 0; 
            
            // 进入下一个交替桥的准备状态 (例如无缝衔接右桥)
            current_bridge_state = BRIDGE_STATE_LEAVING;
        }
        break;
}
```

### 总结建议
如果你直接**硬开**，不管你的电机多强，底盘的几何干涉和重心转移都会把你的赛车抛飞。
既然你连 `bridge.c` 都要重构，而且有极其宝贵的**全局坐标数据**，**请务必采用前馈（测距到点瞬间缩腿）+ PID微调**的策略。这就是智能车单边桥项目里所谓的**“凌波微步”**。
