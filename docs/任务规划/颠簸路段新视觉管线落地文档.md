## 1. 现状与目标

### 1.1 现有（被替代）视觉

| 项 | 旧算法（`code1/vision/bumpy_vision.c`） |
|---|---|
| 输入 | 188×120 原图 `image_copy[0]` |
| 输出 | 全图结构张量方向向量 `direction_x/y` + `coherence_r` + `is_bumpy` |
| 缺点 | 只给"全局条纹方向"，没有左右边线；无法稳定输出横向偏差；方向上无时间验证 |

### 1.2 新管线（`trials/bumpy-road-new`）

```
94×60 灰度 → 7-tap 卷积(汇编 SMLAD/SMLAL, ITCM)
  → 平面区域二值化(p85分位) → 横向条纹掩膜(整数 tan² 免 atan2)
  → 8邻域连通域 + PCA 域方向角 → 外点提取(倾角外扩跨域剔除)
  → RANSAC(穷举对) 边线拟合 → 帧航向角 + 夹角门控 → 时间验证(连续稳定)
  → 左右边线 bumpy_line_t { valid, ang[0,180), cx, cy, n }
```

- 性能：avg 5.56ms / p99 6.08ms / max 13.65ms（@250MHz，板端实测）
- 正确性：PC 对拍存在性一致 99.7%，双侧显示参数通过率 100%

## 3. 决策二：输出对准（核心映射）

### 3.1 坐标系对照

| 坐标系 | 定义 |
|---|---|
| 新管线图像系 | x = 列(右+)，y = 行(**下+**，C 数组行优先)；`ang = atan2f(vy,vx)`（PCA 主轴角）∈ [0,180)，即**条纹延伸方向**相对 +X 轴角度 |
| IPC 契约 | `yaw_error_deg_x100` 正=需右转；`lateral_mm` 正=车身偏右；`direction_x/y` 条纹主方向（图像 +Y=前/下，+X=右） |

### 3.2 映射表（新管线 → IPC）

| IPC 字段 | 来源 | 公式/规则 |
|---|---|---|
| `bumpy_detected` | 边线存在性 | `res.L.valid \|\| res.R.valid`（可在宏 `BP_ADAPTER_DETECT_BOTH=0` 改为两侧都有效才算） |
| `bumpy_direction_x/y` | 条纹方向角 | `dir_x = cosf(ang)`, `dir_y = sinf(ang)`。因 `ang∈[0,180)` ⇒ `dir_y ≥ 0`，天然满足"方向指向图像下/前方"约定，**无需 180° 消歧** |
| `yaw_error_deg_x100` | 条纹法向 vs 车头 | `err = atan2f(-sinf(ang), cosf(ang))`（°），`×100` 取 int16。**正 = 需右转**。推导见 §3.3 |
| `lateral_mm` | 左右边线中心 + IPM | 仅双侧有效时更新：`row=(L.cy+R.cy)/2`，`cxs=(L.cx+R.cx)/2`；`lateral = IPM(47,row).x_mm − IPM(cxs,row).x_mm`（车身偏右为正）；IPM 无效(`IPM_INVALID_VAL`)不更新 |
| `meas_valid` | 双侧有效 + IPM 有效 | `res.L.valid && res.R.valid && IPM有效`；单侧有效时**只置 bumpy_detected，不置 meas_valid**（横向无意义，避免记录向 0 漂移） |

### 3.3 偏差角度推导（务必理解，别照抄符号）

条纹方向角 `ang`（条纹延伸方向，headless）。车要沿**条纹法向**行驶：

```
法向 n = (cos(ang+90°), sin(ang+90°)) = (−sin ang, cos ang)
航向偏差 = n 相对车头(图像 +y/前)的夹角，向右为正:
  err = atan2(n_x, n_y) = atan2(−sin ang, cos ang)
```

自检：
- 条纹水平（`ang=0`，直行正前方）：`err = atan2(0,1) = 0°` ✓
- 条纹向右下倾（`ang=+10°`，法向偏左）：`err = atan2(−0.17, 0.98) = −10°`（需左转，负）✓

> ⚠️ **与旧算法的差异**：旧 `vision_bumpy_calc_err_degree` 用 `−atan2f(dir_x, dir_y)`（条纹方向相对前向，天然 ±90° 偏移且从未真正启用过）。新公式是**物理正确的航向偏差**。0 核侧 `VISION_BUMPY_YAW_SIGN`（默认 +1）仍保留，实车反向就翻它，不再需要动公式。

### 3.4 角度环绕平均（双侧有效时）

L/R 两侧条纹角应近似平行，取 doubled-angle 平均防 0°/180° 跳变：

```c
/* 双侧有效: 角度×2 取 sin/cos 平均再折半 */
static float line_angle_avg(float a, float b)
{
    float r1 = a * (3.14159265f / 180.0f) * 2.0f;
    float r2 = b * (3.14159265f / 180.0f) * 2.0f;
    float sx = sinf(r1) + sinf(r2);
    float sy = cosf(r1) + cosf(r2);
    float avg = atan2f(sx, sy) * 0.5f * (180.0f / 3.14159265f);
    if (avg < 0.0f) avg += 180.0f;   /* 归一化回 [0,180) */
    return avg;
}
```

### 3.5 符号验证清单（实车必做，见 §9）

1. 车在中心线右侧 5~10cm → 上位机 `lateral_mm > 0`；
2. 车头偏右 → `yaw_error_deg_x100 > 0`（否则翻 `VISION_BUMPY_YAW_SIGN`）；
3. 出颠簸偏右 → 融合坐标落在出口锚点右侧（否则翻 `BUMPY_LATERAL_OVERLAY_SIGN`）。

#### 5.3.4 `bumpy_vision_process_camera_frame()` 新分支（对准映射）

```c
void bumpy_vision_process_camera_frame(const uint8 *gray)
{
#if BUMPY_USE_NEW_PIPELINE
    /* —— 新管线：输入 94×60 压缩图 —— */
    bumpy_frame_result_t res;
    bumpy_vision_output_t next = {0};
    uint8 both = 0U, any = 0U;
    float ang = 0.0f;

    bumpy_pipeline_frame(&s_bumpy_pipeline, gray, &res);

    any  = (uint8)((res.L.valid || res.R.valid) ? 1U : 0U);
    both = (uint8)((res.L.valid && res.R.valid) ? 1U : 0U);

    /* 条纹方向角：双侧 doubled-angle 平均 / 单侧直接取 */
    if (both) ang = line_angle_avg(res.L.ang, res.R.ang);
    else if (res.L.valid) ang = res.L.ang;
    else if (res.R.valid) ang = res.R.ang;

    next.frame_id = g_bumpy_vision_output_shadow.frame_id + 1U;
    next.bumpy_detected = any;
    next.direction_x = cosf(ang * (3.14159265f / 180.0f));
    next.direction_y = sinf(ang * (3.14159265f / 180.0f));

    /* 偏差角度：条纹法向相对车头(图像+y)夹角，正=需右转 */
    next.yaw_error_deg_x100 = (int16)(atan2f(-sinf(ang * (3.14159265f / 180.0f)),
                                             cosf(ang * (3.14159265f / 180.0f)))
                                      * (180.0f / 3.14159265f) * 100.0f);

    /* 水平方向偏差：仅双侧有效时经 IPM 换算，车身偏右为正 */
    if (both)
    {
        const int row  = (int)((res.L.cy + res.R.cy) * 0.5f);
        const int cxs  = (int)((res.L.cx + res.R.cx) * 0.5f);
        const IPM_Point_t p0 = IPM_GetPhysicalCoord((uint8_t)47, (uint8_t)row);
        const IPM_Point_t p1 = IPM_GetPhysicalCoord((uint8_t)cxs, (uint8_t)row);
        if ((p0.x_mm != IPM_INVALID_VAL) && (p1.x_mm != IPM_INVALID_VAL))
        {
            next.lateral_mm = (int16)(p0.x_mm - p1.x_mm);
        }
    }

    /* 可信位：双侧边线 + IPM 有效才给（横向才有意义） */
    next.meas_valid = (uint8)(both && (next.lateral_mm != 0 || 1) ? 1U : 0U);
    /* 说明：lateral_mm==0（真居中）也有效，故上面恒真；
       真正的门控是 both + IPM 有效（已在上面保证）。*/

    g_bumpy_vision_output_write_busy = 1U;
    g_bumpy_vision_output = next;
    g_bumpy_vision_output_shadow = next;
    g_bumpy_vision_output_write_busy = 0U;
#else
    /* ……旧算法（现有逻辑）保持不变…… */
#endif
}
```

> 注：`meas_valid` 的门控实际是 `both && IPM有效`。上面的 `|| 1` 写法是占位示意，正式代码直接写成：
> ```c
> next.meas_valid = both;   /* 进入 both 分支时 IPM 有效性已保证 */
> ```
> 若 IPM 无效（单帧），则走 `both` 为假的分支，`meas_valid=0`、`lateral_mm` 保持 0。

```icf
define symbol cm7_0_sram_reserve                = 448K - cm0plus_sram_reserve; // (SRAM0/320KB) -> cm7_0, 让64K给CM7_1
```

- ⚠️ **icf 注释必须纯 ASCII**（IAR 链接器遇中文注释会跳过后续行 → `Error[Lc036]/Li005]`）。
- `.itcm_text` 段主工程 icf 已 place（旧 edge_conv_asm 已用），`edge_conv7_asm.s` 直接复用，无需新增。

### 6.4 汇编对齐宏

`edge_conv7_asm.h` 内的 `ALIGN4` 宏在 IAR 用 `_Pragma("data_alignment=4")`、GCC 用 `__attribute__((aligned(4)))`——**主工程为 IAR，无需改**；若 `bumpy_conv.c` 在别处编译需双版本（源文件已带，确认保留）。

## 7. 内存预算与风险（P0 级，必须先确认）

### 7.1 新管线静态占用

| 块 | 大小 |
|---|---|
| `bumpy_pipeline_t`（调用方持有，`bumpy_vision.c` 静态实例） | ~110KB（gx/gy int32 45KB + mag2 uint64 45KB + strong/horiz/labels 17KB + 历史） |
| `bumpy_pipeline.c` 内部静态工作缓冲 | ~50KB（uf/relab/coff/cur/labels/px/py/外点/inl） |
| **合计** | **~160KB** |

### 7.2 CM7_1 现有占用估算

| 项 | 大小 |
|---|---|
| `image_copy` 188×120 | 22.6KB |
| `compressed_image_copy` 94×60 | 5.6KB |
| 桥融合/PVC/三级跳状态 + IPC 双核缓冲 | ~20-40KB（需 map 实测） |
| 栈（cm7_stack_reserve） | 8K |
| wifi 发送缓冲等 | 需 map 实测 |

当前 CM7_1 256K 减去已有占用后，**大概率放不下 160KB 新管线**。**落地第一步必须是：编译前先看现有 `Debug_m7_1/List/*.map` 的 `.bss/.data` 占用，算清楚余量。**

### 7.3 取舍方案（按优先级）

| 方案 | 做法 | 代价 |
|---|---|---|
| A（首选） | 先不动 icf，直接加新管线编译，看链接是否过；过了最好 | 若爆则白跑一轮 |
| B | 若爆且 CM7_0 map 有余量：`cm7_0_sram_reserve` 384K→320K，CM7_1 得 320K | CM7_0 缩 64K，需重验 CM7_0 链接 |
| C | 新管线内存优化：`mag2` 改 uint32 存平方根前值（45KB→22.5KB）或改为临时复用 gx/gy 缓冲 | 改动新管线源码，破坏与 trials 对拍同源性，**不推荐首轮** |
| D | 旧 `image_copy` 188×120 在新内核下不再需要（新用压缩图），若旧 bumpy_vision 完全移除可省 22.6KB | 牺牲旧内核回退的渲染 |

**落地决策**：文档推荐 **A→B** 顺序，先实测 map 再动 icf；严禁直接照抄 trials 的"CM7_0→128K"（主工程 CM7_0 是控制核，不是空壳）。

## 11. 坑与注意事项（综合 trials 交接文档 + 主工程）

| # | 坑 | 规避 |
|---|---|---|
| 1 | **icf 中文注释** → Lc036/Li005 一堆错 | icf 只写 ASCII |
| 2 | reflect 边界语义：scipy `convolve1d(mode='reflect')` 是**半采样对称**（-1→0），numpy.pad 是整采样 | 新管线 C 已按 scipy 实现，**不要改** |
| 3 | M7 无 64 位 FPU，double 的 sqrt/atan2 走软件数千周期 | 新管线全 float；适配层也用 `atan2f/sinf/cosf` |
| 4 | 横向判定免 atan2（整数 tan²）是最大单项优化 | 已内置于新管线，勿改回 atan2 |
| 5 | 汇编 LDR 4 字节对齐 | `ALIGN4` 宏已处理（IAR 分支保留） |
| 6 | 垂直 pass 输出布局（行优先直接写会写进） | 骨架用 vout 列缓冲已处理 |
| 7 | 垂直 pad 索引 `out[y]=Σw[k]·pad[y+6-k]` | 已实现，勿"优化"成 y+3-k |
| 8 | D 核垂直权重反转 | 已实现 |
| 9 | **内存**：CM7_1 只有 256K，新管线 ~160KB | 先看 map 再决定是否动 icf（§7） |
| 10 | `BP_TEMPORAL`：部署必须 1（连续 3 帧才显示）；0 是 batch 图集专用 | CCDefines 显式设 1 |
| 11 | 时间验证状态按"路段"隔离：`bumpy_vision_reset_filter()` 必须 `bumpy_pipeline_init()` | §5.3.3 |
| 12 | `WIFI_CAMERA_SEND_MODE` 若被改成 RAW，bumpy 整块被 `#if` 排除 | 保持默认 COMPRESSED |
| 13 | IAR 无 glob，新源文件漏加 ewp → Pe007 | §6.1 手动加 |
| 14 | 新管线输出 `ang∈[0,180)` 是 headless | 适配层用"条纹法向"公式（§3.3），不需要消歧 |
