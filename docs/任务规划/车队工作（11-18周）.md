## 一、PID 与底层控制

### 1. PID 三环控制

- [ ] 梳理三环结构：`speed -> angle -> gyro`。
- [ ] 实现或验证速度前馈策略。
  -  [ ]当前想法：当当前速度与目标速度差距过大时，放大 `angle` 输出的 `kp`。
  -  [ ]当前想法：`duty = duty + duty_base`，由三环和速度共同作用。
  - 可选策略：直接拉高 duty（bang-bang）。
  - 总限幅：`10000`。

### 2. 转向控制

- [ ] 梳理转向控制结构：`yaw -> gyro`。
- [ ] 明确线性转向不能直接使用前馈。

### 3. PID 与 duty 限幅

- [ ] 整理三环限幅策略。
- [ ] 整理转向限幅策略。
- [ ] 验证三环输出与转向输出叠加后的总限幅。
  - 当前约束：`三环输出 + 转向输出 <= 10000`。
  - 正常建议区间：`8000-9000`。
- [ ] 验证长期顶到 `10000` 时是否会导致电压跳变或控制不稳定。

## 三、导航与 GPS/惯导融合

### 1. 数据来源与频率

| 数据源 | 周期 | 数据字段 | 用途 | 完成 |
| --- | ---: | --- | --- | --- |
| 惯导 | 10 ms | `gd.x`, `gd.y` | 高频位置递推 | [ ] |
| GPS | 100 ms | `gps.x`, `gps.y` | 低频绝对位置校正 | [ ] |
| fusion | 10 ms / 100 ms | `fx`, `fy` | 有条件使用 GPS 覆盖融合位置 | [ ] |

### 2. 融合流程

- [ ] 每 `10 ms`，使用惯导增量更新 `gd.x`, `gd.y`。
- [ ] 每 `10 ms`，同步更新 `fx`, `fy`，增量为 `dx`, `dy`。
- [ ] 每 `100 ms`，获取 `gps.x`, `gps.y`。
- [ ] 对 GPS 数据执行规则判断。
- [ ] 如果 GPS 合理，则更新：`fx = gps.x`, `fy = gps.y`。
- [ ] 如果 GPS 不合理，则抛弃本次 GPS 数据，继续使用惯导递推。

### 3. GPS 合理性判断规则

- [ ] 如果 GPS 增量大幅超过惯导增量，则判定为不合理。
- [ ] 如果 GPS 推算速度超过车辆极限速度，则判定为不合理。
- [ ] 在特定元素内使用不同策略。
  - 雷区：可以考虑不使用 GPS。
  - 单边桥等元素：可以考虑只使用开始和结束位置的 GPS。
- [ ] 根据卫星数决定 GPS 是否可用。
  - 卫星数过少：直接不用。
  - 卫星数一般：提高使用限制。
  - 卫星数充足：按正常规则使用。

### 4. 导航融合验证任务

- [ ] 记录同一段路线上的 `gd.x/gd.y`、`gps.x/gps.y`、`fx/fy`。
- [ ] 离线画出三条轨迹，观察 GPS 覆盖是否造成跳变。
- [ ] 统计 GPS 被接受/拒绝的次数和原因。
- [ ] 验证不同元素内的 GPS 使用策略是否符合预期。
- [ ] 输出一版默认规则参数，作为后续 ESKF 或更复杂融合算法的基线。
