## 2. TCM 编译要点（性能关键）

### 2.1 三段宏（`code/tcm.h`，主工程已有，与 trials 内容一致）

| 宏 | 放置 | 链接段 | 说明 |
|---|---|---|---|
| `ITCM_FUNC` | 函数 | `.itcm_text` → SELF_ITCM(16K@0x0) | 仅 C 函数；**汇编函数在 .s 里直接 `SECTION .itcm_text:CODE:ROOT(3)`** |
| `DTCM_DATA` | 带初值数据 | `.dtcm_data` → SELF_DTCM(16K@0x20000000) | 启动 Flash→DTCM 自动拷贝 |
| `DTCM_BSS` | 零初始化数据 | `.dtcm_bss` → SELF_DTCM | **不自动清零**（ICF `do not initialize`），需显式 memset 或每帧先写后读 |

### 2.2 ICF（主工程 `iar/icf/linker_directives_tviibh.icf`，与 trials 逐行一致，仅行尾符 CRLF/LF 差异）

- 区域：`SELF_ITCM 16K@0x00000000`、`SELF_DTCM 16K@0x20000000`（核内地址，每个核相同，硬件自动路由）。
- 初始化：`initialize by copy { ro section .itcm_text, rw section .dtcm_data }`；`do not initialize { section .dtcm_bss }`。
- 放置：`place in SELF_ITCM { rw section .itcm_text }; place in SELF_DTCM { rw section .dtcm_data, section .dtcm_bss }`（在通用 SRAM/Flash 放置之后）。
- ECC：ICF 导出 `__ecc_init_itcm/dtcm_*` 符号，startup 的 `InitRamEcc()` 负责 ECC 清零。
- ⚠️ 陷阱：ICF 注释必须纯 ASCII（中文注释曾导致 `block HEAP_STACK defined but not referenced`）。

### 2.3 放什么进 TCM

- **放 ITCM**：汇编算子（conv1d/mlp_fc 内核）、热点 ISR/紧密循环。
- **放 DTCM**：卷积行缓冲（`s_raw/s_ringx/s_ringy`，共 1.7KB）、MLP 激活/累加缓冲、高频权重。
- **不要放**：图像帧缓冲（几百 KB）、日志字符串、初始化一次就不用的数据、大查找表。

## 3. 汇编算子经验（bridge_asm_ops.s）

### 3.1 函数清单（C26 后）

| 函数 | 作用 | 备注 |
|---|---|---|
| `b2_conv1d_horiz_gxgy` | 水平 Pass：一行 → Gx_horiz + Gy_horiz | SMLAD 双发射，1.0 c/MAC |
| `b2_conv1d_vert_gxgy_row` | 垂直 Pass：4 行 → 1 行 Gx + Gy | LDRSH+PKHBT+SMLAD |
| `mlp_fc_s8_layer` | 单层 int8 全连接 | SMLAD，CMSIS-NN 风格 |

- 核常量 `D=[-1,-1,1,1]`、`S=[1,3,3,1]` 全寄存器常驻（MOVW+MOVT）。
- 数据要求：输入/激活 `int16`（值域 [-128,127]），权重交错布局（每 int32 两个 int16 半字），**4 字节对齐**（LDR 字加载），DTCM 内。
- **对齐**：权重 32B、激活/累加器 8B；`s_mlp_feat` 用 `__attribute__((aligned(4)))`（IAR 支持该 GCC 语法）。

### 3.2 ⚠️ 与本工程 `edge_conv_asm.s` 的关系（C26，重要）

- 主工程既有 `edge_conv_asm.s`（bumpy_vision 在用）**已导出** `conv1d_horiz_gxgy`/`conv1d_vert_gxgy_row`。
- 两文件虽同源（bridge_asm_ops.s 由 edge_conv_asm.s + mlp_asm_ops.s 合并精简而来），但**卷积核方向相反**：
  - edge_conv_asm.s：S 核 `[3,1,1,3]`（r6={3,1}/r11={1,3}）
  - bridge_asm_ops.s：S 核 `[1,3,3,1]`（r6={1,3}/r11={3,1}）
- 梯度输出不同 → **模块阈值按 bridge 版本标定，两者不可混用**。已通过 C26 给 bridge 版加 `b2_` 前缀解决重名，`edge_conv_asm.s`/`bumpy_vision.c` 零改动。

## 4. 测时与串口验证范式（阶段 1 自测用）

### 4.1 DWT 周期测时（trials 测试台原样，250MHz → us = cyc/250）

```c
CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
DWT->CYCCNT = 0;
DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;
uint32_t t0 = DWT->CYCCNT;
bridge_detect_frame(img, &st, &res);   // 被测区
uint32_t cyc = DWT->CYCCNT - t0;       // us = cyc / 250
```

- 本项目阶段 1 用 `runtime_profiler_t` + `TC_TIME2_CH1`（与 pvc_vision 共用通道，无冲突），输出 `[BridgeV2]` 摘要（`DEBUG_LOG_ENABLE=1` 且每 50 帧一条）。
- 实测参考：v13c avg **5.54ms**、p99 6.07、max 6.44ms，预算按 ≥8ms/帧。

### 4.2 串口输出格式（PC 渲染/对拍用，trials 测试台）

```
bridge <name>: <us> us mode=<m> nl=<n> nr=<n> R<0/1> G<0/1> B<0/1> T<0/1> ra=<a*100> rb=<b*100> ga=.. gb=.. ba=.. bb=.. ta=.. tb=.. tn=.. trms=..
bridge: avg=<us> us, max=<us> us, frames=100    （每 100 帧汇总）
```

- a/b 定点 ×100 供 PC 渲染；解析正则见 `trials/bridge/桥检测C模块移植清单.md` §4.3。

### 4.3 状态复位（对拍一致性坑）

- `bridge_state_t` 有跨帧状态（gate 锁存、间距滑动窗、wp_a 自校准）。**PC host 对拍必须 `--init-each`**（每图 init 一次）与 MCU 测试循环对齐，否则先验状态漂移导致差异（trials 已踩坑）。
- 上桥/开场/复位调用 `bridge_detect_init(&st)` 一次。

## 6. 踩坑汇总（本次整理新增/确认）

1. **符号冲突（C26，新增）**：新模块 `conv1d_*` 与主工程 `edge_conv_asm.s` 重名且核方向相反——移植清单未预见到，必须重命名。教训：**拷贝汇编前先比对主工程既有 PUBLIC 符号**。
2. **`.dtcm_bss` 不自动清零**：DTCM 缓冲要么显式 memset，要么保证"每帧先写后读"（本模块环形缓冲满足，v13c 真机验证过）。
3. **ICF 中文注释**：会干扰 IAR 解析（`HEAP_STACK defined but not referenced`），保持纯 ASCII。
4. **对拍 `--init-each`**：先验状态漂移导致 host/MCU 不一致。
5. **`getenv` 在 MCU 恒 NULL**：`bridge_detect_init` 里的 2 行无害，编译报错时才需删。
6. **7/28 主工程曾集成过模块**：历史 `.map` 显示模块曾在主工程编译链接成功（Errors: none），内存放得下（SRAM 余 ~39KB、DTCM 余 11.4KB、ITCM 富余）——阶段 1 内存核对完成。
