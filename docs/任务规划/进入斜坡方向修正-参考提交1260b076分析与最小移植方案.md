### 5.2 为什么参考做法更好（核心论据）

1. **航向通道（P）——"基本正开上去"的主干（参考工程设计核心）**：参考做法的设计哲学（见参考分支《进入段方向控制LQR改PD结构-详细规划.md》§1.2）就是"航向角度给 PD **一直维持在自适应回归的正确角度**（entry_yaw）"，`P·ψ_err` 是主干、`K_E·e` 是视觉扰动。效果：
   - 上桥瞬间车头**基本正**（|ψ|≤20°）——满足"基本正开上去"；
   - 进入后 30cm 内车头**转正**（验收标准，见 §5.4）。
   当前做法 `yaw_err` 恒为 0，**完全没有航向保持**，上桥瞬间车头方向不受控——这正是参考做法要补的核心能力。

2. **距离自归一化的 e 通道**：像素域固定增益有两个先天缺陷：
   - 近处透视效应把同样的物理偏差放大成很大的像素偏差 → 打角过猛、甩头；
   - 远处像素偏差小 → 修正力度不足、拉不回来。
   `e = D·sin(β−ψ_err)` 用物理距离 D 加权，1.5m 检测窗内远近行为一致，且 β 由 IPM 方位角直接给出（含航向投影修正）。

3. **物理限幅与底层解耦**：当前做法 `err_degree ±18°` 经转向角度环后实际角度环输出 = 18×|TURN_ANG_KP|，物理含义随底盘参数漂移；参考做法 ω∈±2.2 rad/s 直接对应执行器极限，参数在换车/换 PID 参数后仍可移植（见 §7 数学论证）。

4. **经物理仿真精修 + 手册化**：`12/8/0.2` 是 MuJoCo 物理仿真（10 种子）搜索的结果（验收=上桥瞬间 |x|≤11.5cm 且 |ψ|≤20°，上桥后 30cm 内拉直；18 工况通过 9/18、裕度 5.66，与 LQR 等效）；同时头文件内嵌完整"症状→动作"调参手册，现场调参成本远低于当前做法。

5. **锁角基准统一**：参考做法把 `locked_yaw` 从"PVC 校准完成瞬间"改为"进入任务时刻"（`entry_yaw_deg`），与 LQR/PD 的基准一致，避免状态切换瞬间基准跳变/锁到运动中航向。

### 5.3 参考做法的代价与注意点（客观）

- **依赖 IPM 物理坐标精度**：e 通道建立在 `pvc_phy_x/y_mm` 标定准确之上；若 IPM 标定偏差大，e 会系统性偏大/偏小（当前像素域做法对此不敏感）。
- **依赖检测窗长度**：参考参数是在 1.5m 检测窗 + 1m/s 量级验证的；若实际检测起点晚（窗短），K_E 需要相应加大（历史经验：短窗下需保证 K_E·D > P 才能让 e 通道生效）。
- **入口确认与 LQR 门控不同步**：入口确认仍用 `stable + ratio≥40% + 25 tick`；而 `VisionEntryLqr_UpdateVision` 的门控只看 `phy≠32767 && D≤1.5m`，不查 stable/帧新鲜度——未 stable 时用的是 raw 坐标（有噪声），沿用参考行为，现场需用诊断字段确认。

### 5.4 参考工程对"车头问题"的完整讨论（设计意图，2026-08-20 澄清后确认）

用户强调：参考工程对"车头问题"已有充分讨论，目标 = **基本正的开上去，开入后 30cm 内能够转正**。参考分支《进入段方向控制LQR改PD结构-详细规划.md》的核心设计：

- **控制律**：`ω = P·ψ_err + D·ψ_err' + K_E·e`
  - `P·ψ_err`：**航向 PD 主干**，把车头一直维持在"自适应回归的正确角度"（`entry_yaw`）附近 → 保证上桥瞬间**基本正**；
  - `K_E·e`：**视觉扰动**，`e = D·sin(β−ψ_err)` 修正横向偏差 → 保证**轮子对得上桥面**（|x|≤11.5cm）；
  - `D·ψ_err'`：航向微分阻尼，抑制抖动。
- **"进入后 30cm 内转正"的机理**：不是独立状态机阶段，而是**验收标准 + 前段工作到位的自然结果**——
  1. 进入前（PVC_ALIGN）P 把车头保持在 |ψ|≤20°（基本正）；
  2. 进入后 ENTRY_HOLD 锁 `entry_yaw`（已基本正的方向）直行 300ms；
  3. 上桥瞬间 |ψ| 已足够小 → 进入后 30cm 内车头自然拉直。
- **验收标准**（MuJoCo 仿真，见 vision_entry_lqr.h 调参手册）：成功 = 上桥瞬间车中心距桥中线 **≤11.5cm** 且 车头与桥向夹角 **≤20°**（上桥后 30cm 内能拉直）。
- **仿真模型**（参考规划 §3.1）：2ms 控制、视觉 30ms 采样 + 1 帧延迟 + 高斯噪声（0/15mm）、IMU 航向白噪声 0.4°、转向执行器一阶 τ=0.03s + slew 9 + |ω|≤2.2、检测距离 1.5m、进入段结束判据 D<0.4m（模拟 PVC 确认压上）、6 标准工况 × 5 种子。

> 结论：用户的需求与参考工程设计**完全一致**——P 保证"基本正"，e 保证"轮子对得上"，二者协同使"进入后 30cm 内转正"。**不需要、也不应该调小 P。**

## 6. 结论：哪个更好？

**在当前"进入斜坡方向修正"场景下，参考提交的做法（航向 PD 保持 entry_yaw + 视觉扰动，物理域）严格优于当前分支的做法（像素域位置式 PID）**：
1. 当前做法**没有航向保持通道**（yaw_err 恒 0），上桥瞬间车头方向不受控，无法保证"基本正开上去"；参考做法 `P·ψ_err` 把车头维持在 `entry_yaw` 附近 → 上桥基本正、进入后 30cm 内转正（与用户需求完全一致）；
2. 当前做法**不做距离归一化**：像素域固定增益近处（透视放大）打角过猛、远处（偏差小）修正不足；参考做法 `e = D·sin(β−ψ_err)` 物理域距离加权，远近行为一致；
3. 参考做法**物理限幅与底层解耦**（ω±2.2 rad/s）、**经过 MuJoCo 物理仿真验证 + 手册化**（验收 = |x|≤11.5cm 且 |ψ|≤20°，30cm 内拉直），可移植性和可维护性更好。

而参考做法的两个缺点（IPM 标定依赖、窗长敏感）在当前分支数据源（同一 `pvc_vision` + 同一 `pvc_phy_*`）下不构成额外风险，且可用新增的诊断字段（`lqr_e_m/lqr_psi_err_deg/lqr_dist_m`）现场核对。

**结论：值得引入参考做法（物理域 P·ψ_err 航向保持 + e 视觉扰动）**。落地方式二选一：完整移植 `vision_entry_lqr`（方案 A，与参考逐字一致）或仅加轻量物理域 PID（方案 B，§8.7，用户倾向——LQR 不需要、改动最小）。两者控制律与参数起点（12/8/0.2）相同。

## 7. 关键数学论证：为什么 TURN_ANG_KP 差异不影响移植

当前分支小车4（`CAR_SELECT=4`）`TURN_ANG_KP = -12`，参考分支为 `-8`。看似不一致，实际上：

```
vision_entry_lqr 输出：err_degree = ω·57.29578 / TURN_ANG_KP        （GetErrDegree 内）
底层角度环输出：      turn_angle_loop_out = TURN_ANG_KP × err_degree
                                           = TURN_ANG_KP × (ω·57.29578 / TURN_ANG_KP)
                                           = ω·57.29578                （TURN_ANG_KP 完全抵消）
```

**无论 TURN_ANG_KP 是 -8 还是 -12，`vision_entry_lqr` 闭环在"期望角速度 ω"域完全等价**，移植不需要同步改 `pid-new.h`。

`PD_ERR_MAX_DEG = PD_W_MAX_RADPS × 57.29578 / 8.0 ≈ 15.76°` 只是 `err_degree` 输入限幅：
- TURN_ANG_KP=-8：实际 err 最大 ±15.76°，恰好贴住限幅；
- TURN_ANG_KP=-12：实际 err 最大 ±10.5°，限幅不触发。
两者闭环行为一致，**无需修改**（若追求严谨可改为 `/(float)(-TURN_ANG_KP)`，但非必需）。

同理，`PD_CTRL_HZ=500`（2ms 微分分母）与 `VisionSlopeTask_Update_2ms` 调度一致，无需改。

D  = hypot(fx,fy)/1000                        (m)
β  = atan2(fx,fy)                             (入口方位角, 车身系)
ψ_err = normalize(entry_yaw − yaw)            (rad, entry_yaw=进入任务时刻航向)
e  = D·sin(β − ψ_err)                         (物理横向偏差, f87b18b 修复公式)
ψ_err' = 2ms 差分 + 一阶低通(τ=0.05s)
ω  = P·ψ_err + D·ψ_err' + K_E·e               (P=8, D=0.2, K_E=12 起点)
ω  = clamp(ω, ±2.2)
err_degree = ω·57.29578 / TURN_ANG_KP         (角度环输出恒=ω·57.29578, 与底层解耦)
门控：phy==32767 或 D>1.5m → 返回 0（直行回退）

## 9. 风险与注意事项

1. **重捕获微分尖峰（已知边界）**：`1260b076` 版 `UpdateVision` 在无效帧（phy 无效或 D>1.5m）时直接 `return 0`，**不更新** `s_psi_err_prev_rad`。若视觉丢失期间 yaw 漂移较大，重捕获第一拍 `ψ_err' = (ψ_now−ψ_prev)·500` 会产生尖峰。当前 `D=0.2` 很小 + 低通 τ=0.05s 已大幅缓解；若实车仍见"重捕获甩头"，可参考 0818 分支已验证的"盲区保活"修复（把微分状态更新移到有效性判定之前，ψ_err 只依赖 IMU 本可每拍更新）。**本次最小移植不包含该修复，列为后续可选项。**

2. **LQR 门控不含 stable**：`UpdateVision` 只看 `phy≠32767 && D≤1.5m`，未 stable 时用 raw 坐标（可能抖动）。行为与参考分支一致，现场用 `lqr_dist_m/lqr_e_m` 诊断确认。

3. **锁角基准变化**：`ENTRY_HOLD` 锁角从"PVC 校准完成瞬间"改为"进入任务瞬间"。若进入任务触发瞬间车头与入口方向偏差较大，锁角会偏——但参考分支认为统一基准（与 LQR/PD 的 `entry_yaw` 一致）利大于弊，且当前入口确认（stable+ratio≥40%）通常已在准对状态下完成。实车需确认无回归。

4. **速度保持 -600 与参考验证条件的差异**：参考参数在 ~1m/s 量级验证（-500~-800）。-600 在其范围内，可接受；若进入段感觉修正时间不够，再单独调速度（属后续调参，非本次移植范围）。

4b. **"基本正"依赖 P 项（重要）**：P 是保证"上桥基本正、进入后 30cm 内转正"的主干，**移植时不要调小 P**（参考 12/8/0.2 已仿真验证）。若实车出现上桥瞬间车头偏（|ψ|>20°），按调参手册症状 C（P +0.5~1）处理。历史短窗教训（K_E=30/P=7 拐弯小）只说明**短检测窗下 K_E/P 比例需要重新标定**，不是"P 越小越好"。

5. **回退能力**：`ENTRY_CTRL_MODE` 宏可切回 LQR 模式（`ENTRY_CTRL_MODE_LQR`）；若完全不想用，把 ⑥ 处改回 `err_cmd = g_vision_pvc_control_status.err_degree_cmd` 即可瞬间回退。改动完全可逆。

6. **编译接入**：新增 .c 必须同步加进 ewp/ewt，否则 IAR 编译不过（§8.4 是**必须**步骤，非可选）。

## 11. 附录：参考提交调参手册要点（源自 vision_entry_lqr.h）

**三个参数一句话**：
- `K_E` = 视觉纠偏力度（目标点偏左/右，方向盘往偏差方向掰多少）——主旋钮；
- `P` = 航向保持刚度（车头偏离锁定方向时自动回正力度）——次主旋钮；
- `D` = 航向阻尼（抑制车头抖动/来回摆）——安全余量旋钮。

**症状→动作表**：
| 症状 | 动作 |
|---|---|
| A 横向拉不回来，直冲向桥侧 | K_E +1~2 |
| B 冲过桥口/甩过头/S 形摆 | K_E −1~2 |
| C 横向对上了但车头斜着上桥 | P +0.5~1（对应"开入后 30cm 内转正"保障；上桥瞬间 |ψ| 偏大时调 P） |
| D 车头来回摆/抖 | D +0.1~0.2 |
| E 低速正常、一加速就摆 | K_E −2，再 P −1 |
| F 雨天/湿路面拉不回来 | 降速 ≤1.5m/s（抓地力问题，勿加 K_E） |
| G 上桥瞬间横偏刚超 11.5cm | K_E +1，或提前检测 |

**安全边界**：D 严禁 >0.5×P（例 P=8 时 D≤4，推荐 0~0.5）；K_E 10~30；P 4~15；W_MAX(2.2) 与检测距离(1.5m) 是物理极限勿当旋钮；速度 >2.0m/s 修不完大偏差（几何极限，要修上游）。

**参数参考区间**：默认 12/8/0.2（干70cm·湿50cm·随机60cm 可修 @1m/s）；保守起步 10/7/0.2；低速快修 15/9/0.2；D=0 理论最优，0.2 仅为实车抖动安全余量。
