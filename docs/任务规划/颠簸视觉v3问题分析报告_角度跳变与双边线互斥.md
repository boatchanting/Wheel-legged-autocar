## 1. 问题 A：角度检测与 0/180 跳变

### 1.1 现象（用户描述）
- 渲染给的角度数值**在 0 和 180 之间跳**；
- 过十字的横线（法向线）**经常抽搐、闪烁变成水平方向**；
- 感觉角度检测效果特别差，疑似**触发了平滑逻辑导致角度无法正确识别**。

### 1.2 数据取证

**A1（0/180 显示跳）—— 纯显示层，物理角度连续：**
- v3 全库 34 帧出现"显示 0.x° ↔ 179.x°"跳变，**全部是连续角 ±0.15° 以内的微抖**：
  `f59: 显示179.94→0.00 | 连续角 -0.00 | dir=(1.0000,-0.0000) | yaw=0`
- `direction=(1, ±0.000x)` 连续、`yaw=0` 连续 → **控制量不受影响**，只有 `%180` 显示层跳。
- v2（csv2_new）同源问题但幅度更大（±15°），386 跳变帧。

**A2（0↔90 法向闪）—— 根因 = 方差门拒绝帧的占位方向：**
- v3 全库 31 帧法向线在 0°/90° 间闪（`mid_dir=(hdg+90)%180`）。
- **关键证据**：hdg=90° 的帧全部是 `bumpy=0`（hdg_valid=0）且 `dir=(0.0000, 1.0000)`（无有效角度时的**占位方向**）：
  ```
  bumpy-2  f66/f67: bumpy=0 dir=(0,1) yaw=0      ← 占位 (0,1) 反推 hdg=90°
  bumpy-11 f94/f95: bumpy=0 dir=(0,1) yaw=0
  ```
- 而这些帧的条纹连通域（lin4）**全部是水平条纹**（如 bumpy-2 f67: `0.2,1.9,162.7,165.3,12.3,7.7,15.1` 度），说明**检测到的方向本是"水平"（≈0°），但方差门判角度不可信 → hdg_valid=0 → 占位 (0,1) 被渲染成水平法向线**，造成"竖直↔水平"闪烁。

**A3（段内角度频繁归零）—— 方差门拒绝率过高：**
- 全库 **887 帧**（2365 帧的 **37.5%**）是"hdg_valid=0 但有条纹 CC"（方差/个数门拒绝），这些帧 `yaw=0`。
- 以"有条纹 CC（lin_n≥2）"为基数的接受率扫描（用 lin4 重算加权圆 std，与 C 同公式）：

  | σ 阈值 | 接受帧 | 接受率 | 被拒（可救回） |
  |---|---|---|---|
  | **2.0°（当前）** | 1077 | **45.8%** | 1272 |
  | 3.0° | 1224 | 52.1% | 1125 |
  | 4.0° | 1344 | 57.2% | 1005 |
  | **5.0°** | 1437 | **61.2%** | 912 |
  | 8.0° | 1685 | 71.7% | 664 |

- 被拒帧的 σ 分布：σ∈[2,5)° 占 **28.3%**（轻度超、可能误杀）、σ∈[5,8)° 19.5%、σ>8° 52%（方向确实杂乱）。
- 例（bumpy-2 f67）：7 个水平条纹 CC 中 5 个在 0~2°、2 个偏 12~17° → 圆 std>2° → 整帧判无效。**若这些偏 12~17° 的 CC 是真实透视/斜条纹，则方差门误杀了本可用的角度。**

### 1.3 根因

1. **平滑逻辑（方差门）阈值过严**：`BP_HDG_STD_MAX=2°` 对条纹 CC 方向角的天然散布（透视、噪声、杂散 CC）容差太小，拒绝过半"有条纹"帧 → 角度频繁归零，且 `bumpy_detected` 段内闪 0。
2. **渲染未区分"无有效角度"**：hdg_valid=0 时 `direction` 为占位 `(0,1)`，板端/离线渲染都把它画成水平法向线 → 闪烁假象。**不是角度检测"乱跳"，而是把"无角度"画成了"角度=90°"**。
3. **显示层 `%180`**：0° 与 180° 是同一个无向条纹方向，`%180` 把 ±0.1° 微抖显示成 0↔180 跳。

### 1.4 修正方案（待审批）

| 项 | 修正 | 影响/风险 |
|---|---|---|
| **A-1 渲染门控** | 板端 `wifi.c` 与离线渲染：**仅 hdg_valid（bumpy_detected=1）时画法向线/hdg 线**；无有效角度帧完全不画（不画占位方向） | 消除法向线闪烁；无风险（只是不画） |
| **A-2 显示去 %180** | 渲染/上位机显示角度用**连续值**（v3 hdg ∈ (-90,90]，直接显示，不用 `%180`） | 消除 0/180 显示跳；无风险 |
| **A-3 放宽方差门** | `BP_HDG_STD_MAX`：2° → **5°**（建议）或 8°（备选）。预计接受率 45.8%→61.2%（救回 ~360 帧） | 可能放行少量杂散帧；需复跑 + 渲染确认（裁决点 1） |
| **A-4 角度归零策略（可选）** | 被拒帧 `yaw_error` 保持上次有效角度（而非归零）——需同时改 0 核"锁角度"语义 | 改变 IPC 输出语义，影响 0 核 `vision_bumpy_control` 失稳分支；**需重点裁决（裁决点 2）**，默认不实施 |

> 注：A-3 是"角度检测效果差"的实质修正；A-1/A-2 消除渲染层的闪烁与 0/180 假象；A-4 是语义级改动，默认维持现状（被拒帧归零、0 核锁角度）更安全。

## 2. 问题 B：一个边识别出双边线 → 中线锁死

### 2.1 现象（用户描述）
- 渲染中疑似**一个边被识别成双边线**，导致**中线跟着一起锁死**。

### 2.2 数据取证
- 全库 `|el−er|<500mm` 的"双边近距"帧共 **3 帧，全部在 bumpy-11**：
  ```
  f100: el=-460 er= 15 |diff|=475 lat=478 valid=1
  f103: el=-445 er= 21 |diff|=466 lat=478 valid=1
  f104: el=-461 er= 27 |diff|=488 lat=474 valid=1
  ```
- 序列上下文（f96~f115）：
  ```
  f98: el=-604 er= 28 lat=460 valid=1     ← 真左边缘 -600，右端点 +28（中间断裂点）
  f99: el=-516 er= 24 lat=469 valid=1
  f100:el=-460 er= 15 lat=478 valid=1     ← 锁死起点
  ...
  f115:el=-682 er= 0  lat=434 valid=1     ← 持续锁在 434~478
  ```

### 2.3 机制与根因
- **场景**：条纹只覆盖左半图，左端点构成真左边线（el≈-460~-700mm），右端点其实是**条纹在中部的断裂/结束点**（er≈+15~70mm，物理上仍在左侧），被误当成"右边线"。
- **当前逻辑**（`bumpy_vision.c`）：
  1. `ok_l && ok_r` → 间距自检 `|(xr-xl)-1000|≤150`：`|15-(-460)-1000|=530>150` → 失败；
  2. 走**抢救分支**：`cl=-(-460+500)=-40`，`cr=-(15-500)=485`；与当前估计 `est≈478` 比较 → `|cr-est|=7 < |cl-est|=528` → **采信 cr=485**；
  3. 采信窗把 485 当作观测 → 中线 **锁死在 ~478mm**（车被误判偏右 478mm，持续多帧）。
- **根因**：左右边线**没有"物理间距下限"校验**——两条"边线"物理 x 相距过近（<1m 且非 500mm 级）时，它们其实是同一条边（或一边一幻影），不应做双侧逆推，更不应进抢救。

### 2.4 修正方案（待审批）

**在 `bumpy_vision.c` 双侧合成处增加 0.5m 互斥唯一逻辑：**

```c
#define BUMPY_EDGE_MIN_GAP_MM  (500)  /* 左右边线物理 x 最小间距: <0.5m 视为同边误检 */

if (ok_l && ok_r) {
    if (fabsf(xr - xl) < (float)BUMPY_EDGE_MIN_GAP_MM) {
        /* 同边误检: 只保留更外侧(离车中心|0|更远)的一条, 另一条丢弃, 按单边逆推 */
        if (fabsf(xl) >= fabsf(xr)) ok_r = 0;   /* 保留左 */
        else                       ok_l = 0;    /* 保留右 */
    } else if (间距自检通过) { ...双侧中点... }
    ...
}
/* 随后统一走单边/抢救逻辑(现状) */
```

- **预期效果**：bumpy-11 f100/103/104 中，保留更外侧 `el≈-460`（丢弃 er=+15 的断裂点），单边逆推 `lat=-(xl+500)=-(-460+500)=-40mm`（车接近中线），**不再锁死 478mm**。
- **保留"更外侧"的依据**：真边线物理位置在 ±500mm（条纹半宽）附近；断裂/幻影点更靠近车中心（|x| 小）。
- **参数**：`500mm` = 0.5m 互斥（远小于正常 1m 间距、大于半宽），可调。

## 4. 裁决点（需用户拍板）

1. **`BP_HDG_STD_MAX` 新值**：5°（建议，接受率 61.2%）/ 8°（接受率 71.7%，风险更大）/ 保持 2°（现状，仅修渲染）。
2. **被拒帧角度输出策略**：维持归零（现状，0 核锁角度）vs 保持上次有效角度（需改 0 核语义，风险高，默认不做）。
3. **互斥保留哪侧**：更外侧（建议，真边线在 ±500mm）vs 其他准则。
4. **互斥距离**：0.5m=500mm（建议）是否定案。
