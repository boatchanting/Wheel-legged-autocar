# 视觉识别及控制优化建议（基于当前 `user`、`code/vision`、`code1/vision`）

## 1. 现状速读（你现在这套链路已经做得不错的点）

当前系统已经形成了比较完整的“双核分工”闭环：

- **CM7_1（1核）做感知**：在 `user/main_cm7_1.c` 中，按帧获取图像、压缩、分别运行 PVC/桥线/凹凸路算法，并通过 IPC 输出结构化结果。 
- **CM7_0（0核）做决策控制**：在 `code/vision/*_control.c` 中读取 IPC 最新包，按状态机输出 `err_degree` 与（部分任务）`target_speed_set`。
- **IPC 机制完整**：`code/vision/vision_ipc_core0.c` 与 `code1/vision/vision_ipc_core1.c` 已有 `seq + crc + valid_mask + enable_mask` 机制，且支持任务使能与复位请求。

这意味着你现在不是“从 0 到 1”的问题，而是“从可用到稳定可赛”的优化问题：

1. 检测精度与鲁棒性（光照、角度、遮挡、噪声）
2. 感知到控制的时延一致性
3. 多视觉任务并发时的资源调度与优先级
4. 参数管理与可复现实验体系

---

## 2. 关键问题定位（按优先级）

## P0（最高优先级，先做）

### 2.1 感知输出未做“时间戳闭环”，控制层只能靠 `stale_ticks`

当前 0 核侧用 `seq` 和 `stale_ticks` 判断过期，能防死机，但不能准确衡量**真实感知延迟**（摄像头曝光、算法耗时、IPC传输、控制执行）导致的相位滞后。

**风险**：高速时易出现“看见了但转向总慢半拍”，尤其在桥线和凹凸路中更明显。

### 2.2 多任务共帧运行，峰值算力可能导致抖动

在 `main_cm7_1.c` 里 PVC/Line/Bumpy 按开关可能同帧全跑。如果某一帧光照复杂、连通域多，某算法耗时突增，会拖慢整体帧处理节奏，导致 IPC 输出周期抖动。

**风险**：控制侧相当于收到“非均匀采样”的误差信号，表现为方向抖、速度不稳。

### 2.3 控制状态机里存在“硬切换”点，缺少过渡器

例如目标丢失、阶段切换、使能开关变化时，有不少直接置零/切模式行为。安全上正确，但可驾驶性会受影响（突然减速或方向突变）。

---

## P1（中优先级）

### 2.4 PVC 距离和横向换算仍偏经验系数

`pvc_estimate_forward_mm_from_row()`、`pvc_estimate_lateral_mm_from_x()` 仍是简化关系。虽然有 IPM 坐标补充，但控制主通道仍易受场景变化影响。

### 2.5 桥线与凹凸路算法都偏“规则法”，缺少统一置信度门控策略

现在三个算法都有 confidence/stable，但 0 核控制层未完全统一“低置信时怎样降级”，存在策略分散问题。

### 2.6 参数分散在头文件宏，在线调参与版本管理成本高

比赛现场通常要高频调参，当前参数分布在多个模块，缺少“参数快照 + 场景配置集”机制。

---

## P2（可持续优化）

### 2.7 缺少标准化回放闭环（离线视频/帧包 -> 控制输出）

你有不少 `tools`，但还可以进一步把“视觉输出与控制输出”做同一套自动评分，减少主观调参。

### 2.8 任务编排策略可以更清晰（谁主谁辅）

目前 `active_target + enable_mask` 已具备基础能力，建议形成明确的“调度表”和抢占规则。

---

## 3. 详细改进方案（可直接排期）

## 阶段A：先把“时延与稳定性”打牢（建议 1~2 周）

### A1. IPC增加时间信息：实现端到端延迟可观测

**目标**：让 0 核知道“当前控制使用的是几毫秒前的视觉结果”。

**改法**：
- 在 `vision_ipc_packet_t` 增加：
  - `capture_ts_us`（采图完成时间）
  - `algo_done_ts_us`（该帧算法完成时间）
  - `publish_ts_us`（写入共享内存时间）
- 0 核接收时记录 `consume_ts_us`，计算：
  - 感知耗时 = `algo_done - capture`
  - IPC链路耗时 = `consume - publish`
  - 总视觉滞后 = `consume - capture`

**控制收益**：
- 可做“按滞后自适应增益”（滞后越大，转向增益适度降低）。
- 可设置硬阈值保护（例如总滞后 > 120ms 时降级直行慢速）。

### A2. 1核建立“帧预算调度器”（避免同帧全跑）

**目标**：稳定输出节拍 > 追求每帧都跑满。

**改法**：
- 在 `main_cm7_1.c` 增加简单调度策略：
  - 若 `active_target=PVC`：PVC每帧跑，Line/Bumpy降频（例如1/3帧）。
  - 若 `active_target=BRIDGE`：Line每帧跑，PVC/Bumpy降频。
  - 若 `active_target=BUMPY`：Bumpy每帧跑，其它降频。
- 若某帧算法耗时超预算（如 >8ms），下一帧自动只跑主任务。

**控制收益**：
- IPC输出周期更均匀，0核状态机更稳定。
- 降低偶发卡帧造成的“失锁-重锁”抖动。

### A3. 0核增加统一“输出过渡器”

**目标**：避免状态切换硬跳变。

**改法**：
- 对 `err_degree` 引入一阶限速：`err_cmd = err_prev + clamp(err_raw-err_prev, ±delta_per_tick)`。
- 对速度命令统一加入加减速斜坡（即使状态机切换，也先走斜坡）。
- 目标丢失时不立即清零，使用短时保持+指数衰减（如 100~200ms）。

## 阶段B：识别精度和抗干扰优化（建议 1~2 周）

### B1. PVC 几何标定落地：替换经验公式为查表/拟合

**目标**：让 `forward_mm`、`lateral_mm` 在不同场地仍可用。

**改法**：
- 采集标定数据：固定距离/横向偏移网格点，记录 `(entry_bottom_y, centroid_x)` 与真值。
- 生成 `row->forward_mm` 查表（或分段线性），`x->lateral_mm` 查表。
- 与 IPM 结果做一致性校验，差异过大时降低置信度。

### B2. 桥线检测改为“多证据融合评分”

**建议证据项**：
- 线拟合质量（rmse）
- 连续行有效点比例
- ROI白点比例区间合理性
- 桥黑块几何稳定性（面积/纵向位置变化率）

综合成 `confidence_fused`，控制层只对高于阈值的数据启用高增益。

### B3. 凹凸路加入“相位一致性”约束

当前已输出 `phase/mode`，建议增加：
- 最近 N 帧相位递进合法性检查
- 非法跳变时置信度扣减
- 在控制侧触发“仅轻微修正，不做大角度动作”

---

## 阶段C：控制策略统一化（建议 1 周）

### C1. 建立统一视觉控制接口层（Vision Control Mixer）

目前 PVC/Bridge/Bumpy 各自算各自命令，建议加一个 mixer：

- 输入：三个控制器的 `err_cmd/speed_hint/confidence/state`
- 输出：最终 `err_degree/target_speed_set`
- 规则：
  1. 特殊动作状态机（如 three_stage）最高优先级
  2. active_target 控制器次优先
  3. 其余控制器仅提供限幅建议，不直接接管

### C2. 统一失效降级策略（Fail-safe Matrix）

按 `valid_mask + confidence + stale + motor/yaw状态` 做矩阵：

- 轻度异常：减速 + 低增益
- 中度异常：保持上次方向并缓慢回中
- 重度异常：停车并释放特殊任务占用

把策略写成统一函数，供 PVC/Bridge/Bumpy 复用。

---

## 阶段D：工程化与调参效率（持续）

### D1. 参数中心化

把关键参数汇总为结构体（可分场景预设）：
- `vision_detect_params_*`
- `vision_ctrl_params_*`
- `vision_scheduler_params`

支持：
- 编译期默认值
- 运行时菜单调参
- Flash保存/恢复
- 参数版本号打印

### D2. 建立“回放-评分-对比”工具链

离线流程建议：
1. 输入：若干典型赛道视频/帧序列
2. 输出：每帧检测结果 + 控制命令 + 时延统计
3. 自动评分：
   - 稳定性（抖动、丢失率）
   - 可控性（方向变化率、超调）
   - 实时性（P50/P90/P99耗时）

调参前后自动生成对比报告。

## 4. 建议的“最小可落地改动包”（先做这 8 项）

1. IPC新增 3 个时间戳字段（A1）
2. 0核打印/上报总视觉滞后统计（A1）
3. 1核按 active_target 做降频调度（A2）
4. 1核超预算帧触发“仅主任务”模式（A2）
5. 0核新增 `err_degree` 限速器（A3）
6. 0核新增速度斜坡器（A3）
7. PVC 距离查表替代线性公式（B1）
8. 统一 fail-safe 函数并接入三模块（C2）

这 8 项完成后，通常就能显著改善“偶发抖动、慢半拍、某些光照下误触发”的问题。

## 5. 里程碑验收标准（建议）

### M1：实时性
- 主任务模式下 IPC有效输出频率稳定（抖动显著下降）
- 视觉总滞后 P90 明确可测且低于你的目标阈值

### M2：稳定性
- 三类任务（PVC/桥/凹凸）在强弱光切换场景下，`stable_detected` 断崖式抖动减少
- 控制输出尖峰（err/speed）明显减少

### M3：可控性
- 赛道重复跑多次，入桥对齐成功率、凹凸路通过率、PVC停靠成功率有可量化提升

## 7. 额外建议（实战很有用）

1. **一条规则**：先稳定帧率与时延，再追求识别细节；否则调参会“漂”。
2. **一套日志**：每 50ms 打一次简化状态（state/confidence/stale/err/speed/latency），比单看图像更容易定位控制问题。
3. **两套参数**：室内灯光版、室外阳光版；现场快速切换。
4. **三段测速**：直道、桥前、凹凸路前分别设上限速度，避免在不确定区间过快。

---

## 8. 结论

你当前架构已经具备“可维护的双核视觉控制系统”基础。下一步不建议大改算法范式，而是按 **“时延可观测 -> 调度稳帧 -> 控制过渡 -> 标定落地 -> 统一降级”** 这条路径推进。

这样做的收益是：
- 风险小（兼容现有模块）
- 回报快（1~3周可看到明显稳定性提升）
- 可持续（后续再叠加更复杂算法也不会把系统拖垮）
