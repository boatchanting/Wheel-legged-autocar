# 纯惯性导航完成三科目的实现思路（基于当前代码）

> 目标：在**不依赖视觉识别**的前提下，仅用 IMU + 轮速 + 已有惯导/打点/回放框架完成比赛流程。
> 适用前提：赛前可在同一场地进行一次或多次打点标定，场地元素位置在比赛期间不大幅变化。

---

## 1. 基本判断：为什么可以做纯惯导

当前代码已经具备纯惯导方案的核心积木：

1. **轨迹点采集**：`NavRam_RecordPoint()` 可记录惯导坐标点与点类型。
2. **持久化**：`NavFlash_SaveRamToFlash()` / `NavFlash_ReadFlashToRam()` 可保存和加载赛道任务点。
3. **回放控制**：`NavReplay_Process()` 已能按点跟踪并在特殊点触发动作。
4. **科目动作执行器**：
   - 科目二转圈：`Minefield_Spin_Controller()`。
   - 科目三桥元素：`Bridge_Update()`（当前仍需从测试调用切回正式调用）。

结论：**不做识别也能跑通**，关键在于“赛前高质量打点 + 赛中状态机容错 + 漂移约束”。

---

## 2. 总体方案：两阶段运行

## 阶段A：赛前建图（Teach）

使用遥控器低速跑一遍赛道，完成：
- 路径点（`NAV_POINT_PATH`）
- 特殊任务点（`NAV_POINT_CIRCLE / BRIDGE / BUMP / GRASS / STAGE / JUMP`）
- 关键速度切换点（建议额外定义慢速点）

并写入 Flash，形成“比赛任务脚本”。

## 阶段B：比赛回放（Replay）

加载 Flash 点集后，按顺序执行：
1. 路径跟踪
2. 到达特殊点触发元素控制器
3. 元素完成后回到路径
4. 全部点完成即结束

---

## 3. 三个科目的纯惯导落地方式

## 3.1 科目一（行进绕桩，已完成）

### 思路
- 赛前把“去程直线 -> 掉头点 -> 回程穿桩间隙中心点序列”全部打点。
- 回放时按点序列跟踪，不在线识别锥桶。

### 关键优化
1. **间隙点密度**：每个间隙前后各加过渡点，减少急转。
2. **掉头点单独标记**：到点后先停稳再执行掉头动作。
3. **速度分层**：直线高速、穿桩中速、掉头低速。

---

## 3.2 科目二（定点排雷，已完成）

### 思路
- 雷区中心作为特殊点（`NAV_POINT_CIRCLE`）打入脚本。
- 回放到点后触发 `Minefield_Spin_Controller()` 完成两圈。

### 关键优化
1. 到雷区点前设置减速点，保证在框内触发。
2. 转圈完成后重置航向目标，避免退出抖动（已有逻辑）。
3. 多雷区直接用多特殊点串联，不依赖识别排序。

---

## 3.3 科目三（当前重点）

> 现状：元素控制能力有基础，但识别未完成。纯惯导策略是：**元素位置前置打点 + 点类型触发控制器**。

### 思路
把每个元素拆成“入口点 + 执行区点 + 退出点”：
- 单边桥：`BRIDGE_IN -> BRIDGE_ON -> BRIDGE_OUT`
- 颠簸路段：`BUMP_IN -> BUMP_OUT`
- 草地：`GRASS_IN -> GRASS_OUT`
- 三级台阶坡道：
  - 正向一次：`STAGE_UP_IN -> STAGE_UP_OUT`
  - 反向一次：`STAGE_DOWN_IN -> STAGE_DOWN_OUT`

### 关键点
1. **台阶双向各一次**：用两个方向的特殊点组合保证规则达成。
2. **元素通过顺序可配置**：通过点序列重排实现。
3. **不依赖识别，依赖里程**：进入元素后按“距离+状态机”完成动作。

---

## 4. 纯惯导方案的风险与对应补偿

## 风险1：惯导累计漂移
### 对策
- 关键锚点重定位：在长赛段中插入“低速校正点”。
- 双圈回放：第一圈记录偏差，第二圈修正关键点。
- 限时容错：超时退出当前元素，避免卡死。

## 风险2：地面摩擦变化导致到点误差
### 对策
- 每个特殊点前增加减速缓冲区（100~300mm 可调）。
- 特殊动作触发改为“距离窗口触发”而非单阈值触发。

## 风险3：台阶/桥通过时姿态扰动大
### 对策
- 进入元素前降低目标速度。
- 执行元素时暂时接管导航速度，元素完成再交还。

## 5. 按文件的最小改造清单（纯惯导版）

## 5.1 `code/navigation/nav_ram.h` / `nav_ram.c`

### 目标
扩展点类型，支持科目三所有元素。

### 建议改造
1. 在 `NavPointType_e` 中补充（如缺失）：`GRASS / STAGE / BUMP / JUMP`。
2. 保留 `NavRam_RecordPoint()`，新增“点类型合法性检查”。
3. 增加“关键点最小间距检查”接口，防止打点过密。

---

## 5.2 `code/navigation/ram2flash.h` / `ram2flash.c`

### 目标
保证新增点类型兼容读写。

### 建议改造
1. 不改存储格式，仅确保 `point_type` 扩展后正常保存。
2. 读取时对未知点类型做降级（当作 PATH 或直接跳过）。

---

## 5.3 `code/navigation/nav_replay.h` / `nav_replay.c`

### 目标
把“特殊点触发”升级为“元素任务状态机切换”。

### 建议改造
1. `NavReplay_Process()` 中引入 `special_mode` 状态。
2. 新增 `NavReplay_HandleSpecialPoint(uint8 point_type)`：
   - CIRCLE -> Minefield
   - BRIDGE/BUMP/GRASS/STAGE -> 对应 plan 控制器
3. 新增 `NavReplay_CanExitSpecialMode()`：元素完成后恢复路径跟踪。

---

## 5.4 `code/plan/bridge.h` / `bridge.c`

### 目标
从“测试态”切到“比赛态纯惯导触发”。

### 建议改造
1. 保留 `Bridge_Trigger(distance)` + `Bridge_Update()`。
2. 新增 `Bridge_IsFinished()`，供 `NavReplay` 判断何时退出特殊模式。
3. 去除对视觉触发的强依赖，保留距离触发与里程判定。

---

### 建议改造

## 6. 训练与标定流程（纯惯导成败关键）

1. **低速打点**：先完成完整赛道点集。
2. **单元素调试**：每个元素单独跑通，记录最优触发距离。
3. **半程联调**：先串联两个元素，观察退出逻辑。
4. **全程联调**：连续跑 5~10 次，统计失败点。
5. **参数固化**：把稳定参数写入 `config`，锁版本比赛。

---

## 7. 结论（给决策）

在当前代码基础上，**纯惯性导航是可落地方案**：
- 科目一、科目二可直接沿用现有“打点+回放+特殊动作”框架。
- 科目三无需等待识别闭环，也可通过“元素前置打点 + 元素控制器状态机”完成比赛。

如果后续再加视觉，建议作为“增益层”（纠偏/防漂），而不是“必需层”（无视觉就不能跑）。
