## 1. 目标与依据

**目标**：把参考工程已定稿的 v11 单边桥检测算法接入本工程双核固件，替换现有旧管线；核间通信与控制侧沿用 0809 分支验证过的接入方案；在此之上新增一层**输出中值滤波**（用户额外要求），全部输出经滤波后才交给控制。

**依据（三个来源，各取所需）**：

| 来源 | 取什么 |
|---|---|
| 参考工程 `D:\WORKS\2026LunTui\trials\bridge` | v11 算法本体：`project/code/bridge_detect_v8.c`、`bridge_detect.h`（详见其 `v11交接文档_20260813.md`） |
| 本仓库 0809 分支（`0809【单边桥】单边桥视觉深度更新`） | 接入方案：IPC `b2_*` 协议、仲裁层 `bridge_v2_arbiter`、控制侧状态机改动、`b2_` 前缀汇编算子 |
| 本工程 HEAD | 被接入方；其自有改动（速度宏 -300、sys_options、main_cm7_0 示波器通道）在合并时保留 |

**关键取舍**：0809 分支里的 `code1/vision/bridge_detect.c` 是旧 v13c 算法（MLP 结束线），**不采用**；用 v11 顶替同一文件位置，接口与 0809 头文件兼容（已 diff 核实，仅 `_pad[1]`→`valid` 字段一处差异，0809 侧代码不受影响）。

## 2. 接入后数据流

```
cm7_1 视觉核（帧循环 ~100fps）:
  mt9v03x 188x120 → 2x2压缩 94x60 灰度
    → bridge_detect_frame()           v11 检测        【新文件】
    → bridge_v2_arbiter_process()     mode→控制线仲裁  【0809 取来】
    → bridge_output_filter_update()   中值滤波+多帧门控 【新写, 额外要求1】
  2ms 中断: vision_ipc_core1_fill_bridge_v2() 读滤波结果 → 写共享内存 b2_* 字段
══════════════════ 共享内存 0x28001400 ══════════════════
cm7_0 控制核（2ms tick）:
  VisionIpc_Core0_Update_2ms() → g_vision_ipc_latest
    → VisionBridgeTask_Update_2ms()   0809 版状态机（与 HEAD 手工合并）
    → err_degree / target_speed_set → 转向环 / 速度环
```

分工原则不变：1 核只检测+仲裁+滤波+发布；0 核持有全部物理/时序逻辑（IPM、里程门、状态机、退出判定、换源 ramp）。

### S4 · 中值滤波层（变更 5，额外要求 1 的落地）

新模块 `code1/vision/bridge_output_filter.c/.h`，串在仲裁层与 IPC 填充之间：

- **控制线 a/b**：W=5 帧滑动窗中值（只纳入有效帧；窗内有效帧 <3 时输出当前帧原值）；**source 切换时清窗**（红蓝中点线与绿线不跨源求中值）。
- **结束线 a/b**：同样 W=5 中值（只纳入 has_top=1 的帧）。
- **结束线 has_top 门控**：**连续 3 帧检出才置 1**；确认后允许连续丢失 2 帧再清 0；未确认期间一律输出 0。
- `valid/source/mode/gate/spacing/mid_ratio`：直通。
- 实现：静态环形缓冲 + 5 元素插入排序取中位（每帧 <5µs）；write-busy 保护，IPC 填充撞上更新时沿用上帧结果。
- 接口：`bridge_output_filter_reset()`（reset 请求时调）、`bridge_output_filter_update(const bridge_v2_arb_t*)`（每帧仲裁后调）、`bridge_output_filter_get()`（IPC/示波器读）、`bridge_output_filter_is_busy()`。
- 参数宏集中在头文件：`BRIDGE_FILTER_WINDOW=5`、`BRIDGE_FILTER_MIN_VALID=3`、`BRIDGE_TOP_CONFIRM_FRAMES=3`、`BRIDGE_TOP_LOST_TOLERANCE=2`（默认值为起点，板端定标）。
- PC 侧单测：构造野值/抖动序列验证 ① 单帧野值被中值抑制；② has_top 前 2 帧输出 0、第 3 帧起输出 1；③ source 切换清窗。

### S5 · IPC 协议（变更 6，双核共享头）

`code/vision/vision_ipc.h` 按 0809 版改：

- 删：`VISION_BRIDGE_STATE_*` 4 宏、旧 `bridge_*` 20 字段（5 条线段端点 + detected/state 等，共 34 字节）。
- 增：`VISION_VALID_BRIDGE_V2 = (1U<<7)`；`b2_*` 13 字段——

```c
uint8  b2_valid, b2_source, b2_mode, b2_gate, b2_has_top;
uint8  b2_line_u_lo, b2_line_u_hi;
int16  b2_line_a_x1000, b2_line_b_x100;   /* 控制线 x=a*y+b */
int16  b2_top_a_x1000,  b2_top_b_x100;    /* 结束线 y=a*x+b */
uint16 b2_spacing_x100, b2_mid_ratio_x1000; /* 诊断 */
```

- 包长由 `offsetof(crc)` 自适应，无需手改 size。**注意：双核共享此头，改后两核固件必须同批重新编译烧录**，否则互判坏包。

### S6 · core1 填充与主循环接线（变更 7、8、9）

- `vision_ipc_core1.c`：删旧 `fill_bridge`，新增 `fill_bridge_v2()`——**读 `bridge_output_filter_get()`**，填 13 个 b2_* 字段，置 `VISION_VALID_BRIDGE|VISION_VALID_BRIDGE_V2`，滤波器 busy 时跳过；`.h` 去掉 `bridge_vision.h` include。

## 6. 风险与注意事项

1. 0809 提交 `28d032a` 是纯调试改动（强制检测 `if(1)`、曝光 150、servo_height 4.5、WIFI_CORE_SELECT/SUBS_CATEGORY/SBUS_ACTIVE_POINT），**一律不带入**。
2. 汇编只用 `b2_` 前缀版；主工程 `edge_conv_asm.s` 的同名无前缀符号卷积核方向相反，混用即错。
3. `vision_ipc.h` 双核共享 → 两核同批编译烧录。
4. ewp 与 ewt 必须同步改（IAR 无 glob）；ICF 不动、保持纯 ASCII。
5. 编辑中文文件用编辑工具，禁用 PowerShell 重写（乱码前科）。
6. v11 移植坑（交接文档）：`v11_top_gy` 拟合点行号已是绝对值勿加偏移；`rnd_he` 保持 banker's rounding。
7. 资源预算安全：v11 约 57KB SRAM + 1.7KB DTCM（余量 ~78KB）；耗时 max 4.74ms < 8ms 预算；滤波器 <1KB / <5µs。
8. 0809 方案本身未实车验证过，板端验证（S9）是新管线首飞，按调试指南五阶段（1核视觉→IPC对照→0核状态机→全链路→标定）推进。

## 7. 验收标准

1. 双核 IAR 编译 0 error。
2. PC 对拍：本工程 `bridge_detect.c` 与参考工程 v11 C 端逐帧一致。
3. 滤波器单测通过（野值抑制、has_top 多帧门控、source 切换清窗）。
4. 板端示波器确认 b2_* 为滤波后数据，结束线无单帧闪现。
5. 全链路实车：惯导 900mm 上桥 → 视觉/锁角控制 → 2300mm+结束线确认脱出 / 10s 超时兜底，两条路径均正确。
