### 2.6 平衡问题修复（2026-08-14 第三轮，用户实车反馈"平衡严重受损"后定位）

**根因**（详细分析过程略，结论）：0809 版状态机使"高腿姿态"从旧逻辑的"几乎不触发"变为"每次任务必然全程保持"——
① ALIGN→RUN 的惯导门/超时路径**无条件** `apply_high_posture()`（旧逻辑只有视觉确认才抬，兜底路径不抬）；
② RUN 的高腿保持（`bridge_hold_ticks` 刷新）只看 `b2_gate`，而 gate 是**锁存量**（一旦"双线+底部变白"即永久置 1 直到 reset）→ 一旦锁存全程刷新 → RUN 全程高腿（height_bridge=6.0，正常 3.0 的两倍），叠加任务期间 rolling 接管被抑制、小车 4 高腿 PID 未标定 → 平衡受损。

**修复内容（只改 `vision_bridge_control.c/.h`，用户定调"抬腿跟旧逻辑、恢复距离强制脱出"）**：

| 位置 | 改动 |

## 3. 中值滤波层与调参接口（额外要求 1 落地）

模块 `code1/vision/bridge_output_filter.c/.h`，串在仲裁层与 IPC 填充之间，是 **b2_* 的唯一数据源**（IPC 填充、WiFi 渲染、示波器、屏幕显示全部读它）。

### 3.1 滤波行为

- **定点域滤波**：直接对 int16 定点量（a×1000、b×100）做中值，与控制侧消费值完全一致。
- **控制线 line_a/line_b**：W 帧滑动窗中值，仅 valid 帧参与统计；窗内有效帧 < MIN_VALID 时直通当前帧原值；**source 切换（含失能 source=2）即清窗**，不跨源求中值。
- **结束线 top_a/top_b**：同样 W 帧中值，仅 has_top=1 的帧入窗。
- **结束线 has_top 多帧门控**：**连续 CONFIRM_FRAMES 帧检出才输出 1**；确认后允许连续丢失 LOST_TOLERANCE 帧再清 0；确认失败期间一律输出 0。
- **直通**：valid/source/mode/gate/u_lo/u_hi/spacing/mid_ratio。
- 偶数有效帧取上中位（下标 n/2）；write-busy 保护与仲裁器同模式；reset 由 `TakeBridgeResetRequest` 触发。

### 3.2 调参接口（全部集中在 `bridge_output_filter.h` 四个宏）

| 宏 | 默认 | 调大效果 | 调小效果 |
|---|---|---|---|
| `BRIDGE_FILTER_WINDOW` | 5 | 中值窗更长：更平滑、抗野值更强，响应滞后更大（≈W/2 帧，100fps 下每帧 10ms） | 更跟手，抗野值变弱。必须取**奇数** |
| `BRIDGE_FILTER_MIN_VALID` | 3 | 更保守：窗内要有更多有效帧才输出中值，否则直通原值 | 更早开始输出中值。应 ≤ WINDOW |
| `BRIDGE_TOP_CONFIRM_FRAMES` | 3 | 结束线更难确认：抗闪现更强，但真结束线首次确认更晚（每+1 帧 = +10ms 延迟） | 确认更快，误确认风险升高 |
| `BRIDGE_TOP_LOST_TOLERANCE` | 2 | 确认后更"粘"：短暂丢帧不清除，但结束线消失后退出判定更晚 | 消失响应更快，易被抖动打断 |

**调参建议**：先不动 WINDOW/MIN_VALID，只调门控两个参数——实车若结束线误触发 → 加 `CONFIRM_FRAMES`；若脱出确认太晚 → 减 `CONFIRM_FRAMES` 或加 `LOST_TOLERANCE`（配合 0 核 `VISION_BRIDGE_TASK_EXIT_Y_TH_PX=15`/`EXIT_HOLD_TICKS=3` 一起调，两者是串联关系：滤波层管"是不是真有结束线"，0 核管"结束线够不够近"）。

**调试观测**：`bridge_output_filter_get_debug(&streak, &confirmed)` 可读出当前连续检出帧数与确认状态；示波器 CH4=滤波后 has_top、CH5=滤波后结束线 y@47。

### 4.2 滤波层单元测试（9 组场景，ALL PASS）

### 4.3 真帧端到端统计（检测→仲裁→滤波全链路，6081 帧实跑）

```
[top]  原始: has_top 206 帧, 0→1 跳变 26 次, run 长度分布 {1帧:9, 2帧:6, 3-5帧:3, 6帧+:8}
[top]  滤波: has_top 187 帧, 0→1 跳变 11 次, run 长度分布 {1帧:0, 2帧:0, 3-5帧:3, 6帧+:8}

[line] 控制线 b 相邻帧 |Δb| 均值: 原始 2.202 px → 滤波 1.678 px (-24%)
```

结论：**所有 1~2 帧的短闪现结束线在输出侧零出现**（15 个短 run 中 14 个被完全抑制，剩余 1 个与已确认 run 的容忍期相邻，属设计内行为）；真实持续结束线（3 帧以上）全部保留；输出侧跳变次数 26→11（-58%）；控制线抖动降低 24%。
