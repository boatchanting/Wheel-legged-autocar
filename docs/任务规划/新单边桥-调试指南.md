## 2. 阶段 A：仅 1核 —— 视觉检测质量（画面 + 示波器曲线）

**目标**：不动 0核、不触发任务，只验证 `bridge_detect` 检测质量与耗时。

**操作（网页上位机模式 H2，推荐）**：
1. `WIFI_CORE_SELECT=1` + `WIFI_PROTOCOL_SELECT=2`，编译烧录**仅 1核**。
2. 双击 `启动实时图传上位机.bat`（浏览器弹网页）。
3. 车对桥面静止/手持横移，从"桥前空地→桥面→桥尾"各看几秒。

**看什么**：
- **图像窗口**：`render_bridge_vision_to_image` 已把仲裁控制线 + 退出线画在原图上 → 直接目检"线画得对不对"。
- **示波器 8 通道**（C29，曲线名自动读自 `telemetry_ipc_core1.c` 的 `data[i]=` 表达式）：

| 通道 | 内容 | 期望 |
| --- | --- | --- |
| CH0 | 控制线 x@y=25（像素） | 桥面时 ≈47（图像中心），偏左/偏右偏离 |
| CH1 | `arb->valid`（0/1） | 桥面有效=1，桥外=0 |
| CH2 | `arb->mode`（0~8） | 桥前 0/3；桥面 4/5；偏 6/7 |
| CH3 | `arb->gate`（锁存） | **0→1 后保持**（上桥标志） |
| CH4 | `arb->has_top` | 桥尾=1 |
| CH5 | 退出线 y@x=47（像素） | 桥尾时出现且随接近下移 |
| CH6 | `cost_us`（耗时） | avg≈5.5ms，**max<8ms** |
| CH7 | `arb->source`（0 中点/1 绿线/2 失能） | 与 mode 对应 |

**逐飞助手模式（H1）**：图像窗口看画线；参数调节可在线试参（扩展见 §6）。

**常见问题**：
- 图像没线：mode 恒 0（曝光/亮度语义不对，桥面应≈白 250+、地面≈暗<100）。
- `gate` 不上锁：画面底部没出现"桥面变白"（车太远/角度太大）。
- `top` 不出现：gate 未锁或桥尾未进画面。
- CH6 超 8ms：查 `.map` 确认汇编算子进 ITCM、行缓冲进 DTCM。

**通过标准**：图像画线正确；CH2 桥面稳定 4/5、CH3 锁存、CH4 桥尾出现；CH6 avg<6ms/max<8ms。

## 3. 阶段 B：IPC 发布验证（b2_* 到 0核）

**目标**：证明仲裁输出 b2_* 正确写共享内存、0核 读得到。1核 已通过 C29 把同一份仲裁数据送示波器；0核 视角用 C-SPY 核对。

**方法**：
1. 上位机示波器（CH0-CH7）作为"1核 侧事实"。
2. C-SPY 挂 0核：Watch `g_vision_ipc_latest.b2_valid / b2_mode / b2_gate / b2_has_top / b2_line_a_x1000 / b2_line_b_x100 / b2_line_u_lo / b2_line_u_hi`，与上位机 CH1/CH2/CH3/CH4 对照应一致。
3. 校验点（仲裁 §3.3）：`b2_valid=1` 时 source=0（mode 4/5）或 1（mode 6/7）；`b2_valid=0`+source=2=失能；`u_lo≤25≤u_hi` 支撑校验。

**常见问题**：
- 0核 恒收不到：检查 `VisionIpc_Core0_PollResult` 的 `valid_mask`（需含 `VISION_VALID_BRIDGE_V2`）；检查 1核 是否 `ShouldRunBridge`（0核 enable 门控）。
- seq 不涨：1核 没在发布（`bridge_v2_arbiter_is_busy` 卡死）。

**通过标准**：上位机曲线与 C-SPY 看到的 b2_* 逐字段一致。

## 4. 阶段 C：0核 状态机单独推进（不依赖 Plan4）

**目标**：验证 ALIGN→RUN→EXIT→FINISH 转换、姿态/速度输出。**用 0核 逐飞助手示波器**验证"输入对不对 + 状态机对不对"（输入对了=九成）。

**操作**：
1. 0核 上位机：`WIFI_CORE_SELECT=0` + `WIFI_PROTOCOL_SELECT=1`（逐飞助手）。
2. **0核 示波器切 bridge 调试组**：`main_cm7_0.c` 的 `WIFI_CORE0_ASSISTANT` 块里已加"4.【调试单边桥新管线】"组——取消那 8 行注释、注释掉上方直立环组：

   ```c
   data[0]=b2_valid  data[1]=b2_mode  data[2]=b2_gate  data[3]=b2_has_top
   data[4]=state     data[5]=exit_d_mm  data[6]=traveled_mm  data[7]=err_degree_cmd
   ```
   → 上位机一眼看全：**0核 收到的输入（CH0-3）** + **状态机（CH4-7）**。
3. 触发：`SBUS_ACTIVE_POINT=4` 遥控侧键 → `VisionBridgeTask_Start()`（等价 Plan4 交接）。也可临时在 `main_cm7_0.c` 置 `vision_detected_bridge_point=1`。
4. （兜底）C-SPY 挂 0核，Watch `s_bridge_task` 与 `g_bridge_vision_task_status`。

**状态转换判据**：
- ALIGN(1) → RUN(2)：`traveled ≥ VISION_BRIDGE_TASK_ON_BRIDGE_TRIGGER_MM(900,待标定)`（C11 惯导门）或对齐达标/超时兜底。
- RUN → EXIT(3)：`exit_d ≤ offset_wheel`（1D EKF，C13）或 `traveled≥2300` 或 `state_ticks≥5000`。
- EXIT → FINISH(4)：底盘降回 3.0 或 `EXIT_SETTLE_TICKS`。
- 姿态：`servo_height` 抬到 6.0（RUN）/降回 3.0（EXIT），示波器看俯仰角突变。

**离线推进技巧**：车悬空也能跑状态机（`traveled` 来自惯导，需 `g_yaw_initialized`）；想验证 EKF，桥尾放白纸当退出线，示波器看 `exit_d`（CH5）从 ~1000 递减到 ≤0。

**常见问题**：
- 卡 ALIGN：`traveled`（CH6）不涨（惯导没动/起点错）。
- 卡 RUN 不出 EXIT：`exit_valid` 没起来（`gate=1` 且 `top=1` 且 `z≤1500mm` 才初始化 EKF）或 `offset_wheel` 待标定。
- CH0-3 全 0：核间传输没通（1核 没发布 / 0核 没读到）——先回头做阶段 B。

**通过标准**：CH4 按时序推进 1→2→3→4、姿态按阶段切换、CH0-3 与 1核 上位机曲线一致。

## 5. 阶段 D：全链路（Plan4 交接 → 过桥）

**目标**：完整过桥 + 导航 rebase。

**操作**：
1. 三路上位机对照：逐飞助手（0核 示波器：电机/姿态）+ 网页上位机（1核 图传画线 + bridge 示波器）+ `tools/webview_nav_marker科目四/`（Plan4 轨迹 vs 实车 `nav_vision_fusion`）。
2. 交接验证：距入口 500mm → `Plan4_StartSpecial` → `VisionBridgeTask_Start`，`g_special_action_trigger=1`。
3. rebase 验证：**仅 `exit_reason==VISUAL_CONFIRMED` 才 rebase** 出口点；AUTO_TIMEOUT 不 rebase。看轨迹 webview 在出口处 `nav_vision_fusion` 是否跳变到出口点。

**常见问题**：
- 桥前状态机没启动：交接没触发（距离/路点表）。
- 上桥太早/太晚：标定 `ON_BRIDGE_TRIGGER_MM`。
- 下桥点不对：标定 EKF 常量与 `offset_wheel`。
- rebase 错误：确认 `exit_reason`。
