## 一、V9 算法输出 → IPC 已有字段映射

> **⚠️ 算法微调**：`detect_crease` 的输出逻辑需要修改 — 将返回值从「双峰间的谷点」改为「更靠上（y 更小）的那个尖峰」。详见 §1.1。

### 1.0 `detect_crease` 输出修改（从 trials 复制后实施，仅改 1 行）

**问题**：当前输出的是双峰之间的「谷点」，实际使用时更需要「上方尖峰」位置作为跳跃参考。

**修改**：`detect_crease` 函数最末尾，把输出从谷点改为上方尖峰。检测逻辑完全不动。

```c
// 修改前 (~第594行):
p_result->crease_y    = (int16_t)valid[0].y;        // 谷点

// 修改后:
p_result->crease_y    = (int16_t)(valid[0].bottom_y - valid[0].span);  // 上方尖峰
```

> `bottom_y = max(i1,i2)`, `span = |i2-i1|` → `bottom_y - span = min(i1,i2)` = 上方尖峰（y 更小）。

**不改动**：Step 2.6 排序、候选筛选、谷点验证 —— 全部保持原样。

### 1.1 IPC 字段映射

```
V9 v9_stair_result_t                   IPC vision_ipc_packet_t (已有字段)
┌──────────────────────────┐          ┌─────────────────────────────┐
│ has_stairs               │ ──────→  │ stair_detected              │
│ (joint_score)            │ (内部用) │                             │
│ crease_y (px) ──→ IPM ──→          │ stair_jump1_mm (mm)         │
│ (其他crease)  ──→ IPM ──→          │ stair_jump2_mm, jump3_mm    │
│ (crease数量)             │ ──────→  │ stair_jump_count            │
│ (crease_y vs 图像底部)    │ ──────→  │ stair_stage (0/1/2)        │
│ has_stairs==0 持续N帧    │ ──────→  │ stair_exit_seen            │
│ crease_y最小者 → IPM     │ ──────→  │ stair_next_jump_mm          │
└──────────────────────────┘          └─────────────────────────────┘
```

### 映射细节

| IPC 字段 | 类型 | V9 来源 | 转换方式 |
|---------|------|--------|---------|
| `stair_detected` | uint8 | `has_stairs` | 直接赋值 |
| `stair_stage` | uint8 | crease_y 位置 | 0=无台阶, 1=远处有台阶(crease_y较小), 2=台阶近在眼前(crease_y靠近图像底部) |
| `stair_jump_count` | uint8 | V9 crease 候选数量 | `detect_crease` 可返回多组候选，取有效候选数（最多3） |
| `stair_exit_seen` | uint8 | has_stairs==0 持续N帧 | 连续丢失台阶信号时置 1 |
| `stair_next_jump_mm` | int16 | crease_y → IPM 前向距离 | `IPM_GetPhysicalCoord(center_x, crease_y)` → y_mm |
| `stair_jump1_mm` | int16 | 第1个 crease → IPM | 同上 |
| `stair_jump2_mm` | int16 | 第2个 crease → IPM | 同上 |
| `stair_jump3_mm` | int16 | 第3个 crease → IPM | 同上 |

### 3.2 `code1/vision/stair_vision.c`（新建）

核心流程（镜像 `bridge_vision.c` 的结构）：

```c
#include "stair_vision.h"

// === DTCM 环形缓冲（与 V9 原始测试代码一致） ===
DTCM_BSS int16_t edge_ring[4][94];    // 4行×94 int16 = 752B

// === SRAM 大数组 ===
static int16_t gx_buf[59][91];        // Gx: 59×91 = 10738B
static int16_t gy_buf[57][91];        // Gy: 57×91 = 10374B

// === 全局输出 ===
volatile runtime_profiler_t g_stair_vision_cost_profiler = {0};
volatile runtime_profiler_t g_stair_vision_frame_profiler = {0};
volatile stair_vision_output_t g_stair_vision_output = {0};
volatile uint8 g_stair_vision_output_write_busy = 0U;

void stair_vision_init(void) {
    memset((void *)&g_stair_vision_output, 0, sizeof(g_stair_vision_output));
}

void stair_vision_reset_filter(void) {
    g_stair_vision_output.stable_detected = 0U;
    g_stair_vision_output.detected_streak = 0U;
    g_stair_vision_output.lost_streak = 0U;
}

const volatile stair_vision_output_t *stair_vision_get_output(void) {
    return &g_stair_vision_output;
}

void stair_vision_process_camera_frame(const uint8 *gray) {
    g_stair_vision_output_write_busy = 1U;

    RUNTIME_PROFILER_START(g_stair_vision_cost_profiler);

    // [阶段1] 卷积：逐行流入，调用汇编算子
    int ring_idx = 0, gx_out = 0, gy_out = 0;
    for (int row = 0; row < 60; row++) {
        int16_t *rb = edge_ring[ring_idx];
        for (int x = 0; x < 94; x++) rb[x] = (int16_t)gray[row * 94 + x];

        if (row >= 1) {
            v9_conv_gx_row(edge_ring[(ring_idx-1)&3], rb, gx_buf[gx_out], 91);
            gx_out++;
        }
        if (row >= 3) {
            v9_conv_gy_row(edge_ring[(ring_idx-3)&3], edge_ring[(ring_idx-2)&3],
                           edge_ring[(ring_idx-1)&3], edge_ring[ring_idx],
                           gy_buf[gy_out], 91);
            gy_out++;
        }
        ring_idx = (ring_idx + 1) & 3;
    }

    // [阶段2] 后处理
    v9_stair_result_t result;
    v9_stair_process_full(&gx_buf[0][0], &gy_buf[0][0], 57, 91, &result);

    RUNTIME_PROFILER_STOP(g_stair_vision_cost_profiler);

    // [阶段3] 填充 raw 结果
    stair_vision_frame_result_t *raw = (stair_vision_frame_result_t *)&g_stair_vision_output.raw;
    raw->detected     = result.has_stairs;
    raw->joint_score  = result.joint_score;
    raw->left_rho     = result.left_rho;
    raw->left_theta   = result.left_theta;
    raw->right_rho    = result.right_rho;
    raw->right_theta  = result.right_theta;
    raw->center_a     = result.center_a;
    raw->center_b     = result.center_b;
    raw->center_c     = result.center_c;
    raw->crease_y     = result.crease_y;
    raw->crease_span  = result.crease_span;
    // TODO: 扩展 detect_crease 返回多候选后填充 crease_y_candidates

    // [阶段4] 连续帧滤波
    g_stair_vision_output.frame_id++;
    g_stair_vision_output.raw_detected = raw->detected;

    if (raw->detected) {
        g_stair_vision_output.detected_streak++;
        g_stair_vision_output.lost_streak = 0U;
        if (g_stair_vision_output.detected_streak >= STAIR_VISION_CONFIRM_FRAMES) {
            g_stair_vision_output.stable_detected = 1U;
            g_stair_vision_output.stable = *raw;
        }
    } else {
        g_stair_vision_output.lost_streak++;
        g_stair_vision_output.detected_streak = 0U;
        if (g_stair_vision_output.lost_streak >= STAIR_VISION_LOST_HOLD_FRAMES) {
            g_stair_vision_output.stable_detected = 0U;
        }
    }

    g_stair_vision_output_write_busy = 0U;
    RUNTIME_PROFILER_UPDATE(g_stair_vision_frame_profiler);
}
```

## 五、V9 与 three_stage_control 的后续对接（本次不实施）

当前 `vision_three_stage_control.c` 使用 **PVC** 作为检测后端（`VISION_TARGET_PVC_ENTRY`），通过 `pvc_entry_bottom_y` / `pvc_entry_top_y` 判断跳跃时机。

V9 接入后，`three_stage_control` 有两种使用方式：

**方式A：V9 替代 PVC**（修改 `Start()`）：
```c
// 将 VisionIpc_Core0_SetTask(VISION_TARGET_PVC_ENTRY, VISION_MASK_PVC_ENTRY)
// 改为同时开启两个检测后端:
VisionIpc_Core0_SetTask(VISION_TARGET_STAIR_UP,
    VISION_MASK_STAIR_UP | VISION_MASK_PVC_ENTRY);
```
然后在 `Update_2ms()` 中同时读取 `stair_*` 和 `pvc_*` 字段。

**方式B：V9 作为辅助**（不修改控制逻辑）：V9 数据仅用于调试/监控，PVC 继续主导跳跃触发。

> 建议先完成本次接入（V9 数据通过 IPC 流通），再根据实测效果决定如何对接 control。
