### 1.2 `v9_stair_postprocess.c` 1 行改动

```c
// detect_crease 末尾，只改这一行:
//   p_result->crease_y = (int16_t)valid[0].y;                         // 谷点
// → p_result->crease_y = (int16_t)(valid[0].bottom_y - valid[0].span); // 上方尖峰
```

检测逻辑完全不动。`bottom_y - span = min(i1,i2)` = y 更小的那个峰。

### 1.3 `stair_vision.h` / `stair_vision.c`

完全镜像 `bridge_vision.h/c` 的模式：`init` / `reset_filter` / `get_output` / `process_camera_frame`。输入为 `compressed_image_copy[0]`（60×94 uint8），内部调用 V9 汇编卷积 + 后处理管线 + 连续帧滤波。

### 1.4 `code1/wifi.c` 渲染函数

在 `render_bridge_vision_to_image()` 旁边新增 `render_stair_vision_to_image()`：

- 读取 `stair_vision_get_output()`
- 若 `has_stairs`：在图像上画 crease 位置（水平横线标记上方尖峰 y 坐标）
- 若有边界线（`left_rho/theta`, `right_rho/theta`）：计算并画出左右边界线

### 1.5 `main_cm7_1.c` 硬编码调用

```c
// 头文件
#include "../code1/vision/stair_vision.h"

// init (在 bridge_vision_init() 之后)
stair_vision_init();

// 摄像头循环 (在 bridge_vision_process 之后, 硬编码开启)
stair_vision_process_camera_frame(compressed_image_copy[0]);
render_stair_vision_to_image();
```

## Phase 2: IPC + 控制对接

> **前提**: Phase 1 验收通过。  
> **目标**: V9 结果通过核间通信传给 Core0，`vision_three_stage_control` 可读取。

### 2.1 改什么

**Core1**：`vision_ipc_core1.c/h` 照抄 bridge 模式补齐 stair 的 `ShouldRun` / `TakeReset` / `command_wants` / `fill` / `PollCommand` 分支 / `PublishCurrent` 分支。`vision_ipc.h` 协议已完备，不需动。

**Core0**：`vision_three_stage_control::Start()` 中把 `SetTask` 调用的目标从 `VISION_TARGET_PVC_ENTRY` 扩展为同时开启 `VISION_TARGET_STAIR_UP`（通用接口 `SetTask` 本身不需要新增 wrapper）。`Update_2ms()` 中读取 `stair_*` 字段的逻辑按需对接。

**main_cm7_1.c**：`stair_vision_process_camera_frame` 从硬编码改为 `ShouldRunStair()` 控制。
