# 循迹系统逻辑文档

> 更新日期：2026-06-30
> 覆盖范围：惯导打点 → 离线规划 → 编译烧录 → MCU实时跟踪 全链路
> 本文档基于代码实际逻辑编写，每处均标注代码出处。

---

## 1. 一句话概括

小车遥控跑一遍、惯导打点记录轨迹 → PC端Python脚本插值平滑+离线速度规划 → 生成C头文件编译烧录 → MCU用纯追踪算法（Pure Pursuit）实时跟踪预规划轨迹，10ms一个周期。

---

## 2. 整体数据流

```
┌──────────────────────────────────────────────────────────────┐
│                     离线阶段（PC端）                           │
│                                                              │
│  遥控跑车 → 惯导打点 → WiFi → nav_marker_host.py             │
│                                    ↓                         │
│                            导出 CSV                           │
│                                    ↓                         │
│              calculate_path.py / chazhi.py                    │
│              (插值 + 曲率计算 + 离线速度规划)                   │
│                                    ↓                         │
│              nav_replay_route_table.h (7字段, const数组)      │
│                                    ↓                         │
│                          编译 & 烧录                          │
└──────────────────────────────────────────────────────────────┘
                              ↓
┌──────────────────────────────────────────────────────────────┐
│                     实时阶段（MCU端）                           │
│                                                              │
│  IMU + 轮编码器 → InertialNav_Update() → (x, y, yaw)        │
│                          ↓                                   │
│  NavReplay_Process() ← 路表 points[]                         │
│       ↓                    ↓                                 │
│  err_degree          target_speed_set                        │

│  转向PID(3ms) → 舵机   速度PID(9ms) → 电机                   │

```

## 4. 数据结构

### 4.1 路表点 `NavRamPoint_t`

> 代码出处：`code/navigation/nav_ram.h` 第37-46行

```c
typedef struct
{
    float x;              // 世界坐标X (mm)，小车向后为正
    float y;              // 世界坐标Y (mm)，小车向右为正
    float target_yaw_deg; // 目标航向角 (deg)，路径切向角
    float heading_deg;    // 绝对航向角（IMU963RA磁力计用，IMU_CATEGORY==3时有效）
    uint8 point_type;     // 点类型，见下表
    float target_speed;   // 目标速度（离线规划写入，速度指令单位，负数=前进）
    float curvature;      // 路径曲率 (1/mm)，离线规划写入，纯追踪弯道自适应用
} NavRamPoint_t;
```

**注意**：字段顺序为 `x, y, target_yaw_deg, heading_deg, point_type, target_speed, curvature`，与旧版5字段格式不同。自动生成的路表头文件中以7字段初始化列表写入。

### 4.2 点类型枚举

> 代码出处：`code/navigation/nav_ram.h` 第18-26行

| 1 | `NAV_POINT_CIRCLE` | 转圈点（雷区入口，会触发特殊动作/停止屏障） |

## 5. 离线阶段详解

### 5.1 打点

> 代码出处：`code/navigation/nav_ram.c` 第48-75行

小车在遥控模式下行驶时，`NavRam_RecordPoint(point_type)` 被调用：
- 从 `inertial_nav.x` / `inertial_nav.y` 快照当前位姿
- 从 `inertial_nav.relative_yaw` 记录目标航向角
- IMU_CATEGORY==3时，从全局变量 `heading` 记录绝对航向（磁力计）
- `target_speed` 和 `curvature` 此时为0，后续由离线脚本写入
- 最多记录 `NAV_RAM_MAX_POINTS`（5000）个点

### 5.2 WiFi传输

MCU通过WiFi将惯导数据实时发送到PC。`nav_marker_host.py` 在 `192.168.137.1:8086` 运行TCP服务器，接收84/86字节遥测帧，解码后在Web界面展示轨迹。操作员标记特殊点后导出CSV。

### 5.3 插值 + 速度规划

> 代码出处：`tools/webview_nav_marker速度规划/chazhi.py`

#### 5.3.1 路径插值

将原始打点插值为均匀间距（默认50mm）。支持6种插值方法：
1. Cubic Spline
2. PCHIP
3. Akima
4. Corner Fillet（默认）
5. B-Spline
6. Linear

特殊点（圆环等）会被snap回原始坐标。

#### 5.3.2 曲率计算

> 代码出处：`tools/webview_nav_marker速度规划/chazhi.py` 第589-607行

对插值后的路径逐点计算有符号曲率 `kappa`，写入 `points[i].curvature`。

#### 5.3.3 离线速度规划

> 代码出处：`tools/webview_nav_marker速度规划/chazhi.py` 第589-629行

**算法流程**（`apply_speed_plan` 函数）：

1. **曲率限速包络**（第602-606行）：
   ```
   curve_limit = sqrt(MAX_LATERAL_ACCEL_MM_S2 / max(|kappa|, 1e-6))
   speed_limit[i] = min(PATH_SPEED_MAX_MM_S, curve_limit)
   ```
   弯道越急（kappa越大），允许的最高速度越低。

2. **停止点约束**（第609-613行）：
   - 最后一个点：`speed_limit = 0`
   - `NAV_POINT_CIRCLE` 类型的点：`speed_limit = 0`

3. **反向减速扫描**（第617-620行）：
   ```
   planned_speed[i] = min(planned_speed[i], sqrt(v[i+1]^2 + 2 * MAX_DECEL * ds))
   ```
   从终点往起点扫，确保每个点有足够的减速距离到达下一个低速点。

4. **正向加速扫描**（第622-625行）：
   ```
   planned_speed[i] = min(planned_speed[i], sqrt(v[i-1]^2 + 2 * MAX_ACCEL * ds))
   ```
   从起点往终点扫，确保每个点的加速不超过物理极限。

5. **单位换算**（第627-629行）：
   ```
   target_speed_cmd = -planned_speed / SPEED_TO_MM_S
   ```
   转为速度指令单位（负数=前进），写入 `point.target_speed`。

**关键参数**（`chazhi.py` 第41-74行）：

| 参数 | 默认值 | 作用 |
|------|--------|------|
| `PATH_SPEED_MAX_MM_S` | 5000.0 | 最大速度上限 (mm/s) |
| `MAX_ACCEL_MM_S2` | 2500.0 | 最大加速度 (mm/s²) |
| `MAX_DECEL_MM_S2` | 1500.0 | 最大减速度 (mm/s²) |
| `MAX_LATERAL_ACCEL_MM_S2` | 2500.0 | 最大横向加速度 (mm/s²)，决定弯道速度上限 |
| `SPEED_TO_MM_S` | 4.936 | 速度指令换算系数（rpm → mm/s） |

#### 5.3.4 输出格式

输出7字段格式到 `nav_replay_route_table.h`：
```c
{x, y, target_yaw_deg, heading_deg, target_speed, point_type, curvature}
```

示例（`code/navigation/nav_replay_route_table.h` 第18行）：
```c
{-50.073f, -0.318f, 0.359f, 0.000f, -607.780f, (uint8)0, -0.000002f}
```

### 5.4 编译 & 烧录

`nav_replay_route_table.h` 被 `plan1_pure_pursuit_speed_planning.c` 通过 `#include` 引入（第3行），编译期成为 `const` 数组 `nav_replay_static_route_points[]`，烧录进Flash。

### 6.2 惯性导航解算（10ms周期）

> 代码出处：`user/cm7_0_isr.c` 第314-371行，`code/navigation/inertial_nav.c` 第31-110行

**调用时机**：`cm7_0_isr.c` 第314行，`loop_counter % 10 == 1` 且 `g_yaw_initialized` 为真。

**调用方式**（以 `IMU_CATEGORY==3 && CAR_SELECT==3` 为例，`cm7_0_isr.c` 第348-357行）：
```c
InertialNav_Update(
    euler_angle.yaw,                                          // 当前偏航角
    9806.65*((float)imu_data.acc_x/4098 - (float)imu_data.grav_x), // 横向加速度 (左+)
    9806.65*((float)imu_data.acc_y/4098 - (float)imu_data.grav_y), // 纵向加速度 (前+)
    (float)motor_value.receive_left_speed_data,               // 左轮速
    (float)motor_value.receive_right_speed_data               // 右轮速
);
```

**算法**（`code/navigation/inertial_nav.c` 第31-110行）：

#### 步骤1：单位转换（第42-44行）
```c
float v_L_mm = -speed_L * SPEED_TO_MM_S;   // 左轮：原始值取反 × 系数
float v_R_mm = speed_R * SPEED_TO_MM_S;     // 右轮：原始值 × 系数
float v_wheel_avg = (v_L_mm + v_R_mm) * 0.5f;  // 平均轮速
```

`SPEED_TO_MM_S` 由 `CAR_SELECT` 决定（`code/navigation/inertial_nav.h` 第23-40行）：
- `CAR_SELECT==0`：3.4596
- `CAR_SELECT==2`：4.866666 × 1.065
- `CAR_SELECT==3`：4.936

#### 步骤2：打滑检测（第47-65行）
```c
float theoretical_yaw_rate = (v_R_mm - v_L_mm) / WHEEL_BASE_MM;  // 理论角速度
// 比较理论角速度与IMU实测角速度
if (fabsf(v_wheel_avg) > 100.0f && fabsf(theoretical_yaw_rate - actual_yaw_rate) > 0.5f)
    slip_flag = 1;  // 打滑
```

阈值 `YAW_RATE_DIFF_THRES = 0.5 rad/s`（`inertial_nav.h` 第16行）。

#### 步骤3：纵向速度融合（第77-81行）
```c
float alpha = slip_flag ? 0.3f : 0.9f;  // 正常90%轮速，打滑30%轮速
float v_pred = vx_body + acc_lon * 0.01f;  // 加速度积分预测
vx_body = alpha * v_wheel_avg + (1 - alpha) * v_pred;  // 互补滤波
```

`NAV_ALPHA_VEL = 0.9f`（`inertial_nav.h` 第15行），打滑时降为 `0.3f`。

#### 步骤4：横向速度（第84-89行）
```c
if (fabsf(acc_lat) < 200.0f)      // 死区：侧向加速度 < 200 mm/s²
    vy_body *= 0.8f;               // 快速衰减
else
    vy_body = vy_body * 0.95f + acc_lat * 0.01f;  // 积分+衰减
```

#### 步骤5：坐标变换与积分（第94-109行）
```c
// 车身坐标系 → 世界坐标系
float vx_world = vx_body * cos(yaw) - vy_body * sin(yaw);
float vy_world = vx_body * sin(yaw) + vy_body * cos(yaw);
// 积分
inertial_nav.x += vx_world * 0.01f;  // 10ms积分
inertial_nav.y += vy_world * 0.01f;
```

#### 步骤6：跳跃保护

> 代码出处：`user/cm7_0_isr.c` 第360-364行

```c
if (jump_flag != 0) {
    inertial_nav.vx_body = 0.0f;  // 冻结速度，防止轮胎空转导致里程突增
    inertial_nav.vy_body = 0.0f;
}
```

**输出**：`inertial_nav` 全局结构体，供 `NavReplay_Process()` 使用。

#### 6.3.1 启动流程

> 代码出处：`user/main_cm7_0.c` 第401-414行，`plan1_pure_pursuit_speed_planning.c` 第112-153行

**启动序列**：

1. `InertialNav_Init()` → 清零惯导状态（`main_cm7_0.c` 第405行）
2. `NavReplay_Start()`（`main_cm7_0.c` 第407行），内部执行：

3. **起跑航向对齐**（`IMU_CATEGORY==3` 时，`plan1_pure_pursuit_speed_planning.c` 第273-306行）：
   - 每个10ms周期计算 `heading_err = NAV_REPLAY_START_HEADING_DEG - heading`
   - 限幅到 ±25° 作为 `err_degree` 输出（舵机会转车对齐）
   - 停车等待（`target_speed_set = 0`）
   - 航向误差连续6个周期稳定在 ±0.3° 内，视为对齐完成
   - 对齐完成后调用 `NavReplay_ResetLaunchPose()`（第312-329行）：清零 x/y/vx/vy/relative_yaw，记录 init_yaw

特殊动作结束后的第一个周期，清空所有滤波历史，避免历史状态干扰恢复后的跟踪。恢复期搜索窗口扩大到300个点（约6米）。

##### 阶段3：最近点搜索

> 代码出处：`plan1_pure_pursuit_speed_planning.c` 第385-436行（函数），第559-562行（调用）

**函数**：`Find_Closest_Point_Index_Strict(current_idx, search_range, is_recovering)`

**搜索逻辑**：
1. 从 `g_target_idx` 开始，向后搜索 `search_range` 个点（正常80个，恢复期300个）
2. 搜索范围受停止屏障限制（不能越过停车点，第413-417行）
3. 找出离车最近的点（欧氏距离平方最小），更新 `g_target_idx`
4. **丢位保护**（第430-433行）：最近距离 > 800mm 时保持原索引不变，防止惯导漂移导致跳点

**核心特性：没有"到达判定"。** 中间点不判断"到了没有"，索引通过最近点搜索自然推进——车在哪，索引就在哪。只有终点有显式到达判定。

##### 阶段4：停止屏障搜索 + 终点检测

> 代码出处：`plan1_pure_pursuit_speed_planning.c` 第339-375行（函数），第574-588行（调用）

**函数**：`NavReplay_FindStopBarrierIndex(start_idx, search_range)`

从当前点向前扫描，找到第一个停止屏障：
- `NAV_POINT_CIRCLE` 类型的点（第360-363行）
- `target_speed` 绝对值 ≤ 1.0 的点（第364-367行，`NAV_STOP_LOCK_SPEED_EPS`）
- 路径最后一个点（第368-371行）

前瞻目标点不能越过停止屏障，否则小车会冲过停车点。

**终点判定**（第578-588行）：
```c
if (stop_idx == last_idx && dist_to_stop <= 20.0f) {  // NAV_DIST_ARRIVE = 20mm
    g_replay_state = REPLAY_FINISHED;
    target_speed_set = 0.0f;
    err_degree = 0.0f;
}
```

##### 阶段5：近停点航向锁死更新

> 代码出处：`plan1_pure_pursuit_speed_planning.c` 第477-493行（函数），第616行（调用）

**函数**：`NavReplay_UpdateStopLock(stop_idx, dist_to_stop)`

```c
if (|target_speed| <= 1.0f && dist_to_stop < 50.0f) {  // NAV_STOP_LOCK_DIST_MM = 50mm
    if (!s_stop_lock_active) {
        s_stop_lock_active = 1;
        s_stop_lock_yaw_deg = inertial_nav.relative_yaw;  // 锁存当前航向
    }
}
```

接近零速停车点时，锁存当前 `relative_yaw`。此后 `err_degree` 用锁存值而非纯追踪计算（阶段6中判断），防止停车时惯导漂移导致车头乱转。

##### 阶段6：纯追踪前瞻计算

> 代码出处：`plan1_pure_pursuit_speed_planning.c` 第634-672行

###### 6a. 前瞻距离计算（第636-643行）

```c
// 基准前瞻距离
lookahead_min = max(PP_LD_MIN_CURVE, base_spacing * PP_LD_MIN_STRAIGHT);
// 曲率缩减因子
ahead_kappa = nav_ram_data.points[base_idx + 15].curvature;  // 前方约750mm处曲率
shrink_factor = 1.0 - |ahead_kappa| * PP_LD_KAPPA_SHRINK_GAIN;
shrink_factor = max(shrink_factor, PP_LD_KAPPA_SHRINK_MIN);
// 最终前瞻距离
lookahead_dist = (lookahead_min + |speed| * PP_LD_SPEED_GAIN) * shrink_factor;
```

**参数**（`plan1_pure_pursuit_speed_planning.h`）：

| 参数 | 值 | 行号 | 作用 |
|------|----|------|------|
| `PP_LD_MIN_CURVE` | 500.0f mm | 第14行 | 最小前瞻距离，弯道基准 |
| `PP_LD_MIN_STRAIGHT` | 1.2f | 第16行 | 直道前瞻倍率，按点间距放大 |
| `PP_LD_SPEED_GAIN` | 0.7f | 第18行 | 速度前瞻增益，速度越大看得越远 |
| `PP_LD_KAPPA_SHRINK_GAIN` | 500.0f | 第26行 | 曲率缩减增益 (1/mm) |
| `PP_LD_KAPPA_SHRINK_MIN` | 0.3f | 第28行 | 前瞻缩减下限，防止急弯时前瞻过小 |

**效果**：速度快 → 前瞻远 → 走线平滑；速度慢 → 前瞻近 → 转弯灵敏；弯道 → 前瞻缩短 → 更贴线。

###### 6b. 前瞻目标查找（第448-469行）

**函数**：`NavReplay_FindLookaheadTarget(base_idx, stop_idx, lookahead_dist, &tx, &ty, &out_idx)`

从基准点向前扫描，找到第一个距离 ≥ 前瞻距离的点作为目标 `(tx, ty)`。不会越过停止屏障。如果所有点都在前瞻距离内，则使用停止屏障点作为目标。

###### 6c. 转向角计算（第647-672行）

**航向锁死分支**（第647-651行）：
```c
if (s_stop_lock_active) {
    err_degree = NormalizeAngle(s_stop_lock_yaw_deg - inertial_nav.relative_yaw);
}
```

**正常纯追踪分支**（第653-672行）：
```c
float target_yaw = -atan2f(ty - y, -(tx - x)) * 57.29578f;  // 转为度
raw_err_degree = NormalizeAngle(target_yaw - relative_yaw);
```

负号是适配坐标系定义（X向后、Y向右）。

**弯道旁路滤波**（第657-661行）：
```c
if (fabsf(target_kappa) > KAPPA_CURVE_BYPASS_THRESH) {  // 0.0005 1/mm
    err_degree = raw_err_degree;  // 跳过滤波，直接输出
}
```

弯道时旁路 Slew Rate 和低通滤波，释放差速底盘敏捷性。

**直道滤波**（第665-670行）：
```c
// Slew Rate 限幅：单周期最大变化 ±35°
if (diff > SLEW_RATE_ANGLE) raw_err_degree = prev + SLEW_RATE_ANGLE;
// 一阶低通：alpha=0.45
err_degree = 0.45 * raw_err_degree + 0.55 * prev;
```

**滤波参数**（`plan1_pure_pursuit_speed_planning.h`）：

| 参数 | 值 | 行号 | 作用 |
|------|----|------|------|
| `FILTER_ALPHA_ANGLE` | 0.45f | 第20行 | 角度低通系数，越大越跟手 |
| `SLEW_RATE_ANGLE` | 35.0f | 第24行 | 单周期最大角度变化 (deg) |
| `KAPPA_CURVE_BYPASS_THRESH` | 0.0005f | 第30行 | 弯道旁路曲率阈值 (1/mm) |

##### 阶段6.5：曲率前馈

> 代码出处：`plan1_pure_pursuit_speed_planning.c` 第675-678行

```c
float feedforward_angle = target_kappa * fabsf(s_prev_speed_set) * K_FF_CURVATURE;
err_degree = err_degree + feedforward_angle;
```

| 参数 | 值 | 行号 | 作用 |
|------|----|------|------|
| `K_FF_CURVATURE` | 100.0f | 第32行 | 曲率前馈增益 |

在纯追踪反馈的基础上，叠加一个与曲率×速度成正比的前馈角，入弯前主动转向，减少反馈滞后。`target_kappa` 取自前瞻目标点的 `curvature` 字段。

##### 阶段7：离线速度查表 + 斜率限幅

> 代码出处：`plan1_pure_pursuit_speed_planning.c` 第681-689行

```c
raw_speed = nav_ram_data.points[base_idx].target_speed;  // 直接从路表读取
if (s_stop_lock_active && raw_speed > 0.0f)
    raw_speed = 0.0f;  // 锁死期间强制停车

target_speed_set = NavReplay_SpeedSlew_Update(raw_speed);
```

速度直接读取路表 `target_speed` 字段，不做运行时计算。

**速度斜率限幅器** `NavReplay_SpeedSlew_Update()`（第233-265行）：

| 场景 | 条件 | 行为 |
|------|------|------|
| 加速 | abs(raw) > abs(prev) | **直接透传原始速度，不限幅**（第241-245行） |
| 跨零 | raw × prev < 0 | 步长限制 120/周期（第248-249行） |
| 高速减速 | abs(prev) > 220 | 步长限制 95/周期（第256-257行） |
| 普通减速 | 其他减速 | 步长限制 65/周期（第256行） |

**注意**：加速时不限幅是为了保留速度台阶，避免把加速前馈的触发条件抹平。`NAV_SPEED_SLEW_UP_LOW`(30) 和 `NAV_SPEED_SLEW_UP_NORMAL`(45) 虽然定义了宏，但在当前代码中不会被使用。

**限幅参数**（`plan1_pure_pursuit_speed_planning.h` 第35-42行）：

| 参数 | 值 | 行号 | 作用 |
|------|----|------|------|
| `NAV_SPEED_SLEW_EPS` | 1.0f | 第35行 | 速度变化死区 |
| `NAV_SPEED_SLEW_LOW_SPEED_TH` | 80.0f | 第36行 | 低速分界 |
| `NAV_SPEED_SLEW_FAST_DECEL_TH` | 220.0f | 第37行 | 高速减速分界 |
| `NAV_SPEED_SLEW_DOWN_NORMAL` | 65.0f | 第40行 | 普通减速步长 |
| `NAV_SPEED_SLEW_DOWN_FAST` | 95.0f | 第41行 | 高速减速步长 |
| `NAV_SPEED_SLEW_DOWN_CROSS_ZERO` | 120.0f | 第42行 | 跨零/停车步长 |
| `NAV_STOP_LOCK_DIST_MM` | 50.0f | 第43行 | 近停点锁死距离 |
| `NAV_STOP_LOCK_SPEED_EPS` | 1.0f | 第45行 | 零速判定阈值 |

## 8. 常见改动场景指引

### 8.1 换车/调车

1. 修改 `code/config/car_select.h` 中的 `CAR_SELECT`
2. 确认 `code/navigation/inertial_nav.h` 中对应车的 `SPEED_TO_MM_S`、`WHEEL_BASE_MM` 校准正确
3. 重新打点、运行 `calculate_path.py` / `chazhi.py` 生成新路表、编译烧录

### 8.2 调整跟踪参数

`code/navigation/nav_replay/plan1/plan1_pure_pursuit_speed_planning.h` 中的关键参数：

| 参数 | 默认值 | 行号 | 作用 | 调大效果 | 调小效果 |
|------|--------|------|------|---------|---------|
| `PP_LD_MIN_CURVE` | 500mm | 14 | 最小前瞻距离 | 走线更平滑，弯道可能切弯 | 转弯更灵敏，可能抖动 |
| `PP_LD_SPEED_GAIN` | 0.7 | 18 | 前瞻速度增益 | 高速看得更远 | 高速看得更近 |
| `PP_LD_KAPPA_SHRINK_GAIN` | 500 | 26 | 曲率缩减增益 | 弯道前瞻更短，更贴线 | 弯道前瞻更长，更平滑 |
| `FILTER_ALPHA_ANGLE` | 0.45 | 20 | 角度低通系数 | 更跟手，可能抖 | 更平滑，可能迟钝 |
| `SLEW_RATE_ANGLE` | 35° | 24 | 单周期最大角度变化 | 转向更迅速 | 转向更平缓 |
| `K_FF_CURVATURE` | 100 | 32 | 曲率前馈增益 | 入弯更主动，过大会振荡 | 入弯更迟钝 |
| `NAV_STOP_LOCK_DIST_MM` | 50mm | 43 | 近停锁死距离 | 更早锁航向 | 更晚锁航向 |

### 8.3 修改速度规划逻辑

速度规划在PC端 `tools/webview_nav_marker速度规划/chazhi.py` 中完成，关键参数（第41-74行）：

```python
PATH_SPEED_MAX_MM_S = 5000.0       # 最大速度
MAX_ACCEL_MM_S2 = 2500.0           # 最大加速度
MAX_DECEL_MM_S2 = 1500.0           # 最大减速度
MAX_LATERAL_ACCEL_MM_S2 = 2500.0   # 最大横向加速度（影响弯道速度）
SPEED_TO_MM_S = 4.936              # 速度指令换算系数
```

修改后重新运行脚本，生成新的 `nav_replay_route_table.h`，重新编译烧录。

### 8.4 切换到运行时曲线测速方案

将 `code/navigation/nav_replay/nav_options.h` 中：
```c
#define NAV_PLAN1_METHOD  PLAN1_PURE_PURSUIT  // 改为2
```

此时速度不再从路表读取，而是运行时根据前方曲率实时计算。路表中的 `target_speed` 字段被忽略。

## 9. 完整的单周期流程图

```
每10ms (user/cm7_0_isr.c, loop_counter % 10 == 3):
│
├─ g_motor_enable? 颠簸/桥任务未激活? → 否 → 跳过
│
├─ g_replay_state == RUNNING? → 否 → 跳过
│
├─ 起跑航向已对齐? → 否 → HandleStartHeadingAlignment()，跳过
│
├─ 阶段1: g_special_action_trigger == 1? → 是 → 跳过（上层接管）
│
├─ 阶段2: 从接管恢复? → 是 → 清空滤波历史，扩大搜索窗口
│
├─ 阶段3: Find_Closest_Point_Index_Strict()
│         从g_target_idx向后80个点内找最近点 → 更新g_target_idx
│         （恢复期300个点；最近距离>800mm则保持原索引）
│
├─ 阶段4: FindStopBarrierIndex() + 终点检测
│         └─ 到达终点(dist<=20mm)? → FINISHED，停车
│
├─ 阶段5: UpdateStopLock()
│         距零速点<50mm → 锁存航向
│
├─ 阶段6: 纯追踪
│         前瞻距离 = [max(500, 间距×1.2) + |速度|×0.7] × shrink_factor
│         找前瞻目标 (tx, ty)
│         弯道(|kappa|>0.0005)? → 旁路滤波，直接输出raw_err
│         直道? → Slew Rate(±35°) + 低通(0.45)
│
├─ 阶段6.5: 曲率前馈
│           err_degree += kappa × |speed| × 100
│
├─ 阶段7: 速度
│         raw_speed = 路表[base_idx].target_speed
│         锁死期间且raw>0? → 强制0
│         加速? → 直接透传
│         减速? → 斜率限幅(65/95/120)
│
└─ 输出: err_degree → 舵机(3ms PID)
         target_speed_set → 电机(9ms PID + 前馈)
```
