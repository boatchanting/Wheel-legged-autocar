# Single Bridge Detection 深度性能优化报告

## 1. 基线与测试方法

- 输入：`94x60`、8 位灰度图。
- 数据：`2026_07_06_16_54_45_Video_v30`，共 568 帧。
- PC 编译：Visual Studio 2022 `cl /O2 /TC`。
- 计时范围：只包围 `bridge_detection_detect_gray()`，不包含 PGM 读取、CSV 写入和日志。
- 基线五轮平均帧耗时中位数：`2717 us`。
- 优化结果与 Python `summary.csv` 逐帧比较。

## 2. 修改前热点分析

数据集统计：

- 每帧阈值候选：平均 `9.04`，最大 `11`。
- 每帧连通域：平均 `17.03`，最大 `40`。
- 进入候选评估的连通域：平均 `11.48`，最大 `31`。
- 侧边拟合点数：平均约 `42`，最大 `58`。
- 横边拟合点数：平均约 `66`，最大 `92`。

实测阶段占比：

| 阶段 | 基线耗时 | 占比预测/实测 |
|---|---:|---:|
| 多阈值生成、阈值图和全图形态学 | 0.82 ms | 30% |
| 连通域提取 | 0.08 ms | 3% |
| 每候选重复形态学 | 0.90 ms | 33% |
| 填洞 | 0.19 ms | 7% |
| 凸包和行边界 | 0.31 ms | 11% |
| 直线拟合和状态输出 | 0.45 ms | 16% |

主要复杂度：

- 字节掩膜形态学：`O(T*N*K)`；`T` 为阈值数，`N=5640`，`K=4/9` 邻域操作。
- 连通域逐像素 BFS：`O(T*N)`，但每像素包含队列、取模和四个分支。
- 原直线拟合：枚举点对后再次扫描全部点，复杂度 `O(P^3)`。
- 原凸包点收集：扫描全部掩膜点并使用通用排序/浮点栅格化。
- 原填洞：对每个候选再次执行全背景逐像素 BFS。

Cache 和分支问题：

- 旧工作区为 8 张 `5760` 字节图加一个 `uint16_t` 队列，共 `57600` 字节。
- 多张字节图反复全图访问，工作集大于必要值，降低数据 Cache 有效性。
- 3x3 形态学在最内层反复进行边界判断和短路分支。
- 连通域对每个像素执行 `% width`、`/ width` 和四邻域分支。
- 阈值最内层原有三个列区间判断。

## 3. 已采用的算法级优化

### 3.1 32 位行位图

每行 94 位使用 3 个 `uint32_t`。3x3、2x2 膨胀/腐蚀通过行间 OR/AND 和跨字移位完成。

- 一次形态学处理由数万次逐像素邻域判断变成约 `60*3` 次字操作/遍历。
- 位图大小为 `720` 字节，能很好地停留在 Cortex-M7 D-Cache。
- 形态学语义与 SciPy 原点规则保持一致。

### 3.2 扫描线连通域

队列元素由“单个像素”改为“水平连续游程”。每次出队只扫描上一行和下一行的重叠范围。

- 拓扑仍为严格 4 邻域。
- 大幅减少队列操作、除法、取模和分支。
- 连续内存访问更适合 M7 Cache 和预取。

### 3.3 删除填洞

原流程为：`连通区域 -> 填洞 -> 凸包`。

填充内部孔洞不会增加新的极值点，因此不可能改变同一连通区域的凸包。优化版直接对形态学结果求凸包，属于数学等价删除，不降低精度。

### 3.4 无排序凸包

每列只保留顶部和底部极值点，按列天然有序，再构造单调链凸包。

- 不使用 `qsort()`。
- 不收集内部点。
- 使用 Q16 整数交点进行扫描线填充。

### 3.5 快速确定性拟合

原拟合为 `O(P^3)`。优化版从最多 24 个均匀分布的确定性样本中枚举点对，再对全部点做残差验证和两轮最小二乘修正：

- 复杂度变为 `O(S^2*P)`，其中 `S<=24`。
- 没有随机数，嵌入式执行时间和输出可重复。
- 568 帧的边线可见性和桥状态全部保持一致。

### 3.6 精确重复帧缓存

缓存前一帧灰度图和完整输出。只有尺寸、配置和全部 5640 个像素完全相同才复用；相似帧不会命中。

- 不影响新帧最坏延迟。
- 数据集中重复帧命中率约 `68.1%`。
- 这是严格结果缓存，不是跳帧或近似检测。

### 3.7 多帧时序快速路径

除逐字节相同帧缓存外，优化版还实现了相邻帧的保守时序检测路径：

1. 先统计当前灰度图相对前帧的变化。只有灰度变化超过 8 的像素不多于 96 个，才允许进入时序路径。
2. 仅在上一帧稳定处于 `ON_BRIDGE` 时运行；进入、退出或未检测到桥时一律全量检测。
3. 使用上一帧阈值及当前候选集合中紧邻的低/高阈值，最多执行 3 个阈值，而不是全量阈值集合。
4. 要求候选中心偏移不超过 1 px、面积变化不超过 1%、行边界变化很小且未接近裁边状态；否则回退全量检测。
5. 最多连续命中 3 帧，随后强制执行一次全量检测，避免累计漂移。

当前数据集的非重复帧变化很大，因此时序路径安全地全部回退：`exact_cache=387`、`temporal_fast=0`、`full=181`，并保持全部字段 0 差异。

额外构造的桥上连续小噪声序列（每像素扰动 ±2）中，8 帧有 6 帧命中时序路径、2 帧按周期全量校正；相对禁用时序路径的全量参考输出，`bridge_found/state/area/center_x/threshold` 均为 0 差异。该序列平均从 `285.9 us` 降至 `206.3 us`。

## 4. Cortex-M7 专项检查

### 浮点和数学函数

- 核心中已无 `double`。
- 核心中已无 `sqrt/pow/sin/cos/floor/ceil`。
- 方差标准差使用 `uint64_t` 整数平方根。
- 凸包交点使用 Q16 定点数。
- 候选评分和最终线性拟合保留 `float`，CYT4BB7 M7 的 FPU 可直接执行，避免定点溢出和精度回归风险。

### 内存

- 核心中无 `malloc/free`。
- 所有工作区由调用方静态分配。
- 位图按行连续保存。
- `BridgeDetectionScratch`：`21860` 字节（最终编译值以 PC ABI 为准，M7 对齐可能略有变化）。
- 估计峰值栈：约 `6~7 KB`，主要来自凸包点和拟合临时数组。
- 工作区加峰值栈约 `28~29 KB`，满足 30 KB 目标但余量较小；车机任务栈建议至少 8 KB。

### 循环和分支

- 形态学内层改为固定 3 字操作。
- 阈值列补偿拆成 5 个无条件连续区间，移除逐像素列判断。
- 连通域使用连续游程，减少难预测分支。
- 没有为了 PC 使用 SSE/AVX，代码仍适合 Cortex-M7。

## 6. 优化前后对比

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| PC 单帧平均，新帧 | 2.72 ms | 约 0.31 ms |
| PC 数据集平均，含严格重复帧缓存 | 2.72 ms | 0.095~0.100 ms |
| PC P95，含缓存 | 约 3.8~4.5 ms | 约 0.35~0.44 ms |
| 静态工作区 | 57,600 B | 21,860 B |
| RAM 降低 | - | 62.1% |
| IAR Cortex-M7 `-Ohz` CODE | 9,860 B | 11,262 B |
| 代码增长 | - | 1,402 B / 14.2% |

速度提升：

- 独立新帧：约 `8.8x`。
- 当前 568 帧平均吞吐：约 `27.7x`，达到约 `0.097 ms/帧`。

贡献最大的是：

1. 32 位位图形态学。
2. 删除凸包之前的冗余填洞。
3. 扫描线连通域。
4. `O(P^3)` 拟合改为有界确定性拟合。
5. 对完全重复帧进行严格缓存。

## 7. CYT4BB7 600 MHz 预估

当前代码已使用 IAR 9.40.1、`Cortex-M7 + VFPv5_d16 + -Ohz` 独立编译通过，无警告。

基于新帧 PC 耗时、约 10 KB 指令规模、22 KB 工作区和 M7 FPU/Cache 特征，保守预估：

- 常规新帧：约 `3~8 ms`。
- 重帧/P95：约 `6~12 ms`。
- 完全重复帧缓存命中：通常低于 `0.1 ms`。
- 小噪声、几何稳定的时序路径：预计比全量路径再节省约 `25~40%`；进入/退出桥时会自动退回全量路径。
- 预计常规吞吐：约 `125~330 FPS`；以实时最坏情况设计时建议按 `80~100 FPS` 预算。

最终数字必须在 CYT4BB7 上使用 DWT `CYCCNT` 包围 `bridge_detection_detect_gray()` 实测。实时调度应按“新帧 P95/最大值”而不是含缓存的平均值分配预算。

## 8. 未采用的高风险方案

### 方案 A：只保留 5 个阈值

- PC 新帧约 `0.27 ms`。
- `bridge_found/bridge_state` 在当前数据集仍一致。
- 但 49 帧面积误差超过 3%，23 帧中心误差超过 1 px。
- 未采用。

### 方案 B：只保留 7 个阈值

- PC 新帧约 `0.36 ms`。
- 状态一致，但仍有 15 帧面积误差超过 3%，12 帧中心误差超过 1 px。
- 对曝光变化的覆盖减少，未采用。

### 最终选择

保留全部自适应阈值，使用等价位图计算、冗余步骤删除、有界拟合和严格缓存。该方案速度略低于裁剪阈值方案，但没有观察到检测鲁棒性或几何精度下降。
